# The site

The public pages at thirstyeggplant.com: the landing page, the pages for one subject each, and their translations. This says how they are made and how they should look. `CLAUDE.md` has the rules in short.

## How it is made

- **`site-src/` is written; `site/` is generated and committed.** `pnpm site` (`scripts/site.mjs`, no dependencies) writes every file under `site/` from `site-src/`; `pnpm site --check` fails when `site/` is not what the sources give, and `pnpm check` runs it. Nothing under `site/` is edited by hand. The landing-page workflow publishes `site/` as it is.
- **A page is a template and its words.** `site-src/pages/<page>.html` is the page's own markup with `{{key}}` where words go; `site-src/layout.html` is what every page shares (the head, the top bar, the footer). The words are in `site-src/strings/en.json`, one entry per key (`"home.hero.title": "…"`). A string may hold `<code>`, `<strong>`, `<em>`, `<br>` and `<a href="…">` and nothing else; the build refuses any other markup in a string.
- **English is the original.** A translation is `site-src/strings/<language>.json`: for each key, the translated words and the fingerprint of the English sentence they were made from (`{ "text": "…", "from": "<fingerprint>" }`). When the English changes, that translation is stale: the page shows the English sentence there (marked `lang="en"`) until it is translated again, and `pnpm site --check` lists what is stale without failing. A key missing from a language is shown in English the same way. A key in a language that English no longer has is an error.
- **Languages are one list**, `site-src/languages.json`: the code, the name in its own language, the `lang` attribute, the direction, and the folder. English is at the root; every other language under `/<folder>/`, with the same paths below it. Each page names its other languages (`hreflang`, and `x-default` for English), has a canonical address of its own, and the sitemap lists them all.
- **A page says when its substance last changed.** Its first line has `"updated": "YYYY-MM-DD"` (with `order`, `path` and the rest), and the sitemap gives that date as each language's `<lastmod>`: a translation takes the English page's date. Change it when what the page says changes, not for a typo, a new translation or a change of the layout; the build refuses a page the sitemap lists without a real date. The Windows page also writes it as `dateModified` (`{{=updated}}`). `<priority>` and `<changefreq>` are not written: search engines ignore them.
- **The sitemap** (`sitemap.xml`, named in `robots.txt`) lists every page of every language once, absolute and with its trailing slash, each with all its alternates (itself and `x-default` included) exactly as the page's own head names them; the 404 page and anything `noindex` are left out. `scripts/site.test.mjs` checks all of this on the real site. Its first lines name `site-src/sitemap.xsl`, which shows it to a person in a browser that still applies XSLT: one row per page, the English address, its date and its other languages, in the site's colors (written into the stylesheet), on the cream ground of the one theme, with no script. A crawler reads the XML as it is. Chromium 157, the one the site's pictures are taken with, has removed XSLT and shows the file as plain text with or without that line; the view was checked by transforming the file with libxslt and showing the result.
- **Commands, addresses, names and code are never translated**: `aubergine start --open`, a key, a file name, "Aubergine", "Claude Code", "Codex". They are in `<code>` or written as they are; the check compares every `<code>` of a translation with the English one.
- **The app itself is in English.** Every translated page says so in one line, and says that the page was translated by a machine and where to send a correction. Pictures of the app are the English ones.
- **The README's translations are its top part only**: `docs/i18n/README.<language>.md`, from the title to the end of "Start in two minutes", ending with a link to the English README for everything else. The English README lists them on one line under its title. `pnpm site` and `pnpm site --check` check them (`checkReadmes`): one for every language in `languages.json`, every relative link and picture leading to a file of the checkout, every `#anchor` to a heading or id of the file it names, and the English README linking to each. Each puts `<a id="what-it-looks-like"></a>` before its translated "What it looks like", and its own links go there.

## What a page may say

- **Only what is built.** The same rule as everywhere: a sentence about the product is true of the code on main, and what was not tried is said not to have been tried. "Planned" is said as planned.
- **Bring your own agent, said exactly.** Aubergine runs ordinary terminals, calls no model, holds no key and has no account: whatever command-line agent and model a person already uses runs in a terminal. What Aubergine does *by itself* for an agent (starting it from the menu, seeing that it waits, resuming a conversation, its past conversations, how it is set up) is built for Claude Code. Any other agent can say the same things by running the `aubergine` commands, when its own instructions tell it to (`aubergine guide --snippet`). A page never blurs the two.
- **Another company's product is named plainly and not imitated.** No logo, no colors, no wording of theirs; one line at the foot of such a page says Aubergine is not affiliated with them and whose mark the name is. Nothing is claimed about their product beyond its being a command-line agent a person installs and signs in to themselves.

## The look

One idea: Aubergine on cream. A warm paper ground with near-black aubergine ink, one solid purple used as flat colour in big blocks, thick ink rules and hard offset shadows, very large heavy headings, and real captures of the app in window frames; no gradients and no glow, so the page reads like a well-printed poster that happens to hold a terminal.

- **One theme.** The cream look is the look for everyone: `color-scheme: light`, no `prefers-color-scheme` switch. The design is made of flat colour blocks (cream, lilac, purple, the dark band) whose order gives each page its rhythm; a second, dark palette would have to be a second design, and the captures of the app are already dark, so they stand out on cream. The page's `theme-color` is the cream.
- **Tokens** (custom properties on `:root` in `site-src/style.css`; every colour, size, space, radius and shadow is one):
  - cream `#F7F0E4` (the ground), lilac `#EEE5EC` (every other section, notes, the translated-page strip), ink `#1F1023` (text, rules, hard shadows, command boxes), muted `#58475C` (what is said about a thing: intros, captions, the text under a name)
  - purple `#5E2580` (the one colour: the stage band, the closing band, numerals, the primary button, the focus ring on light grounds), deep purple `#4A1D66` (a purple Copy button pointed at), dark `#2A1233` (the dark band), on-dark `#F7F0E4` and on-dark-soft `#D9C9DD` (text on dark, purple and ink), lavender `#D6B8E8` (the headline's stroke, the `$` of a command, marks on dark), amber `#F2B13E` (see below), hairline `#CDBFC6` (between table rows; not text)
  - inline code sits on 8% of ink mixed into its ground (`#E6DED5` on cream, `#DDD4DC` on lilac), or 14% of cream on dark and purple (`#47314C`, `#73418E`); a note on the dark band is 8% of cream (`#3A2441`).
  - **Contrast**, measured (WCAG 2), for every pair of text and ground the pages use: ink on cream 16.03, ink on lilac 14.74, muted on cream 7.50, muted on lilac 6.90, purple on cream 9.03, cream on purple 9.03, on-dark-soft on purple 6.50, cream on dark 15.04, on-dark-soft on dark 10.83, lavender on dark 9.64, cream on ink 16.03, lavender on ink 10.27, ink on lavender 10.27 (the headline's stroke), ink on amber 9.63, cream on deep purple 11.18, ink on code-on-cream 13.64, ink on code-on-lilac 12.56, muted on code-on-cream 6.38, cream on code-on-dark 10.23, on-dark-soft on code-on-dark 7.37, cream on code-on-purple 6.45, on-dark-soft on code-on-purple 4.64 (the lowest), on-dark-soft on a dark note 8.85, purple on lavender 5.79. A new pair is measured and added here.
- **Type**: headings in Bricolage Grotesque 800 (variable, self-hosted from `site/fonts/` with its license beside it, Latin and Latin Extended only), tight (0.94 for the hero and page headings, 1.02 for section headings) and tracked in (−0.045em, −0.035em, −0.02em for smaller ones); text in the system's sans, so that every script reads in a face made for it; commands, crumbs and labels in the system's monospace. The scale: text 17px on 1.6; 13, 15 and 20px beside it; a lead of 20–26px; h3 20–26px, a big claim 30–52px, a prose heading 26–38px, a section heading 34–72px, a page's heading 38–88px, the hero 40–100px, numerals 52–104px (each a `clamp()` token). One measure for prose, 68 characters.
- **Other scripts.** Languages the heading face has no letters for (Japanese, Chinese, Korean, Hindi, Bengali, Arabic) use the system's sans at the same weight: the stack says so. For them headings have no negative letter-spacing (it pulls Arabic apart) and looser leading (`:lang()` rules: 1.4 for Japanese, Chinese and Korean, 1.5 for Hindi and Bengali, 1.45 for Arabic; their h1 1.2 and 1.3), the giant sizes come down a step (CJK square letters fill a line faster; Indic and Arabic letters stand taller), and in Japanese, Chinese and Korean a heading's measure is in `em`, since a `ch` is half their letter. Korean breaks between words (`word-break: keep-all`), Japanese headings by phrase (`auto-phrase`, and anywhere if a phrase is wider than its box). German and Indonesian put long words in the headline: it is a step smaller there, and on a page head French, Spanish and Portuguese too, so no word breaks at 390px. The kicker's pills and the tag drop their capitals and tracking in those scripts. No font is loaded from another server.
- **Layout**: an 84rem column with a gutter of 16–48px; sections are bands that run the whole width, each ended by a 2px ink rule, 64–128px of room inside. Everything is written with logical properties, so right-to-left is the same page mirrored, except what is not mirrored: the captures (a picture of the English app), the frame's title bar (`dir="ltr"`), commands, code and blocks of code (left to right, isolated), and the language menu's chevron (physical borders, so it points down).
- **The hard shadow** is the one shadow: a flat ink offset of 3px under a button, 6px under a menu, a command on purple, a card and the boxed note, and 6–18px under a framed capture. It falls toward the end edge and the bottom; on a right-to-left page `--shadow-dir` is −1 and every shadow falls to the left.
- **Pieces**:
  - *the top bar*: cream with a 2px ink rule under it; the mark, the pages, and the language menu as a bordered box (all 12 languages, the current one inked with a tick, the open list boxed with the hard shadow).
  - *the command*: an ink box, the `$` in lavender, a cream Copy button; on purple it turns cream with a purple Copy and the hard shadow; `cmd-big` is the closing band's large one.
  - *the button*: squarish (8px), 2px ink border, a 3px hard shadow that it presses into when pointed at; purple, cream (quiet), or ink on purple.
  - *the frame*: a real capture in a window with a cream title bar, three circles (the first purple) and `localhost · Aubergine`, a cream caption under a 2px rule, the hard shadow.
  - *rows under thick rules*: a name and what it says, each under a 2px ink rule (the powers with their 01/02/03, the "what else is built" grid with small purple mono numbers, the trust pairs, the commands of the Codex page, the roadmap's groups under dashed rules).
  - *the note*: a lilac block with a 4px purple rule at its start edge; *the boxed note* adds an ink border and the hard shadow, for what must be read (the Windows trial, Codex not tried yet).
  - *the card*: cream, ink border, hard shadow, pressed as a whole (the guides, the 404 page).
  - *the questions*: rows that open, the question in the heading face, a bordered + that turns into an inked −.
  - *numbered steps*: purple numerals (`01`, `02`…) in the heading face beside each step, under 2px rules; on the home page's purple band, a cream square with the number.
  - *tables*: a 2px ink rule under the head, hairlines between rows, the first column semibold.
  - *the closing band*: every page ends on purple with a heading, a line, the install command and one or two buttons onward.
- **The hero** is three lines: "All your terminals," in ink, "side by side." in purple, "Bring your own *agents*." in ink with the agents word on a lavender stroke (a flat band behind the letters, not amber: nothing in it waits). The three are separate strings (`home.hero.title.a`, `.b`, `.c`); the kicker is four pills (`home.hero.tag.*`), the first inked. Under it, the lead at the start and the command with the two buttons beside it. Then the real capture of the canvas, `canvas.png`, in the frame, standing half on the cream and half on the purple band (an inset shadow of cream on the band's top, so there is no gradient), with its caption on the purple. On a phone the capture is cropped to its right-hand top, where the terminals are.
- **Amber has one meaning**: *waiting for you*. It is the highlighter stroke behind words that say so (the claim "The one that waits stands out", the row "See who is waiting") and, as in the app, nothing else; it is also the focus ring on the dark, purple and ink grounds, where purple would not show.
- **Pictures are readable.** A capture is of one part of the app at a size where its words can be read on the page (the list of terminals, one terminal that waits, the focus view, the For you column), except the hero's, which shows the whole canvas at once and links to the full-size file. Each has its width and height, an alt text that says what is in it, and loads lazily below the fold.
- **Motion**: a button and a card press into their shadow in 120ms when pointed at; nothing else moves, and for someone who asked for less motion nothing transitions at all.
- **A phone is a first reader**: at 390px nothing scrolls sideways, the top bar is one row of the mark, the language's short code (`{{=langshort}}`, its name staying its accessible name and in the menu) and Menu, both bordered boxes whose open list has the hard shadow; a command wraps inside its own box; rows and columns become one column, and a subject page's headings sit above their words.
- **Reached without a mouse**: every control has a visible focus ring (3px purple on cream and lilac, amber on dark, purple and ink), the language menu and the page menu open with Enter and close with Escape, giving the focus back to their button, headings go in order, and each page has one `h1`.
- **The Open Graph picture** (`site-src/og.png`, 1200×630) is a stored file: the headline, the capture in its frame over the purple band and the install command, made by screenshotting a small local HTML card with headless Chromium. Make it again the same way when the headline or the look changes.

## The pages

- **Home**, top to bottom: the hero (the kicker's four pills; the headline in three lines; that it runs as many terminals as you like with the agents and models you already use; the install command and two buttons); the real capture of the canvas between the cream and the purple band; what it adds to the terminals you already use, three numbered columns (productivity, the developer experience, nothing to switch to); on lilac, three pictures with one claim each (many terminals on one canvas; the one that waits; one terminal by itself); on the dark band, bring your own agent (Claude Code, Codex, any other, each with its link); the rest of what is built, ten numbered rows; on lilac, why it can be trusted, four names beside what they mean, and the link to the security page; five questions that open, and the link to all of them; on lilac, one line on what is planned, with a link; on purple, install in three steps.
- **Subject pages** (install, Windows, guides, several agents, working copies, the queue, security, the roadmap, the FAQ, and the 404 page): a head (crumbs, the heading, the lead, a 2px rule), the body, and the closing band. The install page and the Windows page close on what comes next instead of the general line.
- **Claude Code** (`/claude/`): a product page. A lilac head; what Aubergine does for Claude Code by itself, in the order a person meets it, as numbered rows, each with where it is in the app, two of them (when it waits, and how it names itself) beside a capture; on the dark band, what has been tried.
- **Codex and ChatGPT** (`/chatgpt/`): a product page like the one for Claude Code (the boxed note that it has not been tried, what works for any terminal on lilac beside the capture of the list, the commands as ink chips, and what is built only for Claude Code on the dark band). It says that Codex is the command-line agent and runs in a terminal like any program; what works for it today; what it can report through the commands and how to tell it to; what is built only for Claude Code; that ChatGPT in a browser is not a terminal program; and that no real Codex has been run in Aubergine yet.
- **Windows with WSL** (`/windows/`): that Aubergine does not run on Windows itself but inside WSL 2, used from a Windows browser; what was tried (the Linux steps, in a container on Ubuntu 24.04, on 2026-11-25) and that nothing was run on Windows; the steps, what is different there, and fixes. Linked from the install page and the guides, not from the top bar.
- **The others stay as they were in substance**: install, guides, run several agents, working copies, the queue and schedules, security, the roadmap, the FAQ. Their words are moved into the strings as they are, corrected only where the code has changed since.
