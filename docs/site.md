# The site

The public pages at thirstyeggplant.com: the landing page, the pages for one subject each, and their translations. This says how they are made and how they should look. `CLAUDE.md` has the rules in short.

## How it is made

- **`site-src/` is written; `site/` is generated and committed.** `pnpm site` (`scripts/site.mjs`, no dependencies) writes every file under `site/` from `site-src/`; `pnpm site --check` fails when `site/` is not what the sources give, and `pnpm check` runs it. Nothing under `site/` is edited by hand. The landing-page workflow publishes `site/` as it is.
- **A page is a template and its words.** `site-src/pages/<page>.html` is the page's own markup with `{{key}}` where words go; `site-src/layout.html` is what every page shares (the head, the top bar, the footer). The words are in `site-src/strings/en.json`, one entry per key (`"home.hero.title": "…"`). A string may hold `<code>`, `<strong>`, `<em>`, `<br>` and `<a href="…">` and nothing else; the build refuses any other markup in a string.
- **English is the original.** A translation is `site-src/strings/<language>.json`: for each key, the translated words and the fingerprint of the English sentence they were made from (`{ "text": "…", "from": "<fingerprint>" }`). When the English changes, that translation is stale: the page shows the English sentence there (marked `lang="en"`) until it is translated again, and `pnpm site --check` lists what is stale without failing. A key missing from a language is shown in English the same way. A key in a language that English no longer has is an error.
- **Languages are one list**, `site-src/languages.json`: the code, the name in its own language, the `lang` attribute, the direction, and the folder. English is at the root; every other language under `/<folder>/`, with the same paths below it. Each page names its other languages (`hreflang`, and `x-default` for English), has a canonical address of its own, and the sitemap lists them all.
- **Commands, addresses, names and code are never translated**: `aubergine start --open`, a key, a file name, "Aubergine", "Claude Code", "Codex". They are in `<code>` or written as they are; the check compares every `<code>` of a translation with the English one.
- **The app itself is in English.** Every translated page says so in one line, and says that the page was translated by a machine and where to send a correction. Pictures of the app are the English ones.
- **The README's translations are its top part only**: `docs/i18n/README.<language>.md`, from the title to the end of "Start in two minutes", ending with a link to the English README for everything else. The English README lists them on one line under its title. `pnpm site` and `pnpm site --check` check them (`checkReadmes`): one for every language in `languages.json`, every relative link and picture leading to a file of the checkout, every `#anchor` to a heading or id of the file it names, and the English README linking to each. Each puts `<a id="what-it-looks-like"></a>` before its translated "What it looks like", and its own links go there.

## What a page may say

- **Only what is built.** The same rule as everywhere: a sentence about the product is true of the code on main, and what was not tried is said not to have been tried. "Planned" is said as planned.
- **Bring your own agent, said exactly.** Aubergine runs ordinary terminals, calls no model, holds no key and has no account: whatever command-line agent and model a person already uses runs in a terminal. What Aubergine does *by itself* for an agent (starting it from the menu, seeing that it waits, resuming a conversation, its past conversations, how it is set up) is built for Claude Code. Any other agent can say the same things by running the `aubergine` commands, when its own instructions tell it to (`aubergine guide --snippet`). A page never blurs the two.
- **Another company's product is named plainly and not imitated.** No logo, no colors, no wording of theirs; one line at the foot of such a page says Aubergine is not affiliated with them and whose mark the name is. Nothing is claimed about their product beyond its being a command-line agent a person installs and signs in to themselves.

## The look

One idea: the page is the product's own room at night. A dark, slightly aubergine black; a canvas of dots; terminals as the only bright things; and one color, amber, that means exactly what it means in the app, *waiting for you*, and is used for nothing else.

- **Tokens** (in `site-src/style.css`, dark first; the light theme redefines colors only, as the app does):
  - ground `#120f14`, raised `#1a161d`, line `#2c2531`, text `#f2ebf1`, quiet text `#a89dab`
  - aubergine `#c690c1` (links, marks), deep aubergine `#5a2956` (fills), amber `#f0b24a` (waiting, and only waiting), green `#84c98d` (a prompt, "done")
  - light: ground `#faf6f2`, raised `#ffffff`, line `#e7ddd9`, text `#201a22`, quiet `#655a6b`, aubergine `#6b2f66`, deep `#ead9e8`, amber `#a3620a`, green `#2c7a3a`
  - every pair of text and ground keeps 4.5:1; say the measured numbers when a token changes. The light amber was `#a8650a` (4.31:1 on the ground) and is `#a3620a`, the same hue darker: 4.53:1 on the ground `#faf6f2`, 4.87:1 on raised `#ffffff`.
- **Type**: headings in Bricolage Grotesque (variable, self-hosted from `site/fonts/` with its license beside it, Latin and Latin Extended only), tight and heavy; text in the system's sans, so that every script reads in a face made for it; commands and labels in the system's monospace. Languages the heading face has no letters for use the system's sans at the same weight: the stack says so. For them headings have no negative letter-spacing (it pulls Arabic apart) and looser leading (`:lang()` rules: 1.4 for Japanese, Chinese and Korean, 1.5 for Hindi and Bengali, 1.45 for Arabic; the hero's 1.3), and in Japanese, Chinese and Korean a heading's measure is in `em`, since a `ch` is half their letter. Korean breaks between words (`word-break: keep-all`), Japanese headings by phrase (`auto-phrase`). No font is loaded from another server.
- **The kicker** over the hero's heading breaks only after a dot: each phrase is held together by no-break spaces in its string, and CJK letters by `word-break: keep-all`.
- **Sizes**: text 17px on 1.65; a heading scale of 1.25 from there; one measure for prose, 68 characters.
- **Layout**: a 72rem column with a 20px gutter; sections 96px apart (64px on a phone); the hero is two columns from 1000px up, words at the start edge and the canvas beside them, one column below that. Everything is written with logical properties, so right-to-left is the same page mirrored, except what is not mirrored: the hero's canvas (`dir="ltr"`, a picture of the English app), commands, code and blocks of code (left to right, isolated), and the menu's chevron (physical borders, so it points down).
- **Pieces**: the top bar (the mark, the pages, the languages); the command (a line of monospace with a button that copies it); the terminal (a title with a state, a few lines); the picture (a real capture of the app, in a frame, with one sentence under it); the row (a name and one sentence, no box; three of them may stand across from 800px up, one under another below); the note (a quiet line with a rule at its start edge). No card holds a card, and a list is rows unless each item needs a picture.
- **The hero's canvas is drawn, not captured**: five terminals placed as on a canvas, not in a grid, of different sizes, named for what runs in them (two agents of different kinds, a shell, a test run), one of them waiting in amber. It is an illustration and its caption says what it shows. Everything below it that shows the app is a real capture.
- **Pictures are readable.** A capture is of one part of the app at a size where its words can be read on the page (the list of terminals, one terminal that waits, the Runs columns, the focus view), never the whole window shrunk. Each has its width and height, an alt text that says what is in it, and loads lazily below the fold.
- **Motion**: the waiting terminal's mark breathes, slowly; a button and a link answer the pointer in 120ms. Nothing else moves, and nothing moves for someone who asked for less motion.
- **A phone is a first reader**: at 390px nothing scrolls sideways, the top bar is one row of the mark, the language button and the page menu (the language button shows the language's code in capitals there, `{{=langshort}}`, its name staying its accessible name and in the menu), and a command wraps or scrolls inside its own line.
- **Reached without a mouse**: every control has a visible focus ring, the language menu and the page menu open with Enter and close with Escape, headings go in order, and each page has one `h1`.

## The pages

- **Home**: the hero (what it is in one sentence; that it runs as many terminals as you like and the agents and models you already use; the install command); what it adds to the terminals you already use, three rows across (productivity, the developer experience, nothing to switch to); three pictures with one claim each (many terminals on one canvas; the one that waits; one terminal by itself); bring your own agent (Claude Code, Codex, any other, each a row with its link); the rest of what is built, as rows; why it can be trusted; install in three steps; five questions; one line on what is planned, with a link.
- **Claude Code** (`/claude/`): what Aubergine does for Claude Code by itself, in the order a person meets it, each with where it is in the app.
- **Codex and ChatGPT** (`/chatgpt/`): that Codex is the command-line agent and runs in a terminal like any program; what works for it today; what it can report through the commands and how to tell it to; what is built only for Claude Code; that ChatGPT in a browser is not a terminal program; and that no real Codex has been run in Aubergine yet.
- **The others stay as they were in substance**: install, guides, run several agents, working copies, the queue and schedules, security, the roadmap, the FAQ. Their words are moved into the strings as they are, corrected only where the code has changed since.
