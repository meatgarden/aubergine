Security and privacy

What Aubergine does to protect your terminals, and, just as important, what it does not. The short version: it is local, it asks before it acts for an agent, and agents still run as you.

Everything stays on your computer

  • The server binds to 127.0.0.1 only. Every request, and every WebSocket upgrade, has its Host and Origin checked, and the browser must hold an access cookie.
  • Using Aubergine from another device is off until you set it up: something on the same computer carries HTTPS to it under a name you write in the settings, and each browser is paired with a one-time code and can be revoked. A paired device can do everything the owner can. Using Aubergine from elsewhere says how.
  • Aubergine calls no model and starts no network request of its own, with two exceptions: fetching a library source (a Git address) when you ask for it, and asking your own gh tool, where it is installed and signed in, for the pull request of a terminal's branch.
  • Desktop notifications come from the open page. Nothing leaves your computer.

Three kinds of caller, each judged on its own

Every request is checked against what the caller may do before anything is looked up, so a caller without the right learns nothing from the answer. The callers are you (signed in to the browser), an agent's session, and an API token.

  • API tokens have scopes. The secret is shown once and never stored; only a hash is kept. Calls made with a token go into an activity log: who, what and how it ended, never the secret and never what was sent.
  • Some things no token can ever do: create or revoke tokens, read the activity log, change settings, and anything about terminals outside Aubergine.
  • Terminal access is two separate scopes, one to read and one to type, each limited to the sessions you choose. You can mark a terminal people only to close it to every token.
  • An agent's own credential is narrow. It can set its own attention, add to its own notes, report its own status and read the run it is on. It cannot reach other terminals, canvases or tokens.

What an agent cannot do alone

  • What an agent or program writes (a workflow, a step) arrives as a draft you review. Accepting is yours alone.
  • A step that waits for a person can be approved or sent back only by a person. Rules, schedules and the demo are yours alone.
  • Aubergine types only a few fixed sentences into an agent's terminal, such as “read your next step”. Nothing you stored, and nothing an agent wrote, is typed.
  • Installing from a library needs you to accept the exact content you were shown.

What this does not protect against

Agents run as you. An agent in a terminal can do anything you can do in that terminal, including running commands, reading files and, if it chooses, using your own browser session.

  • Approvals are not a lock. An agent that runs as you can decide as you. The decision is recorded, not prevented.
  • Working copies are not a sandbox. They keep work apart and do not keep an agent in.
  • The review screen is the control for library items. An item is instructions an agent will follow with everything that agent may do. Do not install what you have not read.
  • The guide for agents is advice, not a lock.

The installer

It changes two things: its own folder and one link named aubergine. No sudo, no edits to your shell startup files, and it never touches your data folder. aubergine uninstall removes only what it made.

Report a problem

Open an issue on GitHub. Do not put secrets or tokens in it.

Related: working copies · FAQ · roadmap (approval modes and command policy are planned, not built)

Up and running in five minutes

You need macOS with tmux 3.2 or newer and Node.js 22 or newer. brew install tmux node gets both.

npm install -g @meatgarden/aubergine
