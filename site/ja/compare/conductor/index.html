Aubergine vs Conductor

Both run several coding agents at once, each in its own Git worktree. Conductor is a Mac app with chats, a diff viewer and a cloud. Aubergine is a free, open-source server on your own computer that shows ordinary terminals side by side in a browser page.

Where this comes from. What is said here about Conductor is from its documentation and its changelog as read on 26 November 2026. We have not run Conductor. If something is wrong or out of date, tell us.

Where Conductor stands. On 4 November 2026 its changelog said Conductor was joining Meta and would wind down; on 13 November it said Conductor is not shutting down. Parts of its site still carried the first message when this was written. Read its changelog for where it stands now.

Which to pick

Pick Conductor if you want a Mac app that takes a task from a prompt to a merged pull request, with a cloud for work that goes on while your Mac is off.

Pick Aubergine if you want your agents as plain terminals you can see all at once, going on in tmux when the window closes, with nothing to sign in to and the source open.

What Conductor is

By its own description, a Mac app that runs many coding agents in parallel on your codebase. Each piece of work is a workspace: a Git worktree on one branch, with chat, terminal and browser tabs. It runs Claude Code, Codex, Cursor and OpenCode with the sign-ins already on your Mac, and has a diff viewer, pull requests, an iOS app and a paid cloud where agents run in sandboxes.

Where they differ

Terminals, not chats. Conductor shows an agent as a chat in a workspace, with a terminal mode beside it. Aubergine shows the agent's own terminal, as it runs in any terminal app, and lays many of them out on a canvas you pan and zoom.

What closing it ends. Conductor's documentation says local sessions end when you close the app or shut down the Mac, and that cloud sessions go on. In Aubergine every terminal is a tmux session: closing the browser or stopping Aubergine ends nothing. A restart of the computer does, in both.

Nothing outside your computer. Conductor documents an account, a cloud, a relay for its phone app and usage analytics. Aubergine has no account and no service of its own: the server listens on 127.0.0.1, and use from another device goes through a proxy you run.

What Conductor has that Aubergine does not

  • A diff viewer where you comment on lines and send the comments back to the agent, then pull requests, checks and merging. Aubergine shows what changed in a working copy and never commits, pushes or merges.
  • A cloud where agents go on with your Mac off, and routines that run there on a schedule. Aubergine's schedules fire on your computer, while it is on.
  • An iOS app and completion sounds. Aubergine has no app and plays no sound.

Questions

Is Aubergine an alternative to Conductor?

For running several command-line agents on your own computer, yes: each agent has a terminal on a canvas and, when you ask, its own Git worktree. It is not a like-for-like replacement: Aubergine has no chat view, no pull requests or merging, no cloud and no phone app.

Is Conductor open source?

No: its terms call it proprietary, and we found no public repository. Its documentation says the local app is free to use and that cloud workspaces need a paid plan. Aubergine is under the MIT license and has no paid plan.

Does Conductor run on Linux or Windows?

Its documentation says it is not available for Windows or Linux yet. Aubergine is built for macOS, has been run on Linux in containers only, and on Windows runs only inside WSL 2, which has not been tried.

Can I use Conductor and Aubergine together?

Nothing stops it: both work in Git worktrees of the same repository, each making its own. We have not run the two side by side.

Aubergine is not affiliated with Conductor or its makers. Conductor is the name of their product: its terms name Melty Labs, Inc., and its site says Conductor from Meta.
