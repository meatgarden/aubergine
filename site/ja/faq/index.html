よくある質問

短い答えです。詳しくはガイドにあります。

Aubergine とは何ですか？

ローカルで動く、ブラウザーベースのターミナルセッションのキャンバスです。各ターミナルは配置して使えるノードなので、複数のコーディングエージェントを同時に動かし、どれがあなたを待っているかを確認できます。

Aubergine は無料でオープンソースですか？

はい。無料で、ソースは GitHub にあります。

Aubergine を動かすには何が必要ですか？

tmux 3.2 以降と Node.js 22 以降を入れた macOS。インストーラーには pnpm も必要です。Linux ではコンテナの中でだけ動かしました。Windows では WSL 2 の中でだけ動き、それもまだ試していません。Windows 向けのガイドを見てください。

どのコーディングエージェントでも使えますか？

Aubergine は普通のターミナルを動かすので、どのコマンドラインエージェントも動かせます。待っていることの把握など、Aubergine がエージェントのために自ら行うことは Claude Code 向けに作られています。Codex を含むほかのエージェントは、aubergine コマンドとローカル API で状態を報告でき、トークンが許すものだけを一覧する MCP サーバーも使えます。

Aubergine はターミナルやコードをどこかに送りますか？

いいえ。すべてあなた自身のコンピューターで動きます。サーバーは 127.0.0.1 でのみ待ち受けます。

Aubergine は AI モデルを呼び出しますか？

いいえ。呼び出すのはあなたのエージェントです。Aubergine はそのターミナルを動かして状況を追うだけで、どのモデルのキーも持ちません。

ブラウザーを閉じるとターミナルはどうなりますか？

動き続けます。各セッションは tmux セッションで、ブラウザーと Aubergine のサーバーの両方より長く生きます。

どのエージェントが自分を待っているか、どう分かりますか？

各ターミナルは、処理中・アイドル・待機中のどれかを表示します。ページ上部の For you の横の数と For you の一覧に、あなたを必要とするものすべてが集まります。

2つのエージェントが同じファイルを編集しないようにするには？

各ターミナルを専用の作業コピーで起動します。専用のブランチ上の専用チェックアウトです。Aubergine があなたの代わりにマージやプッシュをすることはありません。

エージェントに従うべきステップの一覧を渡せますか？

はい。ワークフローは順番付きのステップの一覧で、エージェントが今どこにいるかを示す帯が付きます。ステップは、あなたが承認するか差し戻すのを待つこともできます。

エージェント同士で話せますか？

はい、制限の範囲内で。ターミナル間のメッセージには送り手の名前、一時停止、ブロックがあり、キャンバスごとに初期状態では閉じています。

API はありますか？

はい。スコープ付きトークンを使うローカル HTTP API、型付きクライアント、そして資格情報が使えるツールだけを一覧する MCP サーバーがあります。

ターミナルを1つだけ単独で開けますか？

はい。ターミナルのタイトルにある Tab ↗ で、専用のブラウザータブに開きます。コピーではなく同じターミナルで、求めれば詳細とノートが横に出ます。タブを閉じても何も終了しません。

ターミナルにチケットや担当者を記録できますか？

はい。ターミナルの詳細には、ラベルと値の組であるフィールドがあります。中のエージェントは aubergine field set で自分のフィールドを設定でき、あなたが同じラベルを設定した場合はあなたのものが残ります。

Aubergine は複数の人やクラウドのエージェントに対応しますか？

どちらも予定中で、まだどちらも作られていません。ロードマップを参照してください。現在はすべて1台のコンピューターで動きます。

インストーラーは私のコンピューターで何を変更しますか？

2つです。インストールフォルダー（~/.aubergine）と、aubergine という名前のリンク1つ。sudo は使わず、シェルの起動ファイルを編集せず、Node.js・pnpm・tmux をインストールすることもありません。

5分で動かす

tmux 3.2 以降と Node.js 22 以降の入った macOS が必要です。brew install tmux node で両方が入ります。

npm install -g @meatgarden/aubergine
