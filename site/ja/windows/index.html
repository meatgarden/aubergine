WSL を使って Windows に Aubergine をインストール

Aubergine は Windows そのものでは動きません。Windows が用意する Linux である WSL 2 の中で動き、Windows のブラウザーから使います。

試したこと。Linux の手順は 2026年11月25日に、WSL ではなくコンテナの中の Ubuntu 24.04.5（x86_64）で、npm の Aubergine 0.2.2 を使って実行しました。端末ライブラリーをコンパイルし、起動し、ブラウザーをサインインさせ、ターミナルとデモを動かしました。Node.js 22 がすでに入っていたため、nvm による Node.js のインストールはそこでは実行していません。このページのことは、まだ何も Windows で実行していません。試したら、結果を教えてください。

必要なもの

Windows 11、または Windows 10 バージョン 2004（ビルド 19041）以降。ここでは WSL 2 をコマンド1つで入れられます。詳しくは Microsoft の WSL のインストールのページにあります。

インストールして起動する

  1. WSL を入れます。PowerShell を管理者として開いてこれを実行し、終わったら Windows を再起動します。Ubuntu 入りの WSL 2 が入ります。

    wsl --install

    再起動したら、スタートメニューから Ubuntu を開き、ユーザー名とパスワードを決めます。以下のコマンドはすべてそこ、Ubuntu の中で入力します。

  2. Aubergine に必要なものを入れます。tmux、zsh、Git と、端末ライブラリーをコンパイルするための道具です。このライブラリーには Linux 向けのビルド済みのものがありません。

    sudo apt update

    sudo apt install -y tmux zsh git build-essential python3

    Node.js 22 を入れます。Ubuntu 自身のパッケージはバージョン 18 で、古すぎます。よく知られた方法の1つが nvm です。nvm を入れ、新しい Ubuntu のウィンドウを開いてから Node.js 22 を入れます。

    curl -o- https://raw.githubusercontent.com/nvm-sh/nvm/v0.40.3/install.sh | bash

    nvm install 22

    これで node -v が v22 以降を表示するはずです。

  3. npm から Aubergine を入れます。インストール中に端末ライブラリーをコンパイルします。試したときはインストール全体で 13 秒でした。

    npm install -g @meatgarden/aubergine

  4. 起動し、そのウィンドウは開いたままにします。

    aubergine start

    ブラウザーをサインインさせます。2つ目の Ubuntu のウィンドウでサインイン用のアドレスを表示し、Windows のブラウザーで開きます。そのブラウザーがサインインするので、パスワードと同じように扱ってください。

    aubergine open --print

    その後は、そのブラウザーで http://127.0.0.1:4600 だけで開けます。空のキャンバスでは Show me around でツアーが始まります。

知っておくと良いこと

  • プロジェクトは Ubuntu の中に置きます。Ubuntu のホームフォルダーに置き、/mnt/c の下には置きません。そこにある Windows のファイルには、遅い橋渡しを通ってアクセスします。
  • エージェントは Ubuntu の中に入れます。Claude Code でも Codex でも他のものでも、ふつうの Linux と同じです。Windows に入れたエージェントは Aubergine のターミナルにはありません。
  • ターミナルは WSL が動いている間だけ生きています。ブラウザーを閉じても何も終わりません。aubergine start のウィンドウで Ctrl+C を押すと、止まるのはサーバーだけです。Windows の再起動や wsl --shutdown で WSL が止まるとターミナルは終わり、次の aubergine start が最後のフォルダーで新しいシェルを開きます。Mac を再起動したあとと同じです。
  • bash と zsh。Ubuntu のシェルは bash で、ターミナルはその中で動きます。ターミナルのコマンドの状態（実行中、失敗したコマンドの終了コード）は zsh からしか得られません。試したときは、zsh のターミナルが失敗したコマンドのあとに exit 3 を表示しました。これを使うには Ubuntu で zsh を自分のシェルにしてください。
  • ないもの：ログイン時の起動は macOS でしか動きません（aubergine service install がそう伝えます）。Open on desktop には Windows の端末アプリ用の設定がありません。試したときは aubergine open が開くブラウザーを見つけられませんでした。aubergine open --print はいつでも使えます。
  • Windows でのキーは、ブラウザーのドキュメントに基づいて選んだもので、測ってはいません。docs/keys.md を見てください。パレットはいつでも使えます。

うまくいかないとき

まず Ubuntu で aubergine doctor を実行します。Node.js、tmux、Git とサーバーを確かめます。

見えるものすること
Aubergine のインストールが node-pty のコンパイル中に失敗するビルド用の道具が足りません。手順 2 の apt の行を実行し、Aubergine をもう一度入れます。
tmux がない、または古すぎるというページUbuntu 24.04 の tmux は 3.4 で、十分に新しいものです。sudo apt install -y tmux を実行し、サーバーを起動し直します。
node -v が v22 より古いバージョンを表示する手順 2 のとおり Node.js 22 を入れ、新しい Ubuntu のウィンドウを開き、Aubergine をもう一度入れます。
Windows のブラウザーでアドレスが開かないUbuntu で aubergine start がまだ動いているか確かめます。それから Microsoft の WSL のネットワークのページを見てください。Aubergine ではまだ試していません。
