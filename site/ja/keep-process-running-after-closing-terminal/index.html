ターミナルを閉じてもプロセスを動かし続ける

ビルドやサーバー、コーディングエージェントを起動したのに、ウィンドウを閉じると終わってしまう。Aubergine ではウィンドウを閉じても何も終わりません。どのターミナルもブラウザーとは別に動き、出力したものは戻ってきたときにそこにあります。

よくあるやり方

ターミナルのウィンドウを閉じると、その中のシェルが終わり、そのシェルが起動したものも一緒に終わります。これを避ける定番の方法は次のとおりです。

  • nohup は、ターミナルが閉じるときに送られるハングアップを無視するコマンドを起動します。出力はファイルに書かれます（別の場所に送らなければ nohup.out）。
  • disown は bash と zsh で、すでに起動したジョブを手放し、シェルがハングアップをそのジョブに伝えないようにします。そのあとターミナルでそのジョブに戻ることはできません。
  • screen と tmux は、シェルを自前のサーバーの中で動かします。デタッチしてウィンドウを閉じ、あとで同じシェルに出力ごとアタッチし直せます。確実な答えですが、使うにはキーとコマンドを覚える必要があります。

Aubergine は最後の方法の上に作られています。tmux をあなたの代わりに動かすので、キーを覚えずに tmux の答えが手に入ります。

Aubergine がすること

Aubergine のどのターミナルも、Aubergine 専用の tmux ソケット上で、ターミナルごとの tmux セッションの中で動くシェルです。tmux はブラウザーとも Aubergine のサーバーとも別に動くので、次のようになります。

  • タブ、ウィンドウ、ブラウザー全体を閉じても何も終わりません。ページを開き直せば（aubergine open でサインインした状態で開きます）、各ターミナルが tmux から今の状態で描かれ、その間に出力されたものはスクロールバックにあります。
  • Aubergine を止めても何も終わりません。aubergine start が動いている場所での Ctrl+C、サーバーのクラッシュ、アップデートで止まるのはサーバーだけです。もう一度起動してページを再読み込みしてください。
  • キャンバス上でターミナルを閉じるとパークされます。タイトルの × でキャンバスから外れ、シェルは動き続けます。キャンバス上のバーにある Parked（パーク中）がパークしたターミナルを一覧し、Restore（戻す）で戻せます。
  • シェルを完全に終わらせる前には確認があります。パークの一覧にある End（終了）は、あなたが「はい」と答えたときだけターミナルを終わらせます。
  • 別の表示を閉じても何も終わりません。ターミナルのタイトルにある Tab ↗ はそのターミナルだけをブラウザーのタブで開き、aubergine attach <name> はターミナルアプリのウィンドウに表示します。どれも同じターミナルで、コピーではありません。そのタブやウィンドウを閉じても動き続けます。

シェルが動いている間、tmux は出力された最後の50,000行を保持します。キーボードを持っているターミナルではホイールでさかのぼれ、パレット（⌘K）で検索できます。

しないこと

  • コンピューターの再起動は越えられません。再起動、コンピューターのクラッシュ、再起動を伴うアップデートは、すべてのシェルとその中で動いているものを終わらせます。Aubergine はその周りのすべてを戻し、各ターミナルを最後のフォルダーで新しいシェルにしますが、自分では何も起動し直しません。再起動のあともターミナルを残すを参照してください。
  • コンピューターを起こしたままにはしません。ノートパソコンがスリープすると、ここで動いているものも含めてプログラムは一時停止し、起きると続きから動きます。
  • サービスマネージャーではありません。再起動のあと自動で戻ってくるべき処理は、システムのサービスに任せてください。
  • ほかの場所ですでに動いているプログラムを引き取ることはできません。動いているプログラムを別のターミナルに移せるツールはありません。ターミナルアプリのタブで aubergine here を実行すると、そのフォルダーのターミナルがキャンバスにできます。タブで動いているプログラムはそこに残り、新しいターミナルの中で起動し直す必要があります。

SSH で別のマシンにいるとき

Aubergine はあなた自身のコンピューターで動きます。サーバーは 127.0.0.1 で待ち受け、ターミナルはそのコンピューター上のシェルです。残したいのが SSH で接続するリモートサーバー上のプロセスなら、そのサーバーでの tmux や screen が今も答えです。

Aubergine 自体を別のマシンで動かし、SSH トンネル、プライベートネットワーク、または名前とプロキシを通じてブラウザーから使うこともできます。手順は Using Aubergine from elsewhere にあります。SSH トンネルの場合、aubergine start を動かしている SSH のウィンドウを閉じるとサーバーは止まりますが、ターミナルは動き続けます。Linux はコンテナーの中でしか動かしておらず、クラウドのマシンでは一度も動かしていません。

よくある質問

ブラウザーを閉じるとターミナルは止まりますか？

いいえ。どのターミナルも tmux 内のシェルで、ブラウザーとは別に動いています。タブ、ウィンドウ、ブラウザーを閉じてからページを開き直すと、各ターミナルは今の状態で、動き続けたまま、その間の出力とともにあります。

SSH が切れたあともプロセスを動かし続けるには？

リモートのマシンで、tmux か screen の中で、または nohup で起動します。Aubergine がターミナルを保つのは、自分が動いているコンピューター上です。リモートのマシンで動かして SSH トンネルやプロキシ経由で使うこともできますが、それはコンテナーの中でしか動かしておらず、クラウドのマシンでは動かしていません。

nohup と tmux のどちらを使うべきですか？

nohup は、出力をファイルに書いてよい1つのコマンドに向いています。tmux は、あとで戻って入力したいシェルに向いています。Aubergine はすべてのターミナルに後者を、ブラウザーのページで、tmux のキーなしで与えます。

ターミナルを閉じたあとに出力を見られますか？

はい、シェルが動いている間は。tmux は各ターミナルの最後の50,000行を保持し、戻ってきたときにページに表示されます。Aubergine 自身は何も記録しないので、コンピューターを再起動するとその出力は消えます。

再起動のあとも動き続けますか？

いいえ。コンピューターの再起動はすべてのプログラムを終わらせます。Aubergine は各ターミナルを、位置、名前、ノートとともに、最後のフォルダーで新しいシェルとして戻し、何も実行し直しません。

tmux 3.2 以降と Node.js 22 以降の入った macOS が必要です。brew install tmux node で両方が入ります。

npm install -g @meatgarden/aubergine
