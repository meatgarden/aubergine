tmux を覚えずに tmux を使う

tmux は、ウィンドウを閉じてもシェルを動かし続けます。その代わり、プレフィックスキー、コピーモード、設定ファイルを覚える必要があります。Aubergine が tmux を動かすので、あなたは各ターミナルをブラウザーのページで、ふつうのターミナルと同じように使えます。

誰のためか

tmux が与えてくれるもの、つまりウィンドウを閉じても残るシェルが欲しいけれど、キーや設定は覚えたくない人のためのものです。すでに tmux を使いこなしているなら、そのまま使ってください。Aubergine はあなたの tmux には触れません。

よくあるやり方

tmux を覚える：各コマンドの前にプレフィックスキー（変えなければ Ctrl+B）、戻るには tmux attach、マウスとクリップボードのために ~/.tmux.conf に数行。あるいは同じ種類の古いツールの screen。日常の操作が、既定の tmux と Aubergine でそれぞれどうなるかは次のとおりです。

そこに戻るtmux attachページを開く

Aubergine がすること

専用のソケットと専用の設定。Aubergine は aubergine という名前の専用のソケットで、あなたのものではなく専用の設定ファイルを使って tmux を起動します。ステータスラインなし、プレフィックスキーなし、マウスはオン、履歴は50,000行。各ターミナルは1つのシェル（あなたのログインシェル）を持つ1つの tmux セッションです。あなた自身の tmux、そのセッション、~/.tmux.conf には触れません。

キーボードを持っているターミナルはホイールでさかのぼれます。キャンバスのそれ以外の場所では、ホイールでズームします。

マウスで選択して離すとクリップボードにコピーされます。tmux が選択されたものを OSC 52（ターミナルがクリップボードに使うエスケープシーケンス）でページに渡し、ページがクリップボードに入れます。ペーストは ⌘V（macOS 以外では Ctrl+Shift+V）。複数行のペーストはブラケットで囲まれるので、シェルが1行ずつ実行することはありません。

ドラッグでサイズを変えます。キャンバス上でターミナルの端をドラッグすると、シェルに新しいサイズが伝わります。2か所で同時に開いているターミナルのサイズは1つで、最後に入力した表示のサイズになります。

中身は今も tmux です。aubergine attach <name> はターミナルをターミナルアプリのウィンドウに表示し、ターミナルのメニューにある Open on desktop（デスクトップで開く）がそれを代わりに行います（macOS では Terminal か iTerm で、Linux では設定したコマンドラインで）。サーバーが止まっていても、tmux -L aubergine ls と tmux -L aubergine attach -t <id> ですべてのシェルに届きます。

必要なもの

tmux 3.2 以降を、ご自身でインストールしてください。macOS では brew install tmux、Linux ではシステムのパッケージです。Aubergine はインストールせず、見つからないときや古いときはそう伝えるページを表示します。zsh では、ターミナルのタイトルに実行中のコマンドと最後のコマンドの終わり方が出ます。ほかのシェルではそれなしで動きます。

これではないもの

  • リモートサーバー上の tmux ではありません。Aubergine の tmux は、サーバーが動いているコンピューター上で動きます。SSH で接続するマシン上のシェルには、今もそのマシンの tmux が道具です。Aubergine 自体を別のマシンで動かすこともできますが（Using Aubergine from elsewhere）、コンテナーの中でしか動かしていません。
  • あなた自身の tmux のセッションは表示されません。キャンバスにあるのは Aubergine のターミナルだけです。aubergine scan はこのコンピューターで Aubergine の外に開いている対話シェルを一覧し、aubergine import や aubergine here はそのうち1つに、同じフォルダーでキャンバス上の新しいターミナルを与えます。古いほうで動いているプログラムはそこに残ります。aubergine shell-hook print が .zshrc 用に出す行は、tmux の中では何もしません。
  • tmux のキーもペインもありません。プレフィックスキーはなく、あなた自身の tmux のキー割り当ては効きません。ターミナルがキーボードを持っている間、すべてのキーはその中のプログラムに届きます。例外は、どのシェルもエディターも tmux も必要としないように選んだいくつかの組み合わせだけです。
  • Windows そのものでは動きません。tmux と Unix のシェルが必要で、Windows では WSL 2 の中で動きます。WSL を使う Windows を参照してください。

よくある質問

ショートカットを覚えずに tmux を使えますか？

はい。Aubergine はプレフィックスキーもステータスラインもなしで tmux を動かすので、tmux のコマンドを入力することはありません。離れるにはタブを閉じ、戻るにはページを開き、ホイールでスクロールし、選択してコピーします。

Aubergine は私の tmux の設定を変えますか？

いいえ。専用のソケット aubergine で、専用の設定ファイルを使って tmux を動かします。あなたの tmux サーバー、そのセッション、~/.tmux.conf はそのままです。

Aubergine のターミナルでスクロールやコピーをするには？

ターミナルをクリックしてキーボードを渡し、ホイールでさかのぼります。マウスでテキストを選択すると、離した時点でクリップボードに入ります。ペーストは ⌘V、macOS 以外では Ctrl+Shift+V です。

自分のターミナルアプリから Aubergine のターミナルにアタッチできますか？

はい。aubergine attach <name>、またはターミナルのメニューの Open on desktop です。どちらでも同じターミナルで、一方で入力したものはもう一方にも表示されます。

SSH で入るサーバーの tmux の代わりに Aubergine を使えますか？

そのままの形では使えません。ターミナルはサーバーが動いているマシン上にあります。サーバーで動かして SSH トンネルやプロキシ経由でブラウザーから使うことはできますが、それはコンテナーの中でしか動かしておらず、クラウドのマシンでは動かしていません。

関連：プロセスを動かし続ける · 再起動のあともターミナルを残す · ターミナルが多すぎるとき

5分で動かす

tmux 3.2 以降と Node.js 22 以降の入った macOS が必要です。brew install tmux node で両方が入ります。

npm install -g @meatgarden/aubergine
