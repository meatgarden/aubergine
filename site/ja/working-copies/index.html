2つのエージェント、1つのリポジトリ：作業コピー

通常、どのターミナルもあなたの実際のフォルダーで作業します。すると1つのリポジトリにいる2つのエージェントは同じファイルを編集し、どの変更が誰のものか分からなくなります。作業コピーは、各ターミナルに専用のブランチ上の専用チェックアウトを渡します。

作業コピーでターミナルを起動する

  1. ターミナル一覧の上にある New terminal の端の ▾ を押し、Shell in a folder or a working copy… を選びます。
  2. フォルダーを指定し、In its own working copy（専用の作業コピーで）を選びます。この選択肢は使える場合にだけ出て、使えない場合はその理由を示します。Git リポジトリではない、ベアリポジトリである、まだコミットがない、のいずれかです。

ターミナルからも同じことができます：

aubergine here --copy
aubergine new "api" --copy --in ~/code/my-project

得られるもの

Git の worktree です。リポジトリの中ではなく、Aubergine がデータフォルダーの下に置くフォルダーにあり、aubergine/<terminal name>-<six characters> という名前の新しいブランチ上にあります。チェックアウトが今いるコミットから始まり、ターミナルはあなたがいたのと同じサブフォルダーで起動します。あなた自身のチェックアウトは決して変わりません。ファイルも、ステージしたものも、チェックアウト中のブランチもです。

引き継がれないもの：コミットしていない変更（あなたの代わりにスタッシュもコミットもしません）と、Git が無視するファイルや追跡していないファイル（インストール済みの依存関係やローカルの設定など）。インストール手順が必要なプロジェクトは、作業コピーでももう一度必要です。

エージェントが変えたものを読む

作業コピーにいるターミナルは、タイトルバーにブランチと差分のあるファイルの数を表示します。クリックすると、変更・追加・削除されたファイルが、どのコミットにもない作業に印を付けて表示され、選んだファイルの読み取り専用の差分を見られます。

ターミナルが終了したら

ターミナルが終了したというだけで作業コピーが削除されることはありません。あなたが選びます：

  • すべてコミット済みなら Keep the branch, remove the folder（ブランチを残してフォルダーを削除）。
  • Keep everything.（すべて残す）一覧に残り、ターミナルがなくなったことが表示されます。
  • Discard both（両方を破棄）。ほかのどこにもない作業がコピーにある場合は、もう一度確認します。
aubergine copies
aubergine copies show api
aubergine copies keep-branch api
aubergine copies discard api

Aubergine はマージ、プッシュ、リベースを一切しません。残したブランチをどうするかはあなた次第です。

Aubergine があなたのリポジトリで実行するもの

Aubergine が使う git は、PATH 上にあるもの（2.31 以降）です。起動するどの Git コマンドでも、フックは動かず、何も入力を求めず、ネットワークにも接続せず、サブモジュールも取得しません。大きなファイルのストレージのように、あなた自身の Git の設定に書かれたフィルターは、あなたが git status を実行したときと同じように動きます。

サンドボックスではありません

作業コピーは作業を分けておくものです。エージェントを閉じ込めるものではありません。エージェントはあなたとして動き、あなた自身のチェックアウトを含め、あなたが読み書きできるすべてのファイルを読み書きできます。間違ったことをするエージェントを抑えるために頼らないでください。セキュリティを参照してください。

関連：複数のコーディングエージェントを同時に動かす · キューとスケジュール（新しいターミナルで始めたタスクは、フォルダーがリポジトリ内にあれば専用の作業コピーを得ます）。

5分で動かす

tmux 3.2 以降と Node.js 22 以降の入った macOS が必要です。brew install tmux node で両方が入ります。

npm install -g @meatgarden/aubergine
