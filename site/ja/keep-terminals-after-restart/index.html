コンピューターが再起動してもターミナルは残る

ブラウザーを閉じても Aubergine を再起動しても、何も失われません。どのターミナルも動き続けます。コンピューターの再起動は動いていたものを終わらせますが、Aubergine はその周りのすべてを戻すので、最初からではなく続きから再開できます。

こんなとき何が起きるか

どのターミナルも tmux セッション内のシェルで、ブラウザーとも Aubergine のサーバーとも別に動いています。中身は2か所にあります。動いているシェルは tmux だけが保持し、ターミナルについて言われていることはすべて、Aubergine が変更のたびにデータフォルダーのファイルに書き込みます。

パークしたターミナルも同じように残り、やはり新しいシェルになります。シェルがすでに終わっていたターミナルは終わったままで、Restart here（ここで再起動）が出ます。

アップデートのあと、すでに開いていたターミナルは、シェルが起動したときのもの（PATH と Aubergine のシェル連携）を、そのシェルを起動し直すまで使い続けます。Aubergine をログイン時に起動しているなら、アップデートのあとはサーバーを手で再起動する代わりに aubergine service install をもう一度実行します。

再起動のあと：作業に戻る

  1. Aubergine を起動します。ログイン時に起動する設定（aubergine service install、macOS のみ）なら、ログインした時点で動いていて、止まれば launchd がまた起動します。そうでなければ、起動してページを開きます。

    aubergine start --open

  2. キャンバスは離れたときのままです。どのターミナルも名前、色、タグ、フィールド、リンク、ノートとともに元の位置にあり、Aubergine が最後に見たフォルダーで（そのフォルダーがもうなければ既定のフォルダーで）新しいシェルになっています。何も入力し直されず、実行し直されません。

  3. エージェントを再開します。Claude Code が動いていて Aubergine がその会話を知っている（Aubergine から起動した）ターミナルでは、タイトルバーに Resume agent（エージェントを再開）が出ます。その会話で Claude Code を再び起動します。ワークフローの実行の途中にあるターミナルでは、その実行についてもう一度エージェントに伝えるので、実行が止まっているステップから続けます。

  4. それぞれがどこまで進んでいたかを見ます。ターミナルのタイトルにある Details（詳細）は、分かっていること（実行のステップと最後の報告、フォルダー、タグ）、要約、フィールドとリンク、そして Log の下にログを表示します。一覧でターミナルの名前にポインターを合わせると振り返りが出ます。

  5. キャンバスにない会話を探します。パレット（⌘K）の Past conversations…（過去の会話）、またはターミナルの詳細にある「Past conversations in this folder…」で、フォルダー内の Claude Code の過去の会話を一覧し、キャンバスに開けます。

ほかのエージェントには Resume agent はありません。Aubergine がその会話を知らないためです。同じターミナルで、そのエージェント自身の再開の方法で起動し直し、ノートを読んでどこまで進んでいたかを伝えてください。

失われるもの、そしてどうするか

  • 動いていたものは終わります。ビルド、テスト、サーバー、作業途中のエージェントはコンピューターとともに止まり、Aubergine はどれも自分では起動し直しません。自分で起動し直してください。再起動を越えて続けるべき処理は、システムのサービスのような、そのために作られた仕組みに任せます。
  • Aubergine が追っている作業はあなたを待ちます。ワークフローの実行は、ステップと提出された報告をすべて保ちます。キューのタスクは順番を保ちます。サーバーが止まった瞬間に開始中だったタスクは、理由の一文とともに失敗と記録され、自動で再試行されるものはありません。サーバーが止まっている間に過ぎたスケジュールの時刻は、6時間以内なら遅れて1回だけ実行され（schedules.lateWithinHours）、それ以外は逃したと記録されます。
  • スクロールバックは消えます。シェルが動いている間、tmux は出力された最後の50,000行を保持し、パレットの検索はそれを読みます。Aubergine はターミナルの出力を記録しないので、コンピューターの再起動のあとに戻せるものはなく、検索で見つかるのはそれ以降の出力だけです。
  • 「離れている間」は最初からになります。ファイルではなくサーバーのメモリーにあるので、サーバーの起動後はそれ以降の変化しか知らず、そのことを伝えます。

再起動を怖くなくする習慣

残るのはノートです。だからエージェントには作業しながらノートに書かせましょう。決めたこと、結果、どこで止めたか。Aubergine から起動した Claude Code では、送ったプロンプトがひとつずつ自動でログに加わり、始めにターミナルに名前を付けて要約を保つよう伝えられます。どのエージェントも次のコマンドで同じことができ、aubergine guide がその使い方を説明します。

aubergine note "Tests pass on the branch. The migration is not written yet."
aubergine describe --summary "Fixing the double redirect at sign-in"

その日の作業を終える前に、ターミナルの詳細で Ask its agent for a recap（エージェントに振り返りを頼む）を押します。エージェントは aubergine recap --write で現状を書き、その振り返りはターミナルとともに保存されます。

ノートパソコンを閉じる、スリープ、ブラウザー

  • スリープは再起動ではありません。ノートパソコンのふたを閉じると、たいていスリープします。プログラムは一時停止し、起きると続きから動き、表の最後の列のことは何も起きません。Aubergine はコンピューターを起こしたままにもせず、起こしもしないので、スリープ中に時刻が過ぎたスケジュールは、上のとおり遅れて実行されるか、逃したことになります。
  • ブラウザー、タブ、そのウィンドウを閉じても、ブラウザーのアップデートで再起動しても、何も終わりません。ページを開き直せば（aubergine open でサインインした状態で開きます）、各ターミナルが tmux から今の状態で描かれます。開いたままのページは、サーバーが戻ると自動で再接続します。
  • aubergine start が動いているウィンドウを閉じるか、そこで Ctrl+C を押すと、止まるのはサーバーだけです。表の真ん中の列にあたります。
  • WSL を使う Windows では、Windows の再起動や wsl --shutdown で WSL が止まることが、Aubergine にとってのコンピューターの再起動です。WSL を使う Windows を参照してください。

よくある質問

Aubergine は再起動のあとにターミナルを復元できますか？

はい、中で動いていたもの以外はすべて。各ターミナルは名前、色、ノート、タグ、フィールド、リンクとともにキャンバスの元の位置に戻り、最後のフォルダーで新しいシェルになります。中で動いていたプログラムは起動し直されません。Claude Code なら Resume agent で会話を続けられます。

Aubergine はターミナルの出力と履歴を残しますか？

出力は、シェルが動いている間だけです。tmux は各ターミナルのスクロールバックを50,000行保持し、ブラウザーを閉じても Aubergine を再起動しても少しも失われません。コンピューターを再起動すると消えます。Aubergine はターミナルの出力を記録しないからです。入力したコマンドの履歴（上矢印で戻ってくるもの）はシェル自身のファイルで、いつもどおりシェルが保存します。

Claude Code の会話は再起動のあとも残りますか？

会話は残ります。Claude Code が自分のファイルに保存し、Aubergine は各ターミナルがどの会話にいたかを覚えています。再起動のあと、ターミナルのタイトルバーの Resume agent がその会話で Claude Code を再び起動します。その瞬間にエージェントがしていたことは止まっていて、あなたが頼むまでやり直されません。

macOS が夜中に自動でアップデートしても大丈夫ですか？

コンピューターを再起動するアップデートは、ほかの再起動と同じです。動いていたプログラムは終わり、それ以外はすべて残ります。ログイン時に起動する設定（aubergine service install）なら、ログインした時点でサーバーがまた動いていて、キャンバスが待っています。最後のフォルダーでの新しいシェルは、Aubergine のコンテナーを再起動したときに確認しました。実際の macOS の夜間アップデートは試していません。

tmux の知識は必要ですか？

いいえ。インストールされている必要はあります（3.2 以降）が、Aubergine は専用のソケットと専用の設定で動かし、ステータスバーもプレフィックスキーもないので、tmux のコマンドを入力することはありません。あなた自身の tmux を使っていても、それには触れません。
