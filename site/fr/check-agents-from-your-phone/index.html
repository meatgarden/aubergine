Surveiller vos agents depuis votre téléphone

Vous avez laissé trois agents au travail et vous êtes sorti. L’un d’eux attend-il un oui ? Une fois configuré, Aubergine peut s’ouvrir dans le navigateur d’un téléphone : la même page et les mêmes terminaux, chaque appareil appairé avec un code à usage unique.

Ce qui a été essayé, et ce qui ne l’a pas été. L’usage depuis un autre appareil a été lancé une fois, le 22 novembre 2026 : la configuration en conteneur de docker/ sur un Mac, avec Caddy devant, sous https://aubergine.localhost, et Chromium sur le même Mac, qui s’est appairé avec un code, a tapé dans des terminaux et a été déconnecté quand son appareil a été révoqué. Pas essayé : un vrai téléphone, le scan du code QR avec un téléphone, un vrai nom avec un certificat public, un réseau privé, une machine dans le cloud, deux machines distinctes. La page n’est pas mise en page pour la largeur d’un téléphone. Le reste vient du code et de ses tests. Voyez-y quelque chose à essayer, pas une promesse.

Ce que l’on fait d’habitude

Une application SSH sur le téléphone, vers l’ordinateur, puis tmux attach à la session où tourne un agent. Ou un tunnel, ou un réseau privé qui rend l’ordinateur joignable depuis le téléphone. Les deux marchent ; surveiller plusieurs agents ainsi veut dire se rattacher à chacun tour à tour sur un petit clavier.

Ce que fait Aubergine

C’est désactivé par défaut, et cela reste lié à cet ordinateur. Le serveur n’écoute que sur 127.0.0.1, et cela ne change pas. Quelque chose sur le même ordinateur lui achemine le HTTPS sous un nom, comme le service HTTPS propre à un réseau privé ou un serveur web tel que Caddy. Aubergine ne parle jamais HTTPS lui-même.

Vous écrivez l’adresse dans les réglages. Elle va sous access.addresses dans config.json, et elle est lue au démarrage du serveur ; aucune page ni aucun programme ne peut la changer. aubergine doctor liste les adresses et ce qui ne va pas avec chacune.

Chaque appareil est appairé avec un code à usage unique. aubergine device add --name "Phone" sur l’ordinateur, ou Settings → Devices → Add a device (ajouter un appareil) dans un navigateur connecté, affiche un code et, pour chaque adresse, le code QR d’un lien qui contient le code. Scannez-le, ouvrez le lien, ou tapez le code sur la page de connexion du téléphone. Un code ne marche qu’une fois, pendant trois minutes.

Un appareil peut être révoqué. aubergine device revoke "Phone", ou Revoke… (révoquer) sous Settings → Devices, le déconnecte aussitôt et ferme ce qu’il a d’ouvert. Un appareil inutilisé pendant 90 jours cesse de fonctionner.

Un appareil appairé, c’est le propriétaire tout entier. Il peut faire tout ce que vous pouvez faire devant l’ordinateur : chaque terminal, donc un shell sur cet ordinateur, en votre nom. N’appairez que des navigateurs à qui vous confieriez votre clavier. Ce qui agit sur le bureau de l’ordinateur lui-même, Open on desktop, est absent de la page sur l’appareil, et refusé.

Ce que vous verriez

La même page que devant l’ordinateur : le canevas et ses terminaux, le compteur à côté de For you et la liste de ce qui attend, et un terminal seul à /t/<terminal> avec ses détails et sa note. Elle n’est pas mise en page pour un téléphone ; elle fonctionne comme dans une fenêtre étroite.

Les trois façons de le configurer (un tunnel SSH, un réseau privé, un nom à vous et un proxy), l’appairage, et que faire quand ça ne marche pas sont dans Using Aubergine from elsewhere. Un tunnel SSH ne demande aucun réglage, et il est peu pratique sur un téléphone.

Ce qu’il ne fait pas

  • Ni application ni push. C’est une page dans le navigateur du téléphone, à jour tant qu’elle est ouverte. Rien n’est envoyé à un téléphone dont la page est fermée.
  • Pas de réponse d’un portable en veille. Avec le serveur sur un portable, le téléphone ne le joint que tant que le portable est éveillé. Une machine qui reste allumée est l’autre option.
  • Aucune protection pour une adresse que tout le monde peut ouvrir. Sans code personne n’entre, et les codes sont difficiles à deviner, mais des inconnus essaieraient de deviner l’accès à un shell. Mettez devant un réseau privé, ou la connexion propre à votre organisation, et n’utilisez jamais le mode d’un réseau privé qui publie une machine sur tout Internet.
  • Pas de mise en page pour un téléphone. La page fonctionne comme dans une fenêtre étroite. Lire un terminal et répondre à une question marchent ainsi ; arranger un canevas, c’est pour un plus grand écran.

Questions

Puis-je surveiller mes agents de code depuis mon téléphone ?

Une fois Aubergine joignable en HTTPS et le navigateur du téléphone appairé, le téléphone affiche la même page : quel terminal attend, la liste de ce qui attend, et chaque terminal. Cela a été lancé avec un navigateur sur le même Mac, pas encore sur un vrai téléphone.

Comment appairer mon téléphone avec Aubergine ?

Lancez aubergine device add --name "Phone" sur l’ordinateur, ou utilisez Settings → Devices → Add a device. Scannez le code QR, ouvrez le lien, ou tapez le code sur la page de connexion du téléphone dans les trois minutes.

Et si je perds mon téléphone ?

Révoquez-le depuis l’ordinateur : aubergine device revoke "Phone", ou Revoke… sous Settings → Devices. Il est déconnecté aussitôt, et ce qu’il avait d’ouvert est fermé.

Est-il sûr de mettre Aubergine sur Internet ?

Une adresse que tout le monde peut ouvrir met la page de connexion devant tout le monde, et un appareil appairé a un shell sur votre ordinateur. Préférez un réseau privé, ou la connexion propre à votre organisation devant l’adresse.

Est-ce que ça marche quand mon portable est en veille ?

Non. Un portable en veille ne répond à rien, et ses terminaux sont en pause jusqu’à son réveil. Pour joindre vos agents à toute heure, le serveur doit tourner sur une machine qui reste éveillée.

Opérationnel en cinq minutes

Il vous faut macOS avec tmux 3.2 ou plus récent et Node.js 22 ou plus récent. brew install tmux node installe les deux.

npm install -g @meatgarden/aubergine
