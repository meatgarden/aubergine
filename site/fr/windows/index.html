Installer Aubergine sous Windows avec WSL

Aubergine ne tourne pas sur Windows lui-même. Il tourne dans WSL 2, le Linux fourni par Windows, et vous l’utilisez depuis votre navigateur Windows.

Ce qui a été essayé. Les étapes Linux ont été lancées le 25 novembre 2026 sous Ubuntu 24.04.5 (x86_64) dans un conteneur, pas dans WSL, avec Aubergine 0.2.2 depuis npm : il a compilé sa bibliothèque de terminal, a démarré, a connecté un navigateur, et a fait tourner un terminal et la démo. L’installation de Node.js avec nvm n’y a pas été lancée, Node.js 22 étant déjà installé. Rien sur cette page n’a encore été lancé sous Windows. Si vous essayez, dites-nous comment cela s’est passé.

Ce qu’il vous faut

Windows 11, ou Windows 10 version 2004 (build 19041) ou plus récent, où WSL 2 s’installe en une commande. La page de Microsoft sur l’installation de WSL donne les détails.

Installer et démarrer

  1. Installez WSL. Ouvrez PowerShell en tant qu’administrateur, lancez ceci, et redémarrez Windows une fois terminé. Cela installe WSL 2 avec Ubuntu.

    wsl --install

    Après le redémarrage, ouvrez Ubuntu depuis le menu Démarrer et choisissez-y un nom d’utilisateur et un mot de passe. Toutes les commandes ci-dessous se tapent là, dans Ubuntu.

  2. Installez ce dont Aubergine a besoin : tmux, zsh et Git, et les outils qui compilent sa bibliothèque de terminal, qui n’a rien de prêt à l’emploi pour Linux.

    sudo apt update

    sudo apt install -y tmux zsh git build-essential python3

    Installez Node.js 22. Le paquet d’Ubuntu est la version 18, trop ancienne. Une méthode bien connue est nvm : installez-le, ouvrez une nouvelle fenêtre Ubuntu, puis installez Node.js 22.

    curl -o- https://raw.githubusercontent.com/nvm-sh/nvm/v0.40.3/install.sh | bash

    nvm install 22

    node -v doit maintenant afficher v22 ou plus récent.

  3. Installez Aubergine depuis npm. Il compile sa bibliothèque de terminal pendant l’installation ; lors de l’essai, l’installation entière a pris 13 secondes.

    npm install -g @meatgarden/aubergine

  4. Démarrez-le, et laissez cette fenêtre ouverte :

    aubergine start

    Connectez votre navigateur. Dans une deuxième fenêtre Ubuntu, affichez l’adresse de connexion, puis ouvrez-la dans votre navigateur sous Windows. Elle connecte ce navigateur : traitez-la comme un mot de passe.

    aubergine open --print

    Ensuite, http://127.0.0.1:4600 fonctionne tout seul dans ce navigateur. Sur un canevas vide, Show me around lance la visite.

Bon à savoir

  • Gardez vos projets dans Ubuntu, dans son dossier personnel, pas sous /mnt/c, où les fichiers de Windows passent par une passerelle plus lente.
  • Installez vos agents dans Ubuntu, Claude Code, Codex ou un autre, comme sur n’importe quel Linux. Un agent installé sous Windows n’est pas dans les terminaux d’Aubergine.
  • Les terminaux vivent tant que WSL tourne. Fermer le navigateur n’arrête rien, et Ctrl+C dans la fenêtre de aubergine start n’arrête que le serveur. Quand WSL s’arrête, parce que Windows redémarre ou après wsl --shutdown, les terminaux se terminent, et le aubergine start suivant ouvre de nouveaux shells dans leurs derniers dossiers, comme après un redémarrage sur un Mac.
  • bash ou zsh. Le shell d’Ubuntu est bash, et les terminaux y fonctionnent. L’état des commandes sur un terminal (occupé, le code de sortie d’une commande en échec) ne vient que de zsh : lors de l’essai, un terminal zsh a affiché exit 3 après une commande en échec. Faites de zsh votre shell dans Ubuntu pour l’avoir.
  • Ce qui n’y est pas : le démarrage à l’ouverture de session ne fonctionne que sous macOS (aubergine service install le dit), et Open on desktop n’a pas de réglage pour une application de terminal Windows. aubergine open n’a trouvé aucun navigateur à ouvrir lors de l’essai ; aubergine open --print fonctionne toujours.
  • Les raccourcis sous Windows ont été choisis d’après la documentation des navigateurs et n’ont pas été mesurés : voir docs/keys.md. La palette fonctionne toujours.

Si quelque chose ne va pas

Lancez d’abord aubergine doctor dans Ubuntu. Il vérifie Node.js, tmux, Git et le serveur.

Ce que vous voyezQue faire
L’installation d’Aubergine échoue en compilant node-ptyLes outils de compilation manquent. Lancez les lignes apt de l’étape 2, puis réinstallez Aubergine.
Une page disant que tmux manque ou est trop ancienLe tmux d’Ubuntu 24.04 est en version 3.4, assez récente : sudo apt install -y tmux, puis redémarrez le serveur.
node -v affiche une version antérieure à v22Installez Node.js 22 comme à l’étape 2, ouvrez une nouvelle fenêtre Ubuntu, puis réinstallez Aubergine.
L’adresse ne s’ouvre pas dans le navigateur sous WindowsVérifiez que aubergine start tourne toujours dans Ubuntu. Puis voyez la page de Microsoft sur le réseau dans WSL ; cela n’a pas été essayé avec Aubergine.

Ensuite

Arrêter, mettre à jour et désinstaller se font comme sur la page d’installation, et tout le reste est dans le README.

npm install -g @meatgarden/aubergine
