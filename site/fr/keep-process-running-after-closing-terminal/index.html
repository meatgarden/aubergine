Garder un processus en marche après avoir fermé le terminal

Vous avez lancé une compilation, un serveur ou un agent de code, et fermer la fenêtre l’arrêterait. Dans Aubergine, fermer la fenêtre n’arrête rien : chaque terminal tourne à part du navigateur, et ce qu’il a affiché est là quand vous revenez.

Ce que l’on fait d’habitude

Fermer une fenêtre de terminal arrête le shell qu’elle contient, et avec lui ce que ce shell a lancé. Les façons habituelles de l’éviter :

  • nohup lance une commande qui ignore le signal de raccrochage envoyé quand le terminal se ferme. Sa sortie va dans un fichier (nohup.out, sauf si vous l’envoyez ailleurs).
  • disown, dans bash et zsh, lâche une tâche déjà lancée, pour que le shell ne lui transmette pas le signal de raccrochage. Vous ne pouvez plus y revenir dans un terminal ensuite.
  • screen et tmux font tourner le shell dans un serveur à eux. Vous vous détachez, fermez la fenêtre, et vous rattachez plus tard au même shell avec sa sortie. C’est la réponse fiable, et il faut apprendre leurs touches et leurs commandes pour s’en servir.

Aubergine repose sur la dernière de ces solutions. Il fait tourner tmux pour vous : vous avez sa réponse sans ses touches.

Ce que fait Aubergine

Chaque terminal d’Aubergine est un shell dans sa propre session tmux, sur un socket tmux propre à Aubergine. tmux tourne à part du navigateur et du serveur d’Aubergine, donc :

  • Fermer l’onglet, la fenêtre ou tout le navigateur n’arrête rien. Rouvrez la page (aubergine open l’ouvre connectée) et chaque terminal est dessiné depuis tmux tel qu’il est maintenant, avec ce qu’il a affiché entre-temps dans son historique de défilement.
  • Arrêter Aubergine n’arrête rien non plus. Ctrl+C là où tourne aubergine start, un plantage du serveur ou une mise à jour arrête le serveur et rien d’autre. Relancez-le et rechargez la page.
  • Fermer un terminal sur le canevas le met de côté. Le × de son titre le retire du canevas, et son shell continue de tourner. Parked (mis de côté), dans la barre au-dessus du canevas, liste les terminaux mis de côté, et Restore (restaurer) en ramène un.
  • Terminer un shell pour de bon demande d’abord. End (terminer), dans la liste des terminaux mis de côté, ne termine un terminal qu’après votre oui.
  • Les autres vues d’un terminal n’arrêtent rien. Tab ↗ dans le titre d’un terminal l’ouvre seul dans un onglet du navigateur, et aubergine attach <name> l’affiche dans une fenêtre de votre application de terminal. C’est chaque fois le même terminal, pas une copie ; fermer cet onglet ou cette fenêtre le laisse tourner.

Tant qu’un shell tourne, tmux garde les 50 000 dernières lignes qu’il a affichées. La molette les fait défiler dans le terminal qui a le clavier, et la palette (⌘K) y cherche.

Ce qu’il ne fait pas

  • Il ne survit pas au redémarrage de l’ordinateur. Un redémarrage, un plantage de l’ordinateur ou une mise à jour qui le redémarre arrête chaque shell et ce qui y tourne. Aubergine ramène tout ce qui les entoure, chaque terminal sous la forme d’un nouveau shell dans son dernier dossier, et ne relance rien de lui-même. Voir Garder vos terminaux après un redémarrage.
  • Il ne garde pas l’ordinateur éveillé. Un portable en veille met ses programmes en pause, ceux-ci compris ; ils reprennent à son réveil.
  • Ce n’est pas un gestionnaire de services. Une tâche qui doit revenir d’elle-même après un redémarrage a sa place dans les services de votre système.
  • Il ne peut pas reprendre un programme qui tourne déjà ailleurs. Aucun outil ne peut déplacer un programme en cours dans un autre terminal. aubergine here, dans un onglet de votre application de terminal, donne à ce dossier un terminal sur le canevas ; un programme qui tourne dans l’onglet y reste, et doit être relancé dans le nouveau terminal.

Sur une autre machine, par SSH

Aubergine tourne sur votre propre ordinateur : son serveur écoute sur 127.0.0.1, et ses terminaux sont des shells de cet ordinateur. Si ce que vous voulez garder est un processus sur un serveur distant que vous joignez par SSH, tmux ou screen sur ce serveur reste la réponse.

Aubergine lui-même peut tourner sur une autre machine et s’utiliser depuis votre navigateur, par un tunnel SSH, un réseau privé, ou un nom et un proxy : les étapes sont dans Using Aubergine from elsewhere. Avec un tunnel SSH, fermer la fenêtre SSH où tourne aubergine start arrête le serveur, et les terminaux continuent de tourner. Linux n’a été lancé que dans des conteneurs, jamais sur une machine dans le cloud.

Questions

Fermer le navigateur arrête-t-il mon terminal ?

Non. Chaque terminal est un shell dans tmux, qui tourne à part du navigateur. Fermez l’onglet, la fenêtre ou le navigateur, rouvrez la page, et chaque terminal est tel qu’il est maintenant, toujours en marche, avec ce qu’il a affiché entre-temps.

Comment garder un processus en marche après une déconnexion SSH ?

Sur la machine distante, lancez-le dans tmux ou screen, ou avec nohup. Aubergine garde les terminaux de l’ordinateur où il tourne. Il peut aussi tourner sur une machine distante, utilisé par un tunnel SSH ou un proxy, mais cela n’a été lancé que dans des conteneurs, jamais sur une machine dans le cloud.

Faut-il utiliser nohup ou tmux ?

nohup convient à une commande dont la sortie peut aller dans un fichier. tmux convient à un shell auquel vous voulez revenir et dans lequel vous voulez taper. Aubergine donne la seconde solution à chaque terminal, dans une page du navigateur, sans les touches de tmux.

Puis-je voir la sortie après avoir fermé le terminal ?

Oui, tant que le shell tourne : tmux garde les 50 000 dernières lignes de chaque terminal, et la page les affiche quand vous revenez. Aubergine n’enregistre rien lui-même : après un redémarrage de l’ordinateur, cette sortie est perdue.

Continuera-t-il de tourner après un redémarrage ?

Non. Un redémarrage de l’ordinateur arrête tous les programmes. Aubergine ramène chaque terminal sous la forme d’un nouveau shell dans son dernier dossier, avec sa place, son nom et sa note, et ne relance rien.

Opérationnel en cinq minutes

Il vous faut macOS avec tmux 3.2 ou plus récent et Node.js 22 ou plus récent. brew install tmux node installe les deux.

npm install -g @meatgarden/aubergine
