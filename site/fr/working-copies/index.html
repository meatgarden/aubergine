Deux agents, un dépôt : les copies de travail

Chaque terminal travaille normalement dans votre vrai dossier. Deux agents dans un même dépôt modifient alors les mêmes fichiers, et vous ne savez plus quelle modification est de qui. Une copie de travail donne à chaque terminal sa propre extraction, sur sa propre branche.

Lancer un terminal dans une copie de travail

  1. Appuyez sur ▾ au bout de New terminal, en haut de la liste des terminaux, puis sur Shell in a folder or a working copy….
  2. Indiquez le dossier et choisissez In its own working copy (dans sa propre copie de travail). Le choix n’est proposé que là où il est possible, et dit pourquoi là où il ne l’est pas : pas un dépôt Git, un dépôt nu, ou encore aucun commit.

Depuis un terminal, la même chose :

aubergine here --copy
aubergine new "api" --copy --in ~/code/my-project

Ce que vous obtenez

Un worktree Git dans un dossier qu’Aubergine garde sous son dossier de données, jamais dans votre dépôt, sur une nouvelle branche nommée aubergine/<terminal name>-<six characters>. Il part du commit sur lequel est votre extraction, et le terminal démarre dans le même sous-dossier que celui où vous étiez. Votre propre extraction n’est jamais modifiée : ni ses fichiers, ni ce qui est indexé, ni la branche que vous avez extraite.

Pas repris : vos modifications non commitées (rien n’est mis de côté ni commité pour vous), et les fichiers que Git ignore ou ne suit pas, comme les dépendances installées et les réglages locaux. Un projet qui a besoin d’une étape d’installation en a de nouveau besoin dans la copie de travail.

Lire ce qu’un agent a modifié

Un terminal dans une copie de travail affiche dans sa barre de titre sa branche et le nombre de fichiers qui diffèrent. Cliquez dessus pour voir les fichiers modifiés, ajoutés et supprimés, avec le travail qui n’est dans aucun commit signalé, et la différence en lecture seule pour le fichier de votre choix.

Quand le terminal se termine

Une copie de travail n’est jamais supprimée simplement parce que son terminal s’est terminé. Vous choisissez :

  • Keep the branch, remove the folder (garder la branche, supprimer le dossier), quand tout est commité.
  • Keep everything. Tout garder : elle reste dans la liste, en indiquant que son terminal n’est plus là.
  • Discard both (tout jeter), qui demande une seconde fois quand la copie contient du travail qui n’existe nulle part ailleurs.
aubergine copies
aubergine copies show api
aubergine copies keep-branch api
aubergine copies discard api

Aubergine ne fusionne, ne pousse et ne rebase jamais. Ce que vous faites d’une branche gardée vous appartient.

Ce qu’Aubergine exécute dans votre dépôt

Aubergine utilise le git de votre PATH (2.31 ou plus récent). Pour chaque commande Git qu’elle lance, aucun hook ne s’exécute, rien ne demande de saisie, rien n’accède au réseau, et les sous-modules ne sont pas récupérés. Les filtres nommés dans votre propre configuration Git, comme le stockage des gros fichiers, s’exécutent bien, comme pour votre propre git status.

Ce n’est pas un bac à sable

Une copie de travail garde le travail séparé. Elle n’enferme pas un agent : l’agent tourne en votre nom et peut lire et modifier tous les fichiers que vous pouvez lire et modifier, y compris votre propre extraction. Ne comptez pas sur elle pour retenir un agent qui fait une erreur. Voir sécurité.

Voir aussi : faire tourner plusieurs agents de code à la fois · la file d’attente et les planifications (une tâche lancée sur un nouveau terminal reçoit sa propre copie de travail quand le dossier est dans un dépôt).

Opérationnel en cinq minutes

Il vous faut macOS avec tmux 3.2 ou plus récent et Node.js 22 ou plus récent. brew install tmux node installe les deux.

npm install -g @meatgarden/aubergine
