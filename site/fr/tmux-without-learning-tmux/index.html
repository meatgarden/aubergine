tmux sans apprendre tmux

tmux garde vos shells en marche quand la fenêtre se ferme. Il vous demande aussi d’apprendre une touche de préfixe, un mode copie et un fichier de configuration. Aubergine fait tourner tmux pour vous, et vous utilisez chaque terminal dans une page du navigateur comme n’importe quel terminal.

Pour qui

Pour qui veut ce que donne tmux, des shells qui survivent à la fenêtre, sans ses touches ni sa configuration. Si vous vivez déjà dans tmux, gardez-le : Aubergine laisse votre tmux tranquille.

Ce que l’on fait d’habitude

Apprendre tmux : une touche de préfixe (Ctrl+B, sauf si vous la changez) avant chaque commande, tmux attach pour revenir, et des lignes dans ~/.tmux.conf pour la souris et le presse-papiers. Ou screen, un outil plus ancien du même genre. Voici chaque geste courant dans tmux par défaut et dans Aubergine :

Ce que fait Aubergine

Son propre socket et sa propre configuration. Aubergine lance tmux sur un socket à lui, nommé aubergine, avec un fichier de configuration à lui au lieu du vôtre : pas de barre d’état, pas de touche de préfixe, la souris activée, 50 000 lignes d’historique. Chaque terminal est une session tmux avec un shell, votre shell de connexion. Votre propre tmux, ses sessions et votre ~/.tmux.conf ne sont pas touchés.

La molette remonte l’historique du terminal qui a le clavier ; partout ailleurs sur le canevas, elle zoome.

Sélectionnez à la souris et c’est copié dans votre presse-papiers quand vous relâchez : tmux transmet la sélection à la page avec OSC 52, la séquence d’échappement qu’utilisent les terminaux pour le presse-papiers, et la page l’y met. Collez avec ⌘V (Ctrl+Shift+V hors de macOS). Un collage de plusieurs lignes est encadré, pour qu’un shell ne l’exécute pas ligne par ligne.

Redimensionnez en faisant glisser les bords d’un terminal sur le canevas, et le shell reçoit sa nouvelle taille. Un terminal ouvert à deux endroits à la fois a une seule taille, fixée par la vue dans laquelle vous avez tapé en dernier.

C’est toujours tmux en dessous. aubergine attach <name> affiche un terminal dans une fenêtre de votre application de terminal, et Open on desktop (ouvrir sur le bureau), dans le menu d’un terminal, le fait pour vous (sous macOS dans Terminal ou iTerm ; sous Linux avec une ligne de commande que vous définissez). Serveur arrêté, tmux -L aubergine ls et tmux -L aubergine attach -t <id> atteignent toujours chaque shell.

Ce qu’il vous faut

tmux 3.2 ou plus récent, installé par vous : brew install tmux sous macOS, le paquet de votre système sous Linux. Aubergine ne l’installe pas, et affiche une page qui le dit quand il manque ou qu’il est trop ancien. Avec zsh, le titre d’un terminal montre la commande en cours et comment la dernière s’est terminée ; les autres shells tournent sans cela.

Ce qu’il n’est pas

  • Pas tmux sur un serveur distant. Le tmux d’Aubergine tourne sur l’ordinateur où tourne son serveur. Pour un shell sur une machine que vous joignez par SSH, tmux sur cette machine reste l’outil. Aubergine lui-même peut tourner sur une autre machine (Using Aubergine from elsewhere) ; cela n’a été lancé que dans des conteneurs.
  • Vos propres sessions tmux ne sont pas affichées. Le canevas ne contient que les terminaux d’Aubergine. aubergine scan liste les shells interactifs ouverts sur cet ordinateur hors d’Aubergine, et aubergine import ou aubergine here donne à l’un d’eux un nouveau terminal sur le canevas dans le même dossier ; un programme qui tourne dans l’ancien y reste. Les lignes que propose aubergine shell-hook print pour votre .zshrc ne font rien dans tmux.
  • Ni touches tmux ni volets. Il n’y a pas de touche de préfixe, et vos propres raccourcis tmux ne s’appliquent pas. Tant qu’un terminal a le clavier, chaque touche va au programme qui y tourne, sauf quelques combinaisons choisies pour qu’aucun shell, éditeur ni tmux n’en ait besoin.
  • Pas sous Windows lui-même. Il faut tmux et un shell Unix ; sous Windows, il tourne dans WSL 2. Voir Windows avec WSL.

Questions

Puis-je utiliser tmux sans apprendre les raccourcis ?

Oui. Aubergine fait tourner tmux sans touche de préfixe ni barre d’état : vous ne tapez jamais de commande tmux. Fermez l’onglet pour partir, ouvrez la page pour revenir, faites défiler avec la molette, copiez en sélectionnant.

Aubergine modifie-t-il ma configuration tmux ?

Non. Il fait tourner tmux sur un socket à lui, aubergine, avec un fichier de configuration à lui. Votre serveur tmux, ses sessions et votre ~/.tmux.conf restent tels quels.

Comment faire défiler et copier dans les terminaux d’Aubergine ?

Cliquez sur un terminal pour lui donner le clavier, puis remontez avec la molette. Sélectionnez du texte à la souris : il est dans votre presse-papiers quand vous relâchez. Collez avec ⌘V, ou Ctrl+Shift+V hors de macOS.

Puis-je me rattacher à un terminal Aubergine depuis ma propre application de terminal ?

Oui : aubergine attach <name>, ou Open on desktop dans le menu du terminal. C’est le même terminal aux deux endroits ; ce que vous tapez dans l’un s’affiche dans l’autre.

Aubergine peut-il remplacer tmux sur un serveur où je me connecte par SSH ?

Pas tel quel : ses terminaux sont sur la machine où tourne son serveur. Il peut tourner sur un serveur et s’utiliser depuis votre navigateur par un tunnel SSH ou un proxy, ce qui n’a été lancé que dans des conteneurs, jamais sur une machine dans le cloud.

Opérationnel en cinq minutes

Il vous faut macOS avec tmux 3.2 ou plus récent et Node.js 22 ou plus récent. brew install tmux node installe les deux.

npm install -g @meatgarden/aubergine
