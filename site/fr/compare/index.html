Outils pour faire tourner plusieurs agents de code, comparés

Sept outils pour le même moment : plus d’un agent de code au travail, et vous au milieu. Voici Aubergine à côté de Conductor, Claude Squad, Vibe Kanban, cmux, Warp et Paradev, avec une page pour chacun.

Comment ceci a été écrit. Ce que ces pages disent d’un autre outil vient du site, de la documentation et du dépôt de cet outil, lus le 26 novembre 2026, et chaque page renvoie vers eux. Nous n’avons pas fait tourner les autres outils. Là où leur documentation ne dit rien, la page dit que rien n’a été trouvé, pas que l’outil ne sait pas le faire. Ces outils changent vite : si quelque chose ici est faux ou dépassé, dites-le-nous et ce sera corrigé.

Une page pour chacun

Chaque page a le tableau complet pour les deux, ce qui les distingue, et ce que l’autre outil a et qu’Aubergine n’a pas.

  • Aubergine vs Conductor

    Choisissez Conductor si vous voulez une app Mac qui mène une tâche d’un prompt jusqu’à une pull request fusionnée, avec un cloud pour le travail qui continue quand votre Mac est éteint.

  • Aubergine vs Claude Squad

    Choisissez Claude Squad si vous vivez dans un terminal et y voulez un seul petit programme qui lance des agents dans des worktrees et pousse leurs branches, et rien de plus.

  • Aubergine vs Vibe Kanban

    Choisissez Vibe Kanban si vous pensez en tickets : planifier sur un tableau, confier chaque carte à un agent, relire son diff avec des commentaires, et fusionner.

  • Aubergine vs cmux

    Choisissez cmux si vous voulez une app de terminal Mac native et rapide, avec des volets, un navigateur intégré et des notifications macOS, et que vous scriptez vous-même votre façon de travailler par-dessus.

  • Aubergine vs Warp

    Choisissez Warp si vous voulez une seule app de terminal pour tout, aussi sous Windows et Linux, avec son propre agent intégré et des agents dans le cloud que vous pouvez planifier.

  • Aubergine vs Paradev, anciennement Superset

    Choisissez Paradev si vous voulez une app de bureau qui crée un worktree pour chaque tâche et la mène à travers le diff, les vérifications et la fusion, avec des apps mobiles et un cloud quand vous payez pour eux.

Ce autour de quoi Aubergine est construite

  • Des terminaux ordinaires. Un agent tourne dans Aubergine comme il tourne dans n’importe quelle app de terminal. Il n’y a pas de vue de chat par-dessus, et rien entre vous et ce qu’il affiche.
  • Tous en vue. Les terminaux se tiennent côte à côte sur un canevas que vous déplacez et zoomez, avec une seule liste de tous les terminaux et de leur état en toutes lettres. Voir Trouver le bon terminal.
  • Fermer la fenêtre n’arrête rien. Chaque terminal est une session tmux, donc le navigateur et Aubergine elle-même peuvent s’arrêter pendant que vos agents continuent. Voir ce qu’un redémarrage garde.
  • Votre ordinateur seulement. Pas de compte, pas de cloud, pas d’offre payante et pas de modèle à elle ; le serveur écoute sur 127.0.0.1. Voir la sécurité.
  • Une personne décide. Ce qu’un agent propose attend votre relecture, une approbation dans un workflow n’appartient qu’à vous, et une seule liste, For you, contient tout ce qui vous attend. Voir la file d’attente.

Ce qu’Aubergine n’a pas

  • Pas d’application de bureau ni d’application mobile. C’est une page dans votre navigateur. Un autre appareil peut être appairé par un proxy que vous faites tourner ; cela a été lancé une fois sur un Mac, et jamais sur un vrai téléphone.
  • Pas de pull requests ni de fusion. Elle montre ce qui a changé dans une copie de travail, fichier par fichier, et ne fait jamais de commit, de push, de rebase ni de fusion.
  • Pas de cloud. Les agents tournent sur l’ordinateur où tourne Aubergine, et les planifications ne se déclenchent que tant qu’il est allumé.
  • Pas de son ni de push. Les notifications viennent d’une page Aubergine ouverte dans votre navigateur.
  • Faite pour macOS. Sous Linux, elle n’a été lancée que dans des conteneurs ; sous Windows, elle ne tourne que dans WSL 2, ce qui n’a pas été essayé.
  • Surtout pour Claude Code. Tout agent en ligne de commande tourne dans un terminal, mais ce qu’Aubergine fait d’elle-même pour un agent (voir qu’il attend, reprendre une conversation) est fait pour Claude Code ; un autre agent rend compte avec les commandes aubergine.

Questions

Quel est le meilleur outil pour faire tourner plusieurs agents Claude Code à la fois ?

Cela dépend de ce que vous voulez autour des agents. Pour une app Mac avec des diffs, des pull requests et la fusion : Conductor ou Paradev. Pour un programme dans le terminal que vous utilisez déjà : Claude Squad. Pour un tableau de tickets : Vibe Kanban. Pour un terminal Mac natif : cmux. Pour un terminal avec son propre agent et des agents dans le cloud : Warp. Pour de simples terminaux côte à côte dans une page du navigateur, maintenus en marche par tmux, sans compte : Aubergine.

Lesquels de ces outils sont open source ?

D’après ce qui a été lu le 26 novembre 2026 : Aubergine (MIT), Paradev (MIT), Vibe Kanban (Apache-2.0), Claude Squad (AGPL-3.0), l’app cmux (GPL-3.0-or-later) et le client Warp (AGPL-3.0). Les conditions de Conductor le disent propriétaire.

Lesquels de ces outils tournent sous Linux ou Windows ?

D’après leur propre documentation : Warp sous macOS, Windows et Linux ; Vibe Kanban sur les trois ; Claude Squad sous macOS et Linux, et sous Windows avec tmux par WSL ; Paradev sous macOS avec une version expérimentale pour Linux ; Conductor et cmux sous macOS seulement. Aubergine est faite pour macOS, n’a été lancée sous Linux que dans des conteneurs, et ne tourne sous Windows que dans WSL 2, pas encore essayé.

Lesquels gardent les agents en marche après la fermeture de l’app ?

Aubergine et Claude Squad font tourner chaque agent dans une session tmux. Paradev documente un daemon d’arrière-plan qui garde les terminaux quand sa fenêtre se ferme. cmux ne garde les processus en cours que dans son mode tmux, à activer. Conductor dit que les sessions locales s’arrêtent avec l’app. Warp restaure les fenêtres et la sortie récente, pas les programmes en cours. Conductor, cmux, Warp et Paradev ont aussi chacun un cloud où les agents continuent. Aucun, Aubergine comprise, ne garde un agent local en marche à travers un redémarrage de l’ordinateur.

Opérationnel en cinq minutes

Il vous faut macOS avec tmux 3.2 ou plus récent et Node.js 22 ou plus récent. brew install tmux node installe les deux.

npm install -g @meatgarden/aubergine
