Questions fréquentes

Des réponses courtes. Les guides vont plus loin.

Qu’est-ce qu’Aubergine ?

Un canevas local de sessions de terminal, dans le navigateur. Chaque terminal est un nœud que vous pouvez disposer et utiliser, pour faire tourner plusieurs agents de code à la fois et voir lequel vous attend.

Aubergine est-elle gratuite et open source ?

Oui. Elle est gratuite et son code source est sur GitHub.

De quoi ai-je besoin pour faire tourner Aubergine ?

macOS avec tmux 3.2 ou plus récent et Node.js 22 ou plus récent ; l’installeur a aussi besoin de pnpm. Sous Linux, il n’a été lancé que dans des conteneurs. Sous Windows, il ne tourne que dans WSL 2, ce qui n’a pas encore été essayé : voir le guide pour Windows.

Est-ce que ça fonctionne avec n’importe quel agent de code ?

Aubergine fait tourner des terminaux ordinaires, donc n’importe quel agent en ligne de commande peut y tourner. Ce qu’Aubergine fait d’elle-même pour un agent, comme voir qu’il attend, est conçu pour Claude Code ; tout autre agent, Codex compris, peut signaler son état avec les commandes aubergine et une API locale, et peut utiliser un serveur MCP qui ne liste que ce que son jeton permet.

Aubergine envoie-t-elle mes terminaux ou mon code quelque part ?

Non. Tout tourne sur votre propre ordinateur. Le serveur écoute uniquement sur 127.0.0.1.

Aubergine appelle-t-elle un modèle d’IA ?

Non. Ce sont vos agents qui le font. Aubergine se contente de faire tourner leurs terminaux et d’en garder le suivi, et ne détient de clé pour aucun modèle.

Que deviennent mes terminaux quand je ferme le navigateur ?

Ils continuent de tourner. Chaque session est une session tmux qui survit au navigateur comme au serveur Aubergine.

Comment savoir quel agent m’attend ?

Chaque terminal indique s’il est occupé, inactif ou en attente. Le compteur à côté de For you en haut de la page et la liste For you rassemblent tout ce qui a besoin de vous.

Comment empêcher deux agents de modifier les mêmes fichiers ?

Lancez chaque terminal dans sa propre copie de travail : sa propre extraction sur sa propre branche. Aubergine ne fusionne ni ne pousse jamais à votre place.

Puis-je donner à un agent une liste d’étapes à suivre ?

Oui. Un workflow est une liste ordonnée d’étapes, avec une bande qui montre où en est l’agent. Une étape peut attendre que vous l’approuviez ou la renvoyiez.

Les agents peuvent-ils se parler ?

Oui, dans certaines limites. Les messages entre terminaux ont des expéditeurs nommés, des pauses et des blocages, et sont fermés par défaut pour chaque canevas.

Y a-t-il une API ?

Oui. Une API HTTP locale avec des jetons à portée limitée, un client typé, et un serveur MCP qui ne liste que les outils qu’un identifiant peut utiliser.

Puis-je ouvrir un terminal à part ?

Oui. Tab ↗ dans le titre d’un terminal l’ouvre dans un onglet du navigateur à lui seul, le même terminal et pas une copie, avec ses détails et sa note à côté quand vous les demandez. Fermer l’onglet ne termine rien.

Puis-je associer un ticket ou un responsable à un terminal ?

Oui. Un terminal a des champs, des paires d’un libellé et d’une valeur, dans ses détails. L’agent qui s’y trouve peut définir les siens avec aubergine field set ; là où vous avez défini le même libellé, le vôtre reste.

Aubergine prendra-t-elle en charge plusieurs personnes ou des agents dans le cloud ?

Les deux sont prévus et aucun n’est construit. Voir la feuille de route. Aujourd’hui, tout tourne sur un seul ordinateur.

Que modifie le script d’installation sur mon ordinateur ?

Deux choses : le dossier d’installation (~/.aubergine) et un lien nommé aubergine. Il n’utilise jamais sudo, ne modifie jamais les fichiers de démarrage de votre shell et n’installe jamais Node.js, pnpm ou tmux.
