Seguridad y privacidad

Lo que hace Aubergine para proteger tus terminales y, igual de importante, lo que no hace. En resumen: es local, pregunta antes de actuar en nombre de un agente, y los agentes siguen ejecutándose como tú.

Todo se queda en tu ordenador

  • El servidor se enlaza solo a 127.0.0.1. En cada petición, y en cada upgrade de WebSocket, se comprueban Host y Origin, y el navegador debe tener una cookie de acceso.
  • Usar Aubergine desde otro dispositivo está desactivado hasta que lo configures: algo en el mismo ordenador le lleva HTTPS bajo un nombre que escribes en los ajustes, y cada navegador se empareja con un código de un solo uso y se puede revocar. Un dispositivo emparejado puede hacer todo lo que puede hacer el propietario. Usar Aubergine desde otro sitio explica cómo.
  • Aubergine no llama a ningún modelo ni inicia ninguna petición de red propia, con dos excepciones: descargar una fuente de la biblioteca (una dirección Git) cuando tú lo pides, y preguntar a tu propia herramienta gh, donde está instalada y con la sesión iniciada, por la pull request de la rama de una terminal.
  • Las notificaciones de escritorio vienen de la página abierta. Nada sale de tu ordenador.

Tres tipos de llamante, cada uno juzgado por separado

Cada petición se comprueba contra lo que el llamante puede hacer antes de buscar nada, así que un llamante sin permiso no averigua nada por la respuesta. Los llamantes son tú (con la sesión iniciada en el navegador), la sesión de un agente y un token de API.

  • Los tokens de API tienen alcances. El secreto se muestra una vez y nunca se guarda; solo se conserva un hash. Las llamadas hechas con un token van a un registro de actividad: quién, qué y cómo terminó, nunca el secreto y nunca lo que se envió.
  • Hay cosas que ningún token puede hacer nunca: crear o revocar tokens, leer el registro de actividad, cambiar los ajustes, y nada que tenga que ver con terminales fuera de Aubergine.
  • El acceso a las terminales son dos alcances distintos, uno para leer y otro para escribir, cada uno limitado a las sesiones que elijas. Puedes marcar una terminal como people only (solo personas) para cerrarla a todos los tokens.
  • La credencial propia de un agente es limitada. Puede marcar su propia atención, añadir a sus propias notas, informar de su propio estado y leer la ejecución en la que está. No puede llegar a otras terminales, lienzos ni tokens.

Lo que un agente no puede hacer solo

  • Lo que escribe un agente o un programa (un flujo de trabajo, un paso) llega como un borrador que tú revisas. Aceptarlo te corresponde solo a ti.
  • Un paso que espera a una persona solo puede aprobarlo o devolverlo una persona. Las reglas, las programaciones y la demo son solo tuyas.
  • Aubergine solo escribe unas pocas frases fijas en la terminal de un agente, como «lee tu siguiente paso». No se escribe nada que hayas guardado ni nada que haya escrito un agente.
  • Instalar desde una biblioteca requiere que aceptes exactamente el contenido que se te mostró.

Contra qué no protege esto

Los agentes se ejecutan como tú. Un agente en una terminal puede hacer cualquier cosa que puedas hacer tú en esa terminal, incluido ejecutar comandos, leer archivos y, si quiere, usar la sesión de tu propio navegador.

  • Las aprobaciones no son un candado. Un agente que se ejecuta como tú puede decidir como tú. La decisión queda registrada, no se impide.
  • Las copias de trabajo no son un sandbox. Mantienen el trabajo separado y no encierran a un agente.
  • La pantalla de revisión es el control de los elementos de la biblioteca. Un elemento son instrucciones que un agente seguirá con todo lo que ese agente puede hacer. No instales lo que no hayas leído.
  • La guía para agentes es un consejo, no un candado.

El instalador

Cambia dos cosas: su propia carpeta y un enlace llamado aubergine. Sin sudo, sin editar los archivos de inicio de tu shell, y nunca toca tu carpeta de datos. aubergine uninstall solo quita lo que creó.

Informar de un problema

Abre una issue en GitHub. No incluyas secretos ni tokens.

En marcha en cinco minutos

Necesitas macOS con tmux 3.2 o posterior y Node.js 22 o posterior. brew install tmux node instala ambos.

npm install -g @meatgarden/aubergine
