Dos agentes, un repositorio: copias de trabajo

Normalmente cada terminal trabaja en tu carpeta real. Entonces dos agentes en un mismo repositorio editan los mismos archivos, y no puedes saber qué cambio es de quién. Una copia de trabajo le da a cada terminal su propio checkout, en su propia rama.

Inicia una terminal en una copia de trabajo

  1. Pulsa ▾ al final de New terminal, arriba de la lista de terminales, y luego Shell in a folder or a working copy….
  2. Indica la carpeta y elige In its own working copy (en su propia copia de trabajo). La opción solo se ofrece donde es posible, y dice por qué donde no lo es: no es un repositorio Git, es un repositorio bare o aún no tiene ningún commit.

Desde una terminal, lo mismo:

aubergine here --copy
aubergine new "api" --copy --in ~/code/my-project

Qué obtienes

Un worktree de Git en una carpeta que Aubergine guarda dentro de su carpeta de datos, nunca dentro de tu repositorio, en una rama nueva llamada aubergine/<terminal name>-<six characters>. Parte del commit en el que está tu checkout, y la terminal empieza en la misma subcarpeta en la que estabas. Tu propio checkout nunca se cambia: ni sus archivos, ni lo que está en el staging, ni la rama que tienes activa.

No se trasladan: tus cambios sin commit (no se hace stash ni commit de nada por ti), ni los archivos que Git ignora o no sigue, como las dependencias instaladas y los ajustes locales. Un proyecto que necesita un paso de instalación lo necesita de nuevo en la copia de trabajo.

Lee lo que cambió un agente

Una terminal en una copia de trabajo muestra en su barra de título su rama y el número de archivos que difieren. Haz clic ahí para ver los archivos cambiados, añadidos y eliminados, con el trabajo que no está en ningún commit marcado, y la diferencia, de solo lectura, de cualquier archivo que elijas.

Cuando la terminal termina

Una copia de trabajo nunca se elimina solo porque su terminal haya terminado. Tú eliges:

  • Keep the branch, remove the folder (conservar la rama, eliminar la carpeta), cuando todo está en commits.
  • Keep everything. (Conservarlo todo). Se queda en la lista, indicando que su terminal ya no existe.
  • Discard both (descartar ambas), que pregunta una segunda vez cuando la copia contiene trabajo que no existe en ningún otro sitio.
aubergine copies
aubergine copies show api
aubergine copies keep-branch api
aubergine copies discard api

Aubergine nunca hace merge, push ni rebase. Lo que hagas con una rama conservada es cosa tuya.

Qué ejecuta Aubergine en tu repositorio

Aubergine usa el git de tu PATH (2.31 o posterior). En cada comando de Git que inicia, no se ejecuta ningún hook, nada pide confirmación, nada sale a la red y no se descargan los submódulos. Los filtros que nombra tu propia configuración de Git, como el almacenamiento de archivos grandes, sí se ejecutan, igual que en tu propio git status.

No es un sandbox

Una copia de trabajo mantiene el trabajo separado. No encierra a un agente: el agente se ejecuta como tú y puede leer y cambiar cualquier archivo que puedas tú, incluido tu propio checkout. No confíes en ella para frenar a un agente que haga algo mal. Mira seguridad.

Relacionado: ejecutar varios agentes de programación a la vez · la cola y las programaciones (una tarea iniciada en una terminal nueva recibe una copia de trabajo propia cuando la carpeta está en un repositorio).

En marcha en cinco minutos

Necesitas macOS con tmux 3.2 o posterior y Node.js 22 o posterior. brew install tmux node instala ambos.

npm install -g @meatgarden/aubergine
