تثبيت Aubergine على Windows باستخدام WSL

لا يعمل Aubergine على Windows نفسه. إنه يعمل داخل WSL 2، وهو نظام Linux الذي يوفّره Windows، وتستخدمه من متصفحك على Windows.

ما الذي جُرّب. شُغّلت خطوات Linux في 25 نوفمبر 2026 على Ubuntu 24.04.5 (x86_64) داخل حاوية، لا داخل WSL، مع Aubergine 0.2.2 من npm: ترجم مكتبة الطرفية الخاصة به، وبدأ، وسجّل دخول متصفح، وشغّل طرفية والعرض التجريبي. لم تُشغَّل هناك خطوة تثبيت Node.js باستخدام nvm، لأن Node.js 22 كان مثبّتًا من قبل. لم يُشغَّل أي شيء في هذه الصفحة على Windows بعد. إن جرّبته، أخبرنا كيف جرى الأمر.

ما تحتاج إليه

Windows 11، أو Windows 10 الإصدار 2004 (البنية 19041) أو أحدث، حيث يُثبَّت WSL 2 بأمر واحد. التفاصيل في صفحة Microsoft عن تثبيت WSL.

التثبيت والتشغيل

  1. ثبّت WSL. افتح PowerShell بصلاحيات المسؤول، وشغّل هذا، وأعد تشغيل Windows عند انتهائه. إنه يثبّت WSL 2 مع Ubuntu.

    wsl --install

    بعد إعادة التشغيل، افتح Ubuntu من قائمة Start واختر له اسم مستخدم وكلمة مرور. كل أمر أدناه يُكتب هناك، في Ubuntu.

  2. ثبّت ما يحتاج إليه Aubergine: tmux وzsh وGit، والأدوات التي تترجم مكتبة الطرفية الخاصة به، إذ ليس لها شيء جاهز لـ Linux.

    sudo apt update

    sudo apt install -y tmux zsh git build-essential python3

    ثبّت Node.js 22. حزمة Ubuntu نفسها هي الإصدار 18، وهو قديم جدًا. إحدى الطرق المعروفة هي nvm: ثبّته، وافتح نافذة Ubuntu جديدة، ثم ثبّت Node.js 22.

    curl -o- https://raw.githubusercontent.com/nvm-sh/nvm/v0.40.3/install.sh | bash

    nvm install 22

    يجب أن يُظهر node -v الآن v22 أو أحدث.

  3. ثبّت Aubergine من npm. إنه يترجم مكتبة الطرفية الخاصة به أثناء التثبيت؛ استغرق التثبيت كله 13 ثانية في التجربة.

    npm install -g @meatgarden/aubergine

  4. شغّله، واترك تلك النافذة مفتوحة:

    aubergine start

    سجّل دخول متصفحك. في نافذة Ubuntu ثانية، اطبع عنوان تسجيل الدخول، ثم افتحه في متصفحك على Windows. إنه يسجّل دخول ذلك المتصفح، فعامِله ككلمة مرور.

    aubergine open --print

    بعد ذلك يعمل http://127.0.0.1:4600 وحده في ذلك المتصفح. على لوحة فارغة، يبدأ Show me around الجولة.

من المفيد أن تعرف

  • احفظ مشاريعك في Ubuntu، في مجلد المنزل الخاص به، لا تحت /mnt/c، حيث يُوصَل إلى ملفات Windows عبر جسر أبطأ.
  • ثبّت وكلاءك داخل Ubuntu، Claude Code أو Codex أو أي وكيل آخر، كما تفعل على أي Linux. الوكيل المثبّت في Windows ليس في طرفيات Aubergine.
  • تبقى الطرفيات ما دام WSL يعمل. إغلاق المتصفح لا ينهي شيئًا، وCtrl+C في نافذة aubergine start يوقف الخادم فقط. عندما يتوقف WSL، لأن Windows أُعيد تشغيله أو بعد wsl --shutdown، تنتهي الطرفيات، ويفتح aubergine start التالي أصدافًا جديدة في آخر مجلداتها، كما بعد إعادة تشغيل جهاز Mac.
  • bash أو zsh. صدفة Ubuntu هي bash، والطرفيات تعمل فيها. حالة الأوامر في الطرفية (مشغولة، ورمز خروج الأمر الفاشل) تأتي من zsh وحده: في التجربة أظهرت طرفية zsh exit 3 بعد أمر فاشل. اجعل zsh صدفتك في Ubuntu لتحصل عليها.
  • ما ليس هناك: التشغيل عند تسجيل الدخول يعمل على macOS فقط (aubergine service install يقول ذلك)، وOpen on desktop ليس له إعداد لتطبيق طرفية على Windows. لم يجد aubergine open متصفحًا يفتحه في التجربة؛ أما aubergine open --print فيعمل دائمًا.
  • المفاتيح على Windows اختيرت مما توثّقه المتصفحات ولم تُقَس: راجع docs/keys.md. لوحة الأوامر تعمل دائمًا.

إذا حدث خطأ

شغّل aubergine doctor في Ubuntu أولًا. إنه يفحص Node.js وtmux وGit والخادم.

ما تراهما تفعله
يفشل تثبيت Aubergine أثناء ترجمة node-ptyأدوات البناء غير موجودة. شغّل أسطر apt من الخطوة 2، ثم ثبّت Aubergine من جديد.
صفحة تقول إن tmux غير موجود أو قديم جدًاإصدار tmux في Ubuntu 24.04 هو 3.4، وهو حديث بما يكفي: sudo apt install -y tmux، ثم شغّل الخادم من جديد.
يُظهر node -v إصدارًا أقدم من v22ثبّت Node.js 22 كما في الخطوة 2، وافتح نافذة Ubuntu جديدة، ثم ثبّت Aubergine من جديد.
لا يُفتح العنوان في المتصفح على Windowsتحقّق من أن aubergine start ما زال يعمل في Ubuntu. ثم راجع صفحة Microsoft عن الشبكات في WSL؛ لم يُجرَّب هذا مع Aubergine.
