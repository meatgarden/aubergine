Codex و ChatGPT

Codex هو وكيل البرمجة لسطر الأوامر من OpenAI. تثبّته وتسجّل الدخول إليه بنفسك؛ وفي Aubergine يعمل في طرفية مثل أي برنامج آخر.

لم يُجرَّب بعد

لم يشغّل أحد Codex حقيقيًا في Aubergine بعد. ما تقوله هذه الصفحة هو ما يفعله Aubergine لأي برنامج في طرفية ولأوامر aubergine، وهذا مبني ومختبَر؛ أما سلوك Codex نفسه هناك فلم يُشاهَد. إذا جرّبته، أخبرنا كيف جرى الأمر.

شغّله

افتح طرفية بـ New terminal، أو N، وشغّل Codex فيها كما تفعل في أي طرفية. لا يستدعي Aubergine أي نموذج ولا يحتفظ بأي مفتاح: ما يحتاجه Codex أعطيته إياه حين سجّلت الدخول إليه.

ما يعمل اليوم

كل ما يفعله Aubergine لأي طرفية:

  • جنبًا إلى جنب

    ما شئت من الطرفيات على لوحة واحدة، واللوحات علامات تبويب.

  • حالة الأوامر

    مع zsh، يُظهر عنوان الطرفية أن أمرًا يعمل، وأيّ أمر هو.

  • الألوان والملاحظات والحقول

    أعطِ طرفيته لونًا، واحتفظ بملاحظة فيها ملخص وسجل، وبحقول مثل تذكرة أو مسؤول.

  • الركن

    العلامة × تركن الطرفية: تغادر اللوحة وتبقى تعمل، وParked يعيدها.

  • طرفية واحدة وحدها

    افتح الطرفية في علامة تبويب خاصة بها في المتصفح، مع تفاصيلها وملاحظتها بجانبها.

  • نسخة عمل

    Shell in a folder or a working copy…‎، أو aubergine new --copy، يشغّل الطرفية في نسختها المسحوبة الخاصة على فرعها الخاص، فلا يعدّل وكيلان الملفات نفسها أبدًا.

  • البحث في المخرجات

    ⌘K يبحث فيما طبعته كل طرفية، ويفتح الطرفية مرجوعًا بها إلى موضع التطابق.

ما يستطيع قوله عبر الأوامر

في كل طرفية Aubergine الأمر aubergine وبيانات اعتماد لتلك الطرفية وحدها. أي برنامج هناك، ومنه Codex، يستطيع استخدامهما:

  • aubergine attention waiting "…"

    يعلّم الطرفية بأنها بانتظارك، مع ما تحتاجه؛ وaubergine attention working وaubergine attention done يقولان الباقي.

  • aubergine note "…"

    يضيف سطرًا إلى سجل ملاحظات الطرفية.

  • aubergine describe

    يسمّي الطرفية باسم العمل ويحتفظ بملخصها؛ وaubergine link add وaubergine field set يضيفان روابط العمل وحقوله. ما كتبته أنت يغلب.

  • aubergine workflow status

    يقرأ الخطوة الحالية من سير العمل؛ وaubergine workflow done يبلّغ بإتمامها ويطبع التالية.

  • aubergine task add

    يقترح مهمة للطابور، وaubergine ask يطلب منك شيئًا لا يستطيعه إلا إنسان. كلاهما ينتظر في قائمتك.

كيف تخبره

لا يعرف Codex شيئًا عن Aubergine حتى يُخبَر. هذا يطبع خمسة أسطر تلصقها في التعليمات التي يقرؤها وكيلك في بداية كل محادثة في المشروع؛ ووثائقه هو تقول أين توضع:

aubergine guide --snippet

تطلب منه الأسطر أن يشغّل aubergine guide مرة واحدة حين يكون في طرفية Aubergine، والدليل يقول الباقي. يطبع Aubergine الأسطر ولا يكتبها في أي ملف أبدًا.

إذا كان وكيلك يستطيع تشغيل خادم MCP، فإن aubergine mcp يقدّم الشيء نفسه أدواتٍ؛ وداخل طرفية Aubergine لا يحتاج إلى عنوان ولا إلى رمز لعمل الطرفية نفسها.

مبني لـ Claude Code وحده اليوم

ما يفعله Aubergine من تلقاء نفسه لوكيلٍ مبني لـ Claude Code. أما لـ Codex، فاليوم:

  • ليس في قائمة New terminal: تشغّله في طرفية بنفسك.
  • لا يراه Aubergine وكيلًا: لا يُعلَّم بأنه ينتظر أو انتهى من تلقاء نفسه، بل فقط حين يشغّل aubergine attention.
  • لا يُكتب له شيء: سير العمل الذي يبدأ في طرفيته لا يكتب شيئًا ويعرض السطر لتعطيه إياه بنفسك، ولا يُعلَن له عن ملخص أو رسالة.
  • لا يعطيه الطابور أي مهمة: المهمة لا تذهب إلا إلى طرفية يُرى فيها وكيل متفرغ.
  • لا يوجد Resume agent، ولا قائمة بالمحادثات السابقة، ولا قائمة بطريقة إعداده، ولا نافذة لأدوات Aubergine.
  • الأمران aubergine move وaubergine here --claude ينقلان Claude Code فقط.
  • لا يُذكَّر بأن يسمّي طرفيته أو يحتفظ بملخص.

كل ذلك في صفحة Claude Code.

ChatGPT في المتصفح

ChatGPT في علامة تبويب في المتصفح صفحة ويب، لا برنامج في طرفية، فلا يعمل على اللوحة.

Aubergine غير تابع لـ OpenAI. Codex وChatGPT علامتان تجاريتان لـ OpenAI.

جاهز للعمل في خمس دقائق

تحتاج إلى macOS مع tmux 3.2 أو أحدث، ومعه Node.js 22 أو أحدث. الأمر brew install tmux node يثبّت الاثنين.

npm install -g @meatgarden/aubergine
