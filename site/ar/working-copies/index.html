وكيلان ومستودع واحد: نسخ العمل

تعمل كل طرفية عادةً في مجلدك الحقيقي. فيعدّل وكيلان في مستودع واحد الملفات نفسها، ولا تستطيع أن تميّز أي تغيير لمن. نسخة العمل تعطي كل طرفية نسختها المسحوبة الخاصة، على فرعها الخاص.

شغّل طرفية في نسخة عمل

  1. اضغط ▾ في آخر New terminal، أعلى قائمة الطرفيات، ثم Shell in a folder or a working copy…‎.
  2. أدخل المجلد واختر In its own working copy (في نسخة عمل خاصة بها). لا يُعرض هذا الخيار إلا حيث يمكن، ويقول السبب حيث لا يمكن: ليس مستودع Git، أو مستودع مجرد (bare)، أو لا إيداع بعد.

ومن طرفية، الشيء نفسه:

aubergine here --copy
aubergine new "api" --copy --in ~/code/my-project

ما تحصل عليه

شجرة عمل Git (worktree) في مجلد يحتفظ به Aubergine تحت مجلد بياناته، لا داخل مستودعك أبدًا، على فرع جديد اسمه aubergine/<terminal name>-<six characters>. تبدأ من الإيداع الذي عليه نسختك المسحوبة، وتبدأ الطرفية في المجلد الفرعي نفسه الذي كنت فيه. نسختك المسحوبة لا تتغير أبدًا: لا ملفاتها، ولا ما هو مُجهَّز للإيداع، ولا الفرع الذي سحبته.

ما لا يُنقل: تغييراتك غير المودَعة (لا يُخبَّأ ولا يُودَع شيء نيابة عنك)، والملفات التي يتجاهلها Git أو لا يتتبعها، مثل الاعتماديات المثبَّتة والإعدادات المحلية. والمشروع الذي يحتاج إلى خطوة تثبيت يحتاجها من جديد في نسخة العمل.

اقرأ ما غيّره وكيل

الطرفية التي في نسخة عمل تُظهر على شريط عنوانها فرعها وعدد الملفات المختلفة. انقره لترى الملفات المغيَّرة والمضافة والمحذوفة، مع تعليم العمل الذي ليس في أي إيداع، والفرق للقراءة فقط لأي ملف تختاره.

حين تنتهي الطرفية

لا تُزال نسخة العمل أبدًا لمجرد أن طرفيتها انتهت. أنت تختار:

  • Keep the branch, remove the folder (أبقِ الفرع واحذف المجلد)، حين يكون كل شيء مودَعًا.
  • Keep everything.‎ (أبقِ كل شيء) تبقى في القائمة، وتقول إن طرفيتها ذهبت.
  • Discard both (تخلّص من الاثنين)، الذي يسأل مرة ثانية حين تحوي النسخة عملًا لا يوجد في أي مكان آخر.
aubergine copies
aubergine copies show api
aubergine copies keep-branch api
aubergine copies discard api

لا يدمج Aubergine ولا يدفع ولا يعيد الأساس أبدًا. ما تفعله بفرع أبقيته شأنك.

ما يشغّله Aubergine في مستودعك

يستخدم Aubergine الأمر git الموجود على PATH لديك (2.31 أو أحدث). في كل أمر Git يشغّله، لا يعمل أي خطاف، ولا يُطلب منك شيء، ولا يصل شيء إلى الشبكة، ولا تُجلب الوحدات الفرعية. أما المرشّحات المذكورة في إعدادات Git الخاصة بك، مثل تخزين الملفات الكبيرة، فتعمل، كما تعمل مع git status الخاص بك.

ليست صندوق عزل

نسخة العمل تُبقي الأعمال منفصلة. لكنها لا تحبس الوكيل: الوكيل يعمل باسمك ويستطيع قراءة وتغيير كل ملف تستطيعه، بما في ذلك نسختك المسحوبة. لا تعتمد عليها لكبح وكيل يفعل الشيء الخطأ. انظر الأمان.

ذو صلة: شغّل عدة وكلاء برمجة في آن واحد · الطابور والجداول الزمنية (المهمة التي تبدأ في طرفية جديدة تحصل على نسخة عمل خاصة بها حيث يكون المجلد في مستودع).

جاهز للعمل في خمس دقائق

تحتاج إلى macOS مع tmux 3.2 أو أحدث، ومعه Node.js 22 أو أحدث. الأمر brew install tmux node يثبّت الاثنين.

npm install -g @meatgarden/aubergine
