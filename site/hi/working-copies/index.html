इस पेज का अंग्रेज़ी से अनुवाद मशीन ने किया है। सुधार भेजें।

दो एजेंट, एक रिपॉज़िटरी: वर्किंग कॉपी

आम तौर पर हर टर्मिनल आपके असली फ़ोल्डर में काम करता है। तब एक रिपॉज़िटरी में दो एजेंट एक ही फ़ाइलें बदलते हैं, और आप नहीं बता सकते कि कौन-सा बदलाव किसका है। वर्किंग कॉपी हर टर्मिनल को उसका अपना चेकआउट देती है, उसकी अपनी ब्रांच पर।

वर्किंग कॉपी में टर्मिनल शुरू करें

  1. टर्मिनलों की सूची में सबसे ऊपर New terminal के अंत में ▾ दबाएँ, फिर Shell in a folder or a working copy…।
  2. फ़ोल्डर दें और In its own working copy चुनें। यह विकल्प सिर्फ़ वहीं मिलता है जहाँ यह हो सकता है, और जहाँ नहीं हो सकता वहाँ कारण बताता है: Git रिपॉज़िटरी नहीं है, bare रिपॉज़िटरी है, या अभी कोई कमिट नहीं है।

किसी टर्मिनल से, यही काम:

aubergine here --copy
aubergine new "api" --copy --in ~/code/my-project

आपको क्या मिलता है

एक Git worktree, ऐसे फ़ोल्डर में जिसे Aubergine अपने डेटा फ़ोल्डर के नीचे रखता है, कभी आपकी रिपॉज़िटरी के अंदर नहीं, aubergine/<terminal name>-<six characters> नाम की एक नई ब्रांच पर। यह उस कमिट से शुरू होती है जिस पर आपका चेकआउट है, और टर्मिनल उसी सबफ़ोल्डर में शुरू होता है जिसमें आप थे। आपका अपना चेकआउट कभी नहीं बदलता: न उसकी फ़ाइलें, न जो stage किया है, न वह ब्रांच जो आपने चेकआउट की है।

साथ नहीं आता: आपके बिना कमिट किए बदलाव (आपके लिए कुछ stash या कमिट नहीं किया जाता), और वे फ़ाइलें जिन्हें Git अनदेखा करता है या ट्रैक नहीं करता, जैसे इंस्टॉल की हुई डिपेंडेंसी और लोकल सेटिंग्स। जिस प्रोजेक्ट को इंस्टॉल स्टेप चाहिए, उसे वर्किंग कॉपी में फिर से चाहिए।

पढ़ें कि एजेंट ने क्या बदला

वर्किंग कॉपी वाला टर्मिनल अपने टाइटल बार पर अपनी ब्रांच और अलग फ़ाइलों की गिनती दिखाता है। बदली, जोड़ी और हटाई गई फ़ाइलों के लिए उस पर क्लिक करें, जिसमें वह काम चिह्नित है जो किसी कमिट में नहीं है, और आपकी चुनी किसी भी फ़ाइल का सिर्फ़ पढ़ने वाला अंतर।

जब टर्मिनल बंद होता है

कोई वर्किंग कॉपी सिर्फ़ इसलिए कभी नहीं हटाई जाती कि उसका टर्मिनल बंद हुआ। आप चुनते हैं:

  • Keep the branch, remove the folder (ब्रांच रखें, फ़ोल्डर हटाएँ), जब सब कुछ कमिट हो चुका हो।
  • Keep everything. (सब कुछ रखें।) यह सूची में रहती है और बताती है कि इसका टर्मिनल जा चुका है।
  • Discard both (दोनों हटाएँ), जो दूसरी बार पूछता है जब कॉपी में ऐसा काम हो जो कहीं और नहीं है।
aubergine copies
aubergine copies show api
aubergine copies keep-branch api
aubergine copies discard api

Aubergine कभी merge, push या rebase नहीं करता। रखी गई ब्रांच का आप क्या करें, यह आपका काम है।

Aubergine आपकी रिपॉज़िटरी में क्या चलाता है

Aubergine वह git इस्तेमाल करता है जो आपके PATH पर है (2.31 या नया)। हर Git कमांड जो वह शुरू करता है, उसमें कोई हुक नहीं चलता, कुछ नहीं पूछा जाता, कुछ भी नेटवर्क तक नहीं पहुँचता, और submodule फ़ेच नहीं होते। आपकी अपनी Git कॉन्फ़िगरेशन में नामित फ़िल्टर, जैसे large-file storage, चलते हैं, जैसे वे आपके अपने git status के लिए चलते हैं।

यह सैंडबॉक्स नहीं है

वर्किंग कॉपी काम को अलग रखती है। यह एजेंट को बंद करके नहीं रखती: एजेंट आपके रूप में चलता है और हर वह फ़ाइल पढ़ और बदल सकता है जो आप कर सकते हैं, आपका अपना चेकआउट भी। गलत काम करने वाले एजेंट को रोकने के लिए इस पर भरोसा न करें। सुरक्षा देखें।

जुड़ा हुआ: एक साथ कई कोडिंग एजेंट चलाएँ · क्यू और शेड्यूल (नए टर्मिनल पर शुरू हुए टास्क को उसकी अपनी वर्किंग कॉपी मिलती है जहाँ फ़ोल्डर किसी रिपॉज़िटरी में हो)।
