Sesuaikan tema, warna, fon, dan tombol terminal

Pilih warna halaman dari sepuluh tema, beri setiap terminal tema sendiri, dan atur warna tunggal, fon dan kursor terminal, serta setiap tombol, di Settings atau di satu berkas pengaturan yang menjelaskan dirinya sendiri.

Sepuluh tema warna, terang dan gelap

Settings → Appearance dimulai dengan tiga pilihan: Light, Dark, dan Match the system, yang menjadi awal pemasangan baru dan mengikuti sistem saat sistem berubah. Di bawahnya Anda memilih satu tema dari tiap jenis: Light, High contrast light, Solarized light, atau Gruvbox light; Dark, High contrast dark, Solarized dark, Gruvbox dark, Nord, atau Dracula. Masing-masing ditampilkan dengan gambar kecil warnanya.

Perubahan langsung berlaku untuk halaman dan setiap terminal, tanpa memuat ulang, dan disimpan di berkas pengaturan, jadi setiap peramban tempat Anda membuka Aubergine akan sama. Palet juga punya hal yang sama sebagai perintah, misalnya Color theme: Nord.

Tema warna yang berbeda untuk tiap terminal

Theme… di menu terminal menggambar terminal itu dengan salah satu dari sepuluh tema, apa pun tema halamannya. Hanya badannya yang berubah: judul, catatan, dan detailnya tetap seperti halaman. Terminal tanpa tema sendiri mengikuti Terminal theme di Settings, yaitu bawaan untuk terminal, dan tanpa itu, mengikuti halaman.

Pilihan yang sama ada di menu baris terminal dalam daftar, di detailnya, dan di palet. Terminal dan bingkai juga bisa punya warna sendiri, salah satu dari tiga belas atau Your own… untuk warna apa saja, begitu pula tab kanvas; warna terminal juga menjadi warna barisnya di daftar.

Atur warna tunggal sendiri

Selain tema, 35 warna halaman bisa diatur di berkas pengaturan, config.json, di bawah appearance.colors: nama warna dan nilai yang ditulis #rrggbb. Ditulis di bagian atas, warna berlaku di atas setiap tema; ditulis di bawah ID tema dalam kurung siku, seperti "[nord]", warna berlaku di atas tema itu saja, dan menang.

{
  "$schema": "./config.schema.json",
  "appearance": {
    "colors": {
      "accent": "#c678dd",
      "[nord]": { "terminal-bg": "#242933" }
    }
  }
}

Namanya adalah token warna halaman, seperti bg, text, accent, dan terminal-bg; docs/design.md mencantumkannya. Entri yang salah dilewati, dan sisa berkas tetap berlaku; Settings → Appearance memberi tahu mana yang dilewati. Warna yang Anda atur adalah milik Anda: tidak ada yang memeriksa apakah tulisan Anda bisa dibaca.

Tema Anda sendiri, sebagai file

Tema Anda sendiri adalah file JSON di themes/ dalam folder data: salah satu dari sepuluh sebagai dasar, dari jenis yang sama, dengan warna mana pun dari 35 warna di atasnya, serta warna terminal itu sendiri: teksnya, kursor, bagian yang dipilih, dan enam belas warna yang diminta program. Tema itu tercantum setelah sepuluh tema sejenisnya, ditandai sebagai milik Anda, dan bisa dipilih di mana pun tema-tema itu bisa: untuk halaman, sebagai bawaan terminal, atau untuk satu terminal. Bayangan dan cincin fokus tetap milik dasarnya, dan tidak ada isi file yang dijalankan.

{
  "$schema": "../theme.schema.json",
  "name": "Harbor",
  "kind": "dark",
  "base": "nord",
  "colors": { "bg": "#0e1a24", "accent": "#5fb3b3" },
  "terminal": { "foreground": "#d8dee9", "cursor": "#5fb3b3" }
}

aubergine theme new harbor --from nord menulis file awal, dengan setiap warna dari tema asalnya; aubergine theme check memberi tahu apa yang salah di dalamnya; Read themes again di Settings memuat perubahan. Apakah warna Anda mudah dibaca, Anda yang menilai: Settings hanya memberi tahu bila teks mungkin sulit dibaca. docs/themes.md menjelaskan formatnya.

Tema untuk sebuah proyek, dan untuk terminal menurut tag

Sebuah proyek dapat menggambar halaman dengan temanya sendiri selama Anda melihatnya, sehingga sekilas pandang menunjukkan di mana Anda berada. Di Projects…, When light dan When dark di samping sebuah proyek memilih satu tema untuk tiap jenis; As the page menyerahkannya ke Settings. Di proyek lain halaman tetap seperti pilihan Anda, dan memuat ulang di alamat proyek itu menggambarnya dengan temanya sejak gambar pertama.

By tag, di bawah Terminal theme di Settings, memberi terminal yang punya sebuah tag tema sendiri: misalnya setiap terminal bertag prod dalam Dracula, seketika dan apa pun tema halamannya. Baris pertama yang tag-nya dimiliki terminal yang berlaku, dan tema milik terminal itu sendiri didahulukan dari semuanya. Di berkas pengaturan, ini adalah appearance.byTag:

{
  "appearance": {
    "byTag": [
      { "tag": "prod", "theme": "dracula" },
      { "tag": "docs", "theme": "solarized-light" }
    ]
  }
}

Sering kali warna aksen lain sudah cukup. aubergine theme new teal --from nord --accent "#2f9e8f" menulis berkas tema yang hanya mengubah aksen Nord dan lima warna yang menyertainya, dihitung agar tetap terbaca. Pilih untuk proyek atau tag seperti tema lainnya.

Fon, kursor, dan pintasan keyboard

Terminal text di Settings → Appearance mengatur ukuran teks terminal, dari 8 sampai 32 piksel, dan fonnya, sebagai daftar yang fon pertama yang ditemukan dipakai. Cursor mengatur bentuknya, blok, batang, atau garis bawah, dan apakah ia berkedip.

Setiap tombol bisa diubah. Tambahkan shortcuts ke berkas pengaturan: nama perintah dengan satu kombinasi, daftar kombinasi, atau null untuk tanpa tombol. shortcutsInAppWindow menerima hal yang sama dan hanya berlaku di tempat Aubergine dipasang sebagai aplikasi dengan jendela sendiri. Muat ulang halaman, maka lembar pintasan (?), palet, dan tooltip menampilkan tombol seperti yang Anda atur.

{
  "shortcuts": {
    "terminal.park": "X",
    "attention.next": ["Ctrl+Cmd+G", "W"],
    "view.fit": null
  }
}

Tombol yang diatur dua kali, atau yang tidak bisa dibaca, dilaporkan di atas lembar pintasan dan oleh server, dan sisa berkas tetap berlaku. Tombol tunggal, atau Ctrl atau Option dengan satu tombol, hanya bekerja selama tidak ada terminal yang memegang keyboard, agar setiap program di terminal tetap menerima tombol yang dibutuhkannya. Selengkapnya di Keyboard, di README.

Pilih apa yang dikatakan judul dan baris

Setelah nama terminal, judulnya dan barisnya di daftar mengatakan apa yang dikatakan dua templat: teks dengan placeholder seperti {state}, {folder}, {time}, dan {field:Ticket}. Ubah di Settings → Appearance → Titles and rows, tempat judul dan baris yang sebenarnya digambar di bawah setiap kolom saat Anda mengetik, atau di file pengaturan. Di sini judul mengatakan status, folder, field Ticket, tautan, dan tag, dan baris mengatakan status, langkah sebuah run, branch, dan waktu:

{
  "appearance": {
    "titleFormat": "{state} {folder} · {field:Ticket} {links} {tags}",
    "rowFormat": "{state} {step} {branch} · {time}"
  }
}

Placeholder yang tidak punya apa-apa untuk dikatakan dihilangkan bersama teks yang mengarah ke sana: pada terminal tanpa tiket, tautan, atau tag, judul itu hanya mengatakan status dan foldernya, tanpa titik yang tersisa. Templat hanya berisi teks dan placeholder, tanpa markup dan tanpa gaya; masing-masing digambar seperti halaman menggambar hal itu di tempat lain, status dalam warnanya dan tautan sebagai chip. Placeholder yang salah disebutkan di bawah kolom dan dilewati, dan Reset mengembalikan persis apa yang digambar tanpa templat. Semua placeholder ada di docs/templates.md.

Stylesheet sendiri

Untuk apa pun yang tidak terjangkau pengaturan, tulis stylesheet Anda sendiri: custom.css di folder data. Server menautkannya sebagai hal terakhir di head halaman, jadi ia ada sejak gambar pertama, dan aturan Anda mengalahkan aturan aplikasi yang sama spesifiknya, tanpa !important. aubergine css new menulis satu untuk memulai, dan Settings → Appearance → Your stylesheet memberi tahu apakah ia ditemukan, mematikannya, dan membacanya lagi tanpa memuat ulang.

Andalkan kait-kaitnya dan tidak ada yang lain: setiap token (--accent, --radius-surface, dan lainnya), atribut di akar halaman (data-theme, data-page), bagian yang ditandai data-part, dan atribut milik terminal sendiri (data-tags, data-state, data-name), sama di simpulnya, barisnya, dan tab browser miliknya sendiri. Semuanya tercantum di docs/hooks.md dan dipertahankan dari satu rilis ke rilis berikutnya; nama kelas tidak. Di sini judul setiap terminal bertag prod berwarna merah tua, dan petanya hilang:

[data-part="terminal"][data-tags~="prod"] [data-part="terminal-title"] {
  background: #5c1f24;
}
[data-part="map"] {
  display: none;
}

Dan sudut yang lebih bulat di mana-mana, lewat dua token:

:root {
  --radius-surface: 16px;
  --radius-control: 10px;
}

Jika sebuah aturan merusak halaman, buka dengan ?plain setelah alamatnya: halaman dikirim tanpa stylesheet Anda. Tidak ada yang disebut stylesheet yang diambil dari alamat lain: gambar, font, atau stylesheet datang dari server ini atau dari data sebaris, sehingga potongan yang ditempel tidak bisa mengirim isi halaman Anda ke tempat lain. Itu pengaman untuk berkas yang Anda tulis atau tempel, bukan sandbox. Baru dicoba di Chromium saja.

Kode Anda sendiri: plugin

Melampaui pengaturan dan stylesheet, tulis kode: plugin adalah modul JavaScript milik Anda di plugins/<id>/ dalam folder data, dengan plugin.json yang menamainya. Halaman mengimpornya apa adanya, tanpa langkah build, dan memberinya satu objek, aubergine: bagian panel samping, filter daftar, placeholder untuk judul atau baris, perintah di palet, cara melihat sebuah run, status dan setiap perubahan saat terjadi, serta setiap panggilan yang dilakukan halaman. aubergine plugin new <id> menulis satu untuk memulai.

Plugin berjalan di halaman sebagai Anda, dan tidak ada yang memisahkannya. Ia dapat membaca setiap terminal, mengetik ke terminal mana pun, dan mengubah apa pun di halaman. Ia tidak berada dalam sandbox. Ia hanya berjalan setelah Anda menyalakannya di Settings → Plugins, dan hanya seperti berkasnya saat itu: berkas yang berubah tidak dimuat sampai Anda melihatnya lagi. Itu mencegah kode berjalan tanpa sengaja; itu bukan kunci, karena agen di terminal juga berjalan sebagai Anda dan bisa menulis berkas pengaturan. Nyalakan hanya yang Anda tulis atau sudah Anda baca.

Anggota aubergine tercantum di docs/plugins.md dan dari satu rilis ke rilis berikutnya hanya ditambah; apa pun yang dijangkau plugin di luar itu bisa berubah. Satu perintah di palet, dalam beberapa baris:

// plugins/hello/index.js
export function activate(aubergine) {
  aubergine.commands.add({
    id: 'hello',
    title: 'Say hello',
    run: () => aubergine.say('Hello from my plugin'),
  });
}

Jika plugin merusak halaman, buka dengan ?plain setelah alamatnya: tidak ada plugin yang dimuat, dan stylesheet Anda ditinggalkan. Plugin yang gagal disebutkan di Settings, dan halaman serta plugin lain tetap berjalan. Saat dimatikan, semua yang ditambahkannya lewat aubergine langsung hilang; yang dilakukannya di luar itu hilang dengan memuat ulang. Baru dicoba di Chromium saja.

Satu berkas pengaturan yang menjelaskan dirinya sendiri

Semua ini disimpan di config.json di folder data Aubergine, dan aubergine settings path menampilkan letaknya. Setiap kunci boleh dihilangkan. Berkas yang tidak bisa dibaca berarti nilai bawaan, tidak pernah server yang gagal dimulai. Settings di halaman hanya menulis kunci yang diubahnya dan membiarkan sisa berkas seperti yang Anda tulis.

Setiap kali dimulai, server menulis config.schema.json di samping berkas. Tambahkan satu baris, dan editor yang membaca JSON Schema akan menjelaskan dan melengkapi setiap kunci:

{ "$schema": "./config.schema.json" }

aubergine settings list menampilkan setiap kunci dengan nilainya sekarang, ditandai jika bukan bawaan, dan aubergine settings schema menampilkan skemanya. docs/settings.md menjelaskan setiap kunci, nilai bawaannya, dan apakah ditulis oleh Settings atau oleh Anda.

aubergine settings path
aubergine settings list
aubergine settings schema

Di halaman, Settings → Every setting mencantumkan kunci yang sama beserta nilainya, dan menemukannya saat Anda mengetik. Kunci yang diubah Settings membawa Anda ke kontrolnya; kunci yang ditulis sendiri punya Copy, untuk baris yang ditambahkan ke berkas. Tidak ada pengaturan yang berubah di sana.

Beberapa pilihan milik peramban ini dan disimpan di sana: apakah kanvas tampil sebagai tab, satu daftar, atau satu kolom; di mana bilah di atas kanvas berada dan apakah tetap terbuka; apakah panel samping dan peta dilipat; lebar panel dan detail terminal; dan bagaimana daftar terminal disaring, dikelompokkan, dan diurutkan.

Apa yang boleh diubah program atau agen, dan apa yang tetap milik Anda

Melalui API lokal, program dengan token API boleh menata kanvas dengan canvases:write: memberi nama, warna, dan urutan, memindahkan, mengubah ukuran, dan mewarnai terminal di atasnya, serta menambah bingkai. Dengan sessions:write ia boleh mengganti nama dan menandai terminal, mengubah kolomnya, dan memberinya tema warna. Ia hanya menjangkau proyek yang dijangkau tokennya.

Agen di dalam terminal menjelaskan terminalnya sendiri dan tidak yang lain: nama, ringkasan untuk apa terminal itu, tautan, dan kolomnya, dengan aubergine describe, aubergine link add, dan aubergine field set. Di tempat Anda sendiri menulis nama, ringkasan, atau kolom, milik Anda tetap dipakai, dan yang dikirim agen disimpan di sampingnya sebagai saran. Agen, atau program dengan workflows:write, juga bisa mengusulkan tema warna dengan aubergine theme propose: tema itu tidak digambar di mana pun sampai Anda membacanya di Review, melihatnya digambar, mencobanya di halaman, lalu menerimanya, dan menerimanya menulis berkasnya tanpa memilih apa pun.

Pengaturan itu sendiri hanya milik Anda. Tidak ada token, terminal, atau agen yang bisa mengubahnya: PUT /v1/settings/appearance hanya menjawab peramban yang sudah masuk, dan appearance.colors, shortcuts, dan lainnya ditulis sendiri di berkas.

Setiap alat di sini menyimpan pengaturannya di sebuah berkas, dan VS Code, Zed, serta Windows Terminal juga punya layar yang menulisnya, seperti Aubergine. Di sebagian besar, tema juga berupa berkas: JSON di VS Code dan Zed, CSS di Obsidian, Lua atau TOML di WezTerm, berkas konfigurasi di kitty dan Ghostty. VS Code, Zed, dan WezTerm memungkinkan Anda mengubah warna tunggal di atas tema, seperti yang dilakukan appearance.colors di sini.

Perbedaan terbesar ada pada kode. Seluruh konfigurasi WezTerm adalah program Lua, kitty dan iTerm2 menjalankan Python Anda sendiri, dan plugin Hyper adalah JavaScript yang membungkus antarmukanya; Obsidian dan Hyper juga menerima CSS Anda sendiri. Ekstensi VS Code tidak punya akses ke DOM antarmukanya, dan ia tidak mendukung stylesheet milik Anda; Zed menjalankan ekstensi sebagai WebAssembly, dengan kapabilitas yang bisa Anda batasi. tmux, WezTerm, kitty, dan iTerm2 membangun judul dan baris status dari templat atau fungsi.

Aubergine kini menjangkau dari sisi pengaturan sampai ke kode: tema, warna, dan tombol dalam berkas yang menjelaskan dirinya sendiri, halaman yang menulis sebagian pengaturan, templat untuk apa yang dikatakan judul terminal dan barisnya, stylesheet milik Anda dengan kait yang dijaga stabil, dan plugin, JavaScript Anda sendiri di halaman dengan API yang hanya bertambah. Plugin berjalan dengan semua yang bisa dilakukan halaman; mode sandbox untuk plugin orang lain ada di peta jalan, dan belum dibangun.

Yang direncanakan

Cara menjalankan plugin tulisan orang lain dalam sandbox, dan memasangnya lewat layar tinjauan, direncanakan dan belum dibangun: lihat peta jalan.

Pertanyaan

Bisakah setiap terminal punya tema warna yang berbeda?

Ya. Theme… di menu terminal menggambar isinya dengan salah satu dari sepuluh tema, apa pun tema halamannya. Terminal yang punya tag bisa diberi tema menurut tag itu di Settings, dan yang lain mengikuti bawaan yang Anda atur untuk terminal, atau halaman.

Bisakah saya menambahkan CSS sendiri ke Aubergine?

Bisa: custom.css di folder data (aubergine css new menulis satu untuk memulai). Ia ditautkan paling akhir di halaman, sejak gambar pertama, dan kait yang bisa diandalkannya tercantum di docs/hooks.md. Tambahkan ?plain ke alamat halaman untuk melihatnya tanpa itu.

Bisakah saya menulis plugin sendiri untuk Aubergine?

Bisa: modul JavaScript di plugins/<id>/ dalam folder data (aubergine plugin new <id> menulis satu untuk memulai), dinyalakan di Settings → Plugins. Ia berjalan di halaman sebagai Anda, dengan semua yang bisa dilakukan halaman; ia tidak berada dalam sandbox.

Di mana berkas pengaturan Aubergine?

Yaitu config.json di folder data Aubergine. aubergine settings path menampilkan letaknya, dan server menampilkannya saat dimulai.

Bisakah agen mengubah tampilan Aubergine?

Bukan pengaturannya: itu hanya milik Anda. Agen bisa memberi nama dan menjelaskan terminalnya sendiri serta mengusulkan tema warna yang menunggu Anda baca dan terima; program yang token API-nya mengizinkan bisa mengganti nama, menandai, dan memberi tema terminal, menata kanvas, dan juga mengusulkan tema.
