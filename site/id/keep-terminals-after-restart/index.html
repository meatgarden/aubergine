Terminal Anda tetap ada saat komputer dimulai ulang

Menutup browser atau memulai ulang Aubergine tidak menghilangkan apa pun: setiap terminal tetap berjalan. Memulai ulang komputer mengakhiri apa yang sedang berjalan, dan Aubergine mengembalikan semua yang ada di sekitarnya, sehingga Anda melanjutkan dari tempat Anda berhenti, bukan mulai dari nol.

Apa yang terjadi saat…

Setiap terminal adalah shell di sesi tmux, yang berjalan terpisah dari browser dan dari server Aubergine. Isinya ada di dua tempat: shell yang berjalan, yang hanya disimpan tmux, dan semua yang dikatakan tentang terminal itu, yang ditulis Aubergine ke sebuah file di folder datanya setiap kali ada perubahan.

Terminal yang disimpan dipertahankan dengan cara yang sama dan juga mendapat shell baru. Terminal yang shell-nya sudah berakhir sebelumnya tetap berakhir, dengan Restart here (mulai ulang di sini).

Setelah pembaruan, terminal yang sudah terbuka tetap memakai apa yang dibawa shell-nya saat dimulai (PATH-nya dan integrasi shell Aubergine) sampai shell itu dimulai lagi. Jika Aubergine dimulai saat login, jalankan lagi aubergine service install setelah pembaruan alih-alih memulai ulang server secara manual.

Setelah mulai ulang: kembali bekerja

  1. Mulai Aubergine. Jika ia dimulai saat login (aubergine service install, hanya macOS), ia sudah berjalan begitu Anda login, dan launchd memulainya lagi jika berhenti. Jika tidak, mulai dan buka halamannya:

    aubergine start --open

  2. Kanvas seperti saat Anda tinggalkan. Setiap terminal ada di tempatnya dengan nama, warna, tag, field, link, dan catatannya, kini sebuah shell baru di folder terakhir tempat Aubergine melihatnya, atau di folder bawaan Anda jika folder itu sudah tidak ada. Tidak ada yang diketik atau dijalankan lagi.

  3. Lanjutkan agen Anda. Di tempat Claude Code berjalan dan Aubergine mengetahui percakapannya (ia dimulai dari Aubergine), bilah judul terminal menawarkan Resume agent (lanjutkan agen): ia menjalankan Claude Code lagi di percakapan itu. Pada terminal yang sedang dalam sebuah run workflow, ia juga memberi tahu agen tentang run itu lagi, sehingga agen melanjutkan dari langkah tempat run berada.

  4. Lihat sampai mana masing-masing. Details (detail) di judul terminal menampilkan apa yang diketahui tentangnya (langkah sebuah run dan laporan terakhirnya, folder, tag), ringkasannya, field dan link-nya, serta log-nya di bawah Log. Mengarahkan penunjuk ke nama terminal di daftar menampilkan rekapnya.

  5. Temukan percakapan yang tidak ada di kanvas. Past conversations… (percakapan sebelumnya) di palet (⌘K), atau “Past conversations in this folder…” di detail terminal, mendaftar percakapan Claude Code sebelumnya di sebuah folder dan membuka salah satunya di kanvas.

Agen lain tidak punya Resume agent, karena Aubergine tidak mengetahui percakapannya: jalankan lagi di terminal yang sama dengan cara melanjutkan milik agen itu sendiri, dan baca catatannya untuk memberi tahu sampai mana ia.

Apa yang hilang, dan apa yang bisa dilakukan

  • Yang sedang berjalan berakhir. Build, uji, server, atau agen yang sedang bekerja berhenti bersama komputer, dan Aubergine tidak memulai satu pun lagi dengan sendirinya. Mulai lagi sendiri; pekerjaan yang harus bertahan melewati mulai ulang sebaiknya ada di sesuatu yang dibuat untuk itu, seperti layanan sistem Anda.
  • Pekerjaan yang dilacak Aubergine menunggu Anda. Sebuah run workflow mempertahankan langkahnya dan setiap laporan yang diserahkan. Tugas di antrean tetap di tempatnya; tugas yang sedang dimulai tepat saat server berhenti ditandai gagal, dengan satu kalimat, dan tidak ada yang dicoba lagi dengan sendirinya. Waktu jadwal yang terlewat saat server berhenti dijalankan sekali, terlambat, jika belum lewat enam jam (schedules.lateWithinHours), dan jika tidak ditandai terlewat.
  • Scrollback hilang. Selama shell berjalan, tmux menyimpan 50.000 baris terakhir yang dicetaknya, dan pencarian di palet membacanya. Aubergine tidak merekam apa yang dicetak terminal, jadi setelah komputer dimulai ulang tidak ada yang bisa dikembalikan, dan pencarian hanya menemukan apa yang dicetak sejak itu.
  • “Selama Anda pergi” mulai dari awal. Ia disimpan di memori server, bukan di file, jadi setelah server dimulai ia hanya tahu apa yang berubah sejak itu, dan mengatakannya.

Kebiasaan yang membuat mulai ulang murah

Catatan adalah yang bertahan, jadi minta agen menulis di sana sambil bekerja: sebuah keputusan, sebuah hasil, di mana mereka berhenti. Claude Code yang dimulai dari Aubergine menambahkan setiap prompt yang Anda kirim ke log dengan sendirinya, dan saat mulai diminta memberi nama terminalnya serta menjaga ringkasannya. Agen mana pun bisa melakukan hal yang sama dengan perintah berikut, yang dijelaskan aubergine guide kepadanya:

aubergine note "Tests pass on the branch. The migration is not written yet."
aubergine describe --summary "Fixing the double redirect at sign-in"

Sebelum berhenti untuk hari itu, tekan Ask its agent for a recap (minta rekap ke agennya) di detail terminal: agen menulis posisinya dengan aubergine recap --write, dan rekap itu disimpan bersama terminal.

Menutup laptop, mode tidur, dan browser

  • Mode tidur bukan mulai ulang. Menutup layar laptop biasanya membuatnya tidur: program berhenti sejenak dan berlanjut saat ia bangun, dan tidak ada yang di kolom terakhir tabel terjadi. Aubergine tidak menjaga komputer tetap terjaga dan tidak membangunkannya, jadi jadwal yang waktunya terlewat selama tidur berjalan terlambat, atau terlewat, seperti di atas.
  • Menutup browser, tab, atau jendelanya, atau pembaruan browser yang memulainya ulang, tidak mengakhiri apa pun. Buka lagi halamannya (aubergine open membukanya dalam keadaan masuk) dan setiap terminal digambar dari tmux seperti keadaannya sekarang. Halaman yang dibiarkan terbuka tersambung lagi dengan sendirinya saat server kembali.
  • Menutup jendela tempat aubergine start berjalan, atau menekan Ctrl+C di sana, menghentikan server dan tidak ada yang lain: kolom tengah tabel.
  • Di Windows dengan WSL, berhentinya WSL, karena Windows dimulai ulang atau setelah wsl --shutdown, bagi Aubergine adalah komputer yang dimulai ulang. Lihat Windows dengan WSL.

Pertanyaan

Bisakah Aubergine memulihkan terminal saya setelah reboot?

Ya, semuanya kecuali yang sedang berjalan di dalamnya. Setiap terminal kembali ke tempatnya di kanvas dengan nama, warna, catatan, tag, field, dan link-nya, sebagai shell baru di folder terakhirnya. Program yang berjalan di dalamnya tidak dimulai lagi; untuk Claude Code, Resume agent melanjutkan percakapannya.

Apakah Aubergine menyimpan output dan riwayat terminal saya?

Output hanya selama shell berjalan: tmux menyimpan 50.000 baris scrollback setiap terminal, dan menutup browser atau memulai ulang Aubergine tidak menghilangkan sedikit pun. Setelah komputer dimulai ulang, output itu hilang, karena Aubergine tidak merekam output terminal. Riwayat perintah yang Anda ketik, yang dimunculkan lagi oleh panah atas, adalah file milik shell Anda sendiri, disimpan oleh shell Anda seperti biasa.

Apakah percakapan Claude Code saya bertahan setelah mulai ulang?

Percakapannya, ya: Claude Code menyimpannya di file miliknya sendiri, dan Aubergine mengingat percakapan mana tempat setiap terminal berada. Setelah mulai ulang, Resume agent di bilah judul terminal menjalankan Claude Code lagi di percakapan itu. Apa yang sedang dikerjakan agen saat itu sudah berhenti, dan tidak dikerjakan lagi sampai Anda minta.

Apakah ini berfungsi saat macOS memperbarui dirinya di malam hari?

Pembaruan yang memulai ulang komputer adalah mulai ulang seperti yang lain: program yang berjalan berakhir dan semua yang lain dipertahankan. Dengan mulai saat login (aubergine service install), server berjalan lagi begitu Anda login, dan kanvas menunggu. Shell baru di folder terakhirnya terlihat saat sebuah kontainer Aubergine dimulai ulang; pembaruan macOS sungguhan di malam hari belum dicoba.

Apakah saya perlu paham tmux?

Tidak. tmux harus terpasang (3.2 atau lebih baru), dan Aubergine menjalankannya di socket sendiri dengan pengaturan sendiri, tanpa bilah status dan tanpa tombol prefiks, jadi Anda tidak pernah mengetik perintah tmux. tmux milik Anda sendiri, jika Anda memakainya, tidak disentuh.
