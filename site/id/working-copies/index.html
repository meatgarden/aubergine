Dua agen, satu repositori: salinan kerja

Biasanya setiap terminal bekerja di folder Anda yang sebenarnya. Dua agen di satu repositori lalu mengedit file yang sama, dan Anda tidak bisa tahu perubahan mana milik siapa. Salinan kerja memberi setiap terminal checkout-nya sendiri, di branch sendiri.

Menjalankan terminal di salinan kerja

  1. Tekan ▾ di ujung New terminal, di bagian atas daftar terminal, lalu Shell in a folder or a working copy….
  2. Tentukan foldernya dan pilih In its own working copy. Pilihan ini hanya ditawarkan jika memungkinkan, dan menjelaskan alasannya jika tidak: bukan repositori Git, repositori bare, atau belum ada commit.

Dari terminal, hal yang sama:

aubergine here --copy
aubergine new "api" --copy --in ~/code/my-project

Apa yang Anda dapat

Worktree Git di folder yang disimpan Aubergine di bawah folder datanya, tidak pernah di dalam repositori Anda, di branch baru bernama aubergine/<terminal name>-<six characters>. Ia dimulai dari commit tempat checkout Anda berada, dan terminal dimulai di subfolder yang sama dengan tempat Anda berada. Checkout Anda sendiri tidak pernah diubah: tidak file-nya, tidak apa yang sudah di-stage, tidak branch yang sedang Anda checkout.

Tidak ikut terbawa: perubahan Anda yang belum di-commit (tidak ada yang di-stash atau di-commit untuk Anda), dan file yang diabaikan atau tidak dilacak Git, seperti dependensi yang sudah terpasang dan pengaturan lokal. Proyek yang perlu langkah instalasi perlu menjalankannya lagi di salinan kerja.

Membaca apa yang diubah agen

Terminal di salinan kerja menampilkan branch-nya dan jumlah file yang berbeda di bilah judulnya. Klik untuk melihat file yang diubah, ditambah, dan dihapus, dengan pekerjaan yang belum masuk commit mana pun ditandai, dan perbedaan hanya-baca untuk file mana pun yang Anda pilih.

Saat terminal berakhir

Salinan kerja tidak pernah dihapus hanya karena terminalnya berakhir. Anda yang memilih:

  • Keep the branch, remove the folder (simpan branch, hapus folder), jika semuanya sudah di-commit.
  • Keep everything. (Simpan semuanya.) Ia tetap ada di daftar, dengan keterangan bahwa terminalnya sudah tidak ada.
  • Discard both (buang keduanya), yang bertanya untuk kedua kalinya jika salinan itu berisi pekerjaan yang tidak ada di tempat lain.
aubergine copies
aubergine copies show api
aubergine copies keep-branch api
aubergine copies discard api

Aubergine tidak pernah melakukan merge, push, atau rebase. Apa yang Anda lakukan dengan branch yang disimpan adalah urusan Anda.

Apa yang dijalankan Aubergine di repositori Anda

Aubergine memakai git di PATH Anda (2.31 atau lebih baru). Untuk setiap perintah Git yang dijalankannya, tidak ada hook yang berjalan, tidak ada yang meminta input, tidak ada yang menyentuh jaringan, dan submodule tidak diambil. Filter yang disebut di konfigurasi Git Anda sendiri, seperti penyimpanan file besar, tetap berjalan, seperti pada git status Anda sendiri.

Ini bukan sandbox

Salinan kerja memisahkan pekerjaan. Ia tidak mengurung agen: agen berjalan sebagai Anda dan bisa membaca serta mengubah setiap file yang bisa Anda akses, termasuk checkout Anda sendiri. Jangan mengandalkannya untuk menahan agen yang berbuat salah. Lihat keamanan.

Terkait: menjalankan beberapa agen coding sekaligus · antrean dan jadwal (tugas yang dimulai di terminal baru mendapat salinan kerjanya sendiri jika foldernya ada di repositori).

Siap dipakai dalam lima menit

Anda memerlukan macOS dengan tmux 3.2 atau lebih baru dan Node.js 22 atau lebih baru. brew install tmux node memasang keduanya.

npm install -g @meatgarden/aubergine
