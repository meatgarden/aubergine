Roadmap

None of this exists today. It is where we want to go, and the order may change. For what is built now, see the guides.

Teams and connections

People working together, and agents reached from the tools you already use.

  • Multiplayer

    Share a canvas with other people and their agents. See who is working where, hand a waiting agent to a teammate, and answer together.

  • Chat interface

    Ask agents and answer their questions from a team chat app, with the same identity and settings as in the browser.

  • Tickets and pull requests

    Turn an issue into a queued task, open a pull request from a working copy, and report the result back to the ticket.

  • Watches, webhooks and triage

    Start work when something happens: a failed CI job, an alert, a watched change or a call from another service. Rules decide what becomes a task.

  • Shared skills and a marketplace

    Share an agent's skills by grant, promote them team-wide with approval, import them from Git, and find reviewed items in a public catalog.

  • Memory for people and rooms

    Keep what an agent has learned for each person and each shared room, apart from the others.

Also: admin controls for models, sharing and strictness · a self-hosted team server · sign-in for teams (SSO and MFA) · usage limits per person, token or agent · read-only reports to share without sharing terminals · a phone view of the “For you” list · reviewed connectors to company tools · more chat apps · small internal web apps published to chosen people.

Cloud

Agents that do not need your laptop awake.

  • Sandboxed agents in the cloud

    Run an agent in an isolated cloud sandbox and watch it on the same canvas as your local ones. Sandboxes sleep when idle, wake on demand and keep storage between runs.

  • A pool of agents

    Describe the work and let a pool of agents pick it up, instead of naming a terminal for each task.

  • Ready-made environments

    Save dependencies, tools, skills, files and variables once, and start any new terminal or cloud agent from them.

  • Long, multi-phase work

    Tasks that run for hours or days in stages, with a check-in after each stage and progress that survives restarts.

  • One-command cloud deploy

    Put a team's shared Aubergine on your own cloud account with one command.

  • Work you can see

    A cloud agent hands back screenshots or a short recording of what it built, in your “For you” list.

Also: MCP over HTTP, for agents on other machines · tested Linux support · shell integration beyond zsh.

Control

How much an agent may do, and a record of what it did.

  • Approval modes

    Choose how much an agent may do alone: approve every action, approve the risky ones, or none.

  • Command policy and screening

    Rules for commands that need approval or are always refused, and optional screening of outside content before an agent reads it.

  • Risk levels per repository

    Stricter limits where it matters, looser where it does not.

  • A full audit trail

    A record of who or what did what, per project, beyond the token calls recorded today.

  • Undo an agent's work

    Roll a working copy back to before a task, or discard its branch in one step.

  • Admin controls

    Team-wide settings for which models may be used and how sharing works.

Also: model choice per terminal, task or schedule.

Quality

Checks that happen before work is called done.

  • Quality gates

    A run cannot finish until review, tests or a security check report a pass.

  • Pull request review

    An agent reviews a pull request and reports to your “For you” list.

  • Browser-driven testing

    An agent drives a browser to test a change and hands back the results.

  • Plan before build

    An agent proposes a plan and waits for your approval before touching files.

  • Task recipes

    Ready-made workflows for test generation, review, dependency and secret scans, and keeping docs current.

  • Outcome metrics

    Time from task to done, how often an agent waited on you, and usage by who started it, per project.

Also: incident write-ups, where an agent investigates and drafts a postmortem.

Everywhere

More ways to reach and build on Aubergine.

  • Published SDK

    The typed client as an installable package, then clients for other languages such as Python.

  • Editor extension

    Show your terminals and “For you” list inside VS Code and similar editors, without leaving the editor.

  • Desktop app

    A packaged app with a menu-bar icon, instead of a browser tab.

  • Windows support

    Run Aubergine on Windows itself. Today it runs only inside WSL 2, as the guide for Windows describes, and nobody has tried that on Windows yet.

Make it yours

More of the page shaped by you, beyond today's themes, colors, keys and templates.

  • Your own stylesheet

    A custom.css file loaded into the page, with documented hooks that are kept stable.

  • Plugins

    Your own code loaded into the page with full control, through named slots and past them. A sandboxed mode for other people's code may come later.

Planned work is a direction, not a promise. The repository shows what is shipped.

Up and running in five minutes

You need macOS with tmux 3.2 or newer and Node.js 22 or newer. brew install tmux node gets both.

npm install -g @meatgarden/aubergine
