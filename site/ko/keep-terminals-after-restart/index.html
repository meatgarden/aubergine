컴퓨터가 재시작되어도 터미널은 남습니다

브라우저를 닫거나 Aubergine을 다시 시작해도 잃는 것은 없습니다. 모든 터미널이 계속 실행됩니다. 컴퓨터가 재시작되면 실행 중이던 것은 끝나지만, Aubergine이 그 주변의 모든 것을 되돌려 주므로 처음부터가 아니라 하던 곳에서 이어 갈 수 있습니다.

이럴 때 무슨 일이 생기나

모든 터미널은 tmux 세션 안의 셸이며, 브라우저와도 Aubergine 서버와도 따로 실행됩니다. 터미널이 가진 것은 두 곳에 있습니다. 실행 중인 셸은 tmux만 가지고 있고, 터미널에 대해 말해진 모든 것은 Aubergine이 바뀔 때마다 데이터 폴더의 파일에 씁니다.

항목브라우저가 닫히거나, 멈추거나, 업데이트되거나, 탭을 닫을 때Aubergine이 멈추거나, 다시 시작되거나, 업데이트될 때컴퓨터가 멈추거나, 재시작되거나, 업데이트를 설치할 때

치워 둔 터미널도 똑같이 남고, 역시 새 셸을 받습니다. 셸이 이미 끝나 있던 터미널은 끝난 채로 남고, Restart here(여기서 다시 시작)가 나타납니다.

업데이트 후에도, 이미 열려 있던 터미널은 셸이 시작될 때 받은 것(PATH와 Aubergine의 셸 통합)을 그 셸이 다시 시작될 때까지 그대로 씁니다. Aubergine이 로그인할 때 시작된다면, 업데이트 후에 서버를 직접 다시 시작하는 대신 aubergine service install을 한 번 더 실행하세요.

재시작 후: 다시 일로

  1. Aubergine을 시작합니다. 로그인할 때 시작되도록 했다면(aubergine service install, macOS 전용) 로그인하는 순간 이미 실행 중이고, 멈추면 launchd가 다시 시작합니다. 그렇지 않다면 시작하고 페이지를 엽니다.

    aubergine start --open

  2. 캔버스는 떠날 때 그대로입니다. 모든 터미널이 이름, 색, 태그, 필드, 링크, 노트와 함께 제자리에 있고, 이제는 Aubergine이 마지막으로 본 폴더에서(그 폴더가 없어졌다면 기본 폴더에서) 새 셸입니다. 아무것도 다시 입력되거나 실행되지 않습니다.

  3. 에이전트를 재개합니다. Claude Code가 실행되던 터미널이고 Aubergine이 그 대화를 안다면(Aubergine에서 시작한 경우), 터미널의 제목 표시줄에 Resume agent(에이전트 재개)가 나타납니다. 그 대화에서 Claude Code를 다시 시작합니다. 워크플로 실행에 속한 터미널이라면 그 실행에 대해서도 다시 알려 주므로, 에이전트는 실행이 멈춰 있는 단계부터 이어 갑니다.

  4. 각자 어디까지 했는지 봅니다. 터미널 제목의 Details(세부 정보)는 알려진 것(실행의 단계와 마지막 보고, 폴더, 태그), 요약, 필드와 링크, 그리고 Log 아래의 로그를 보여 줍니다. 목록에서 터미널 이름에 포인터를 올리면 요약이 보입니다.

  5. 캔버스에 없는 대화를 찾습니다. 팔레트(⌘K)의 Past conversations…(지난 대화) 또는 터미널 세부 정보의 “Past conversations in this folder…”는 한 폴더의 이전 Claude Code 대화를 나열하고, 그중 하나를 캔버스에 엽니다.

다른 에이전트에는 Resume agent가 없습니다. Aubergine이 그 대화를 모르기 때문입니다. 같은 터미널에서 그 에이전트 자체의 재개 방법으로 다시 시작하고, 노트를 읽어 어디까지 했는지 알려 주세요.

잃는 것, 그리고 할 일

  • 실행 중이던 것은 끝납니다. 빌드, 테스트, 서버, 작업 중인 에이전트는 컴퓨터와 함께 멈추고, Aubergine은 그중 어느 것도 스스로 다시 시작하지 않습니다. 직접 다시 시작하세요. 재시작을 넘어 계속되어야 하는 작업은 시스템의 서비스처럼 그걸 위해 만들어진 것에 맡기세요.
  • Aubergine이 추적하는 작업은 여러분을 기다립니다. 워크플로 실행은 단계와 제출된 모든 보고를 유지합니다. 대기열의 작업은 자리를 지키고, 서버가 멈춘 순간 시작되던 작업은 한 문장의 이유와 함께 실패로 표시되며, 아무것도 스스로 다시 시도되지 않습니다. 서버가 멈춘 동안 지나간 일정의 시각은 지난 지 6시간이 안 되었다면(schedules.lateWithinHours) 늦게 한 번 실행되고, 그렇지 않으면 놓침으로 표시됩니다.
  • 스크롤백은 사라집니다. 셸이 실행되는 동안 tmux는 마지막으로 출력된 50,000줄을 가지고 있고, 팔레트의 검색이 그것을 읽습니다. Aubergine은 터미널이 출력하는 것을 기록하지 않으므로, 컴퓨터를 재시작한 뒤에는 되돌릴 것이 없고 검색은 그 이후에 출력된 것만 찾습니다.
  • “자리를 비운 동안”은 다시 시작됩니다. 파일이 아니라 서버의 메모리에 있으므로, 서버가 시작된 뒤에는 그 이후의 변화만 알고, 그렇다고 알려 줍니다.

재시작을 가볍게 만드는 습관

남는 것은 노트이므로, 에이전트가 일하면서 노트에 쓰게 하세요. 결정, 결과, 멈춘 곳. Aubergine에서 시작한 Claude Code는 여러분이 보내는 프롬프트가 하나하나 저절로 로그에 더해지고, 시작할 때 터미널에 이름을 붙이고 요약을 유지하라는 안내를 받습니다. 어느 에이전트든 다음 명령으로 같은 일을 할 수 있고, aubergine guide가 그 방법을 알려 줍니다.

aubergine note "Tests pass on the branch. The migration is not written yet."
aubergine describe --summary "Fixing the double redirect at sign-in"

하루를 마치기 전에 터미널 세부 정보에서 Ask its agent for a recap(에이전트에게 요약 요청)을 누르세요. 에이전트가 aubergine recap --write로 지금 상황을 쓰고, 그 요약은 터미널과 함께 남습니다.

노트북 덮개 닫기, 잠자기, 브라우저

  • 잠자기는 재시작이 아닙니다. 노트북 덮개를 닫으면 보통 잠자기에 들어갑니다. 프로그램은 잠시 멈췄다가 깨어나면 이어서 실행되고, 표의 마지막 열에 있는 일은 일어나지 않습니다. Aubergine은 컴퓨터를 깨어 있게 하지도, 깨우지도 않으므로, 잠자는 동안 시각이 지난 일정은 위와 같이 늦게 실행되거나 놓치게 됩니다.
  • 브라우저, 탭, 그 창을 닫거나, 브라우저 업데이트로 다시 시작해도 아무것도 끝나지 않습니다. 페이지를 다시 열면(aubergine open은 로그인된 상태로 엽니다) 각 터미널이 tmux에서 지금 모습 그대로 그려집니다. 열어 둔 페이지는 서버가 돌아오면 저절로 다시 연결됩니다.
  • aubergine start가 실행 중인 창을 닫거나 거기서 Ctrl+C를 누르면 서버만 멈추고 다른 것은 그대로입니다. 표의 가운데 열에 해당합니다.
  • WSL을 쓰는 Windows에서는 Windows가 재시작되거나 wsl --shutdown을 실행해 WSL이 멈추는 것이 Aubergine에게는 컴퓨터 재시작입니다. WSL을 쓰는 Windows를 보세요.

질문

Aubergine이 재부팅 후에 터미널을 복원할 수 있나요?

네, 안에서 실행 중이던 것만 빼고 모두. 각 터미널은 이름, 색, 노트, 태그, 필드, 링크와 함께 캔버스의 제자리로 돌아오고, 마지막 폴더의 새 셸이 됩니다. 그 안에서 실행되던 프로그램은 다시 시작되지 않습니다. Claude Code라면 Resume agent로 대화를 이어 갑니다.

Aubergine이 터미널 출력과 기록을 남기나요?

출력은 셸이 실행되는 동안만입니다. tmux가 터미널마다 스크롤백 50,000줄을 가지고 있고, 브라우저를 닫거나 Aubergine을 다시 시작해도 하나도 잃지 않습니다. 컴퓨터를 재시작하면 사라집니다. Aubergine은 터미널 출력을 기록하지 않기 때문입니다. 입력한 명령의 기록(위쪽 화살표로 다시 나오는 것)은 셸 자신의 파일이며, 늘 그렇듯 셸이 보관합니다.

Claude Code 대화가 재시작 후에도 남나요?

대화는 남습니다. Claude Code가 자신의 파일에 보관하고, Aubergine은 각 터미널이 어느 대화에 있었는지 기억합니다. 재시작 후 터미널 제목 표시줄의 Resume agent가 그 대화에서 Claude Code를 다시 시작합니다. 그 순간 에이전트가 하던 일은 멈췄고, 여러분이 요청할 때까지 다시 하지 않습니다.

macOS가 밤사이 스스로 업데이트해도 괜찮나요?

컴퓨터를 재시작하는 업데이트는 다른 재시작과 같습니다. 실행 중이던 프로그램은 끝나고 나머지는 모두 남습니다. 로그인할 때 시작하도록 해 두었다면(aubergine service install) 로그인하는 순간 서버가 다시 실행되고 캔버스가 기다립니다. 마지막 폴더의 새 셸은 Aubergine 컨테이너를 다시 시작할 때 확인했고, 실제 macOS 야간 업데이트는 시험해 보지 않았습니다.

tmux를 알아야 하나요?

아니요. 설치는 되어 있어야 하지만(3.2 이상), Aubergine은 자체 소켓에서 자체 설정으로 실행하며 상태 표시줄도 프리픽스 키도 없으므로 tmux 명령을 입력할 일이 없습니다. 여러분이 쓰는 tmux가 있다면 건드리지 않습니다.

tmux 3.2 이상과 Node.js 22 이상이 설치된 macOS가 필요합니다. brew install tmux node로 둘 다 설치할 수 있습니다.

npm install -g @meatgarden/aubergine
