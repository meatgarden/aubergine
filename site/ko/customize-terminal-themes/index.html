Aubergine 앱 자체는 영어로 되어 있습니다. 버튼, 메뉴, 그림은 모두 영어판 그대로입니다.

이 페이지는 영어 원문을 기계 번역한 것입니다. 수정 제안 보내기.

  2. 가이드
  3. 사용자 지정

터미널 테마, 색, 글꼴, 키 사용자 지정

열 가지 테마에서 페이지의 색을 고르고, 터미널마다 자기 테마를 주고, 개별 색, 터미널의 글꼴과 커서, 모든 키를 Settings나 스스로를 설명하는 설정 파일 하나에서 정합니다.

밝은 테마와 어두운 테마, 열 가지

Settings → Appearance는 세 가지 선택으로 시작합니다. Light, Dark, 그리고 새로 설치하면 이것으로 시작하고 시스템이 바뀌면 따라가는 Match the system입니다. 그 아래에서 종류마다 테마를 하나씩 고릅니다. Light, High contrast light, Solarized light, Gruvbox light 중 하나와, Dark, High contrast dark, Solarized dark, Gruvbox dark, Nord, Dracula 중 하나입니다. 각 테마에는 색을 보여 주는 작은 그림이 붙어 있습니다.

바꾸면 다시 불러오지 않아도 페이지와 모든 터미널에 바로 적용되고, 설정 파일에 저장되므로 Aubergine을 여는 모든 브라우저에서 같습니다. 팔레트에도 같은 명령이 있습니다. 예를 들어 Color theme: Nord입니다.

터미널마다 다른 색 테마

터미널 메뉴의 Theme…는 페이지가 어떤 테마이든 그 터미널을 열 가지 테마 중 어느 것으로든 그립니다. 바뀌는 것은 본문뿐이고, 제목, 노트, 세부 정보는 페이지 그대로입니다. 자기 테마가 없는 터미널은 Settings의 Terminal theme, 즉 터미널의 기본값을 따르고, 그것도 없으면 페이지를 따릅니다.

같은 선택이 목록에서 터미널 행의 메뉴, 세부 정보, 팔레트에도 있습니다. 터미널과 프레임에는 자기 색도 줄 수 있고(열세 가지 중 하나, 또는 아무 색이나 고르는 Your own…), 캔버스 탭도 마찬가지입니다. 터미널의 색은 목록에서 그 행의 색이기도 합니다.

개별 색을 직접 정하기

테마 외에도 페이지의 색 35가지를 설정 파일 config.json의 appearance.colors에서 정할 수 있습니다. 색 이름과 #rrggbb 형태의 값입니다. 맨 위에 쓰면 모든 테마 위에 적용되고, "[nord]"처럼 대괄호로 감싼 테마 ID 아래에 쓰면 그 테마에만 적용되며 우선합니다.

{
  "$schema": "./config.schema.json",
  "appearance": {
    "colors": {
      "accent": "#c678dd",
      "[nord]": { "terminal-bg": "#242933" }
    }
  }
}

이름은 페이지의 색 토큰입니다. 예를 들어 bg, text, accent, terminal-bg이며, docs/design.md에 목록이 있습니다. 잘못된 항목은 건너뛰고 파일의 나머지는 그대로 적용되며, 어느 것을 건너뛰었는지 Settings → Appearance가 알려 줍니다. 직접 정한 색은 여러분의 몫입니다. 쓴 색이 읽기 좋은지는 아무것도 확인하지 않습니다.

글꼴, 커서, 키보드 단축키

Settings → Appearance의 Terminal text는 터미널 글자의 크기(8~32픽셀)와 글꼴을 정합니다. 글꼴은 목록이며, 처음 찾은 글꼴을 씁니다. Cursor는 모양(블록, 막대, 밑줄)과 깜박임 여부를 정합니다.

모든 키를 바꿀 수 있습니다. 설정 파일에 shortcuts를 넣고, 명령 이름에 키 조합, 키 조합 목록, 또는 키 없음을 뜻하는 null을 적습니다. shortcutsInAppWindow도 같은 형식이며, Aubergine을 자기 창이 있는 앱으로 설치했을 때만 적용됩니다. 페이지를 다시 불러오면 단축키 표(?), 팔레트, 툴팁이 정한 대로 키를 보여 줍니다.

{
  "shortcuts": {
    "terminal.park": "X",
    "attention.next": ["Ctrl+Cmd+G", "W"],
    "view.fit": null
  }
}

두 번 정한 키나 읽을 수 없는 키는 단축키 표 맨 위와 서버가 알려 주고, 파일의 나머지는 그대로 적용됩니다. 키 하나만, 또는 Ctrl이나 Option과 키를 함께 쓰는 조합은 어떤 터미널도 키보드를 갖고 있지 않을 때만 동작합니다. 터미널 안의 모든 프로그램이 필요한 키를 계속 받도록 하기 위해서입니다. 자세한 내용은 README의 Keyboard에 있습니다.

스스로를 설명하는 설정 파일 하나

이 모든 것은 Aubergine 데이터 폴더의 config.json에 저장되며, 위치는 aubergine settings path가 알려 줍니다. 어떤 키든 빼도 됩니다. 읽을 수 없는 파일은 기본값을 뜻할 뿐, 서버가 시작되지 않는 일은 없습니다. 페이지의 Settings는 바꾼 키만 쓰고, 파일의 나머지는 쓴 그대로 둡니다.

서버는 시작할 때마다 파일 옆에 config.schema.json을 씁니다. 한 줄만 더하면 JSON Schema를 읽는 편집기가 모든 키를 설명하고 자동 완성합니다.

{ "$schema": "./config.schema.json" }

aubergine settings list는 모든 키를 지금 값과 함께 보여 주고 기본값이 아닌 것에 표시하며, aubergine settings schema는 스키마를 출력합니다. docs/settings.md는 모든 키와 기본값, 그리고 Settings가 쓰는지 직접 쓰는지를 설명합니다.

aubergine settings path
aubergine settings list
aubergine settings schema

페이지에서는 Settings → Every setting이 같은 키를 값과 함께 보여 주고, 입력하는 대로 찾아 줍니다. Settings가 바꾸는 키는 해당 컨트롤로 데려가고, 직접 쓰는 키에는 파일에 넣을 줄을 위한 Copy가 있습니다. 거기서는 어떤 설정도 바뀌지 않습니다.

어떤 선택은 이 브라우저의 것이며 브라우저에 저장됩니다. 캔버스를 탭, 목록 하나, 열 중 무엇으로 보일지, 캔버스 위 막대의 위치와 열어 둘지, 사이드 패널과 지도를 접을지, 패널과 터미널 세부 정보의 너비, 그리고 터미널 목록의 필터, 묶음, 정렬입니다.

프로그램이나 에이전트가 바꿀 수 있는 것, 여러분의 것으로 남는 것

로컬 API를 통해, API 토큰을 가진 프로그램은 canvases:write로 캔버스를 정리할 수 있습니다. 이름, 색, 순서를 정하고, 그 위의 터미널을 옮기고 크기를 바꾸고 색을 주고, 프레임을 더합니다. sessions:write로는 터미널의 이름을 바꾸고 태그를 달고 필드를 바꾸고 색 테마를 줄 수 있습니다. 토큰이 닿는 프로젝트에만 닿습니다.

터미널 안의 에이전트는 자기 터미널만 설명하고 다른 터미널은 설명하지 않습니다. 이름, 무엇을 위한 것인지에 대한 요약, 링크, 필드를 aubergine describe, aubergine link add, aubergine field set으로 정합니다. 여러분이 직접 쓴 이름, 요약, 필드는 그대로 남고, 에이전트가 보낸 것은 제안으로 옆에 보관됩니다.

설정 자체는 오직 여러분의 것입니다. 어떤 토큰, 터미널, 에이전트도 바꿀 수 없습니다. PUT /v1/settings/appearance는 로그인한 브라우저에만 응답하고, appearance.colors, shortcuts 등은 파일에 직접 씁니다.

다른 도구는 인터페이스를 어떻게 사용자 지정하게 하나요?

이 표를 쓴 방법. 표에서 각 도구에 대해 말하는 내용은 그 도구 자체의 문서를 2026년 11월 28일에 읽은 것이며, 이름과 칸에서 링크됩니다. 이를 위해 이 도구들을 실행하지는 않았습니다. ‘찾지 못함’은 읽은 문서에 설명이 없다는 뜻이지, 그 도구가 할 수 없다는 뜻이 아닙니다. 틀리거나 오래된 내용이 있으면 알려 주세요.

Aubergine
캔버스 위의 터미널		config.json과 Settings, 편집기용 JSON Schema 포함테마 열 가지, 밝게, 어둡게, 시스템대로; 터미널마다 하나; 직접 정하는 색 35가지, 모든 테마 또는 하나에없음. 계획: 문서화된 훅이 있는 custom.css없음. 계획: 플러그인없음. 계획: 터미널 제목과 목록 행에

여기 있는 모든 도구는 설정을 파일에 두며, VS Code, Zed, Windows Terminal에는 Aubergine처럼 그 파일을 쓰는 화면도 있습니다. 대부분에서 테마도 파일입니다. VS Code와 Zed에서는 JSON, Obsidian에서는 CSS, WezTerm에서는 Lua나 TOML, kitty와 Ghostty에서는 설정 파일입니다. VS Code, Zed, WezTerm에서는 여기의 appearance.colors처럼 테마 위에 개별 색을 바꿀 수 있습니다.

가장 크게 다른 것은 코드입니다. WezTerm의 설정은 통째로 Lua 프로그램이고, kitty와 iTerm2는 내 Python을 실행하며, Hyper의 플러그인은 인터페이스를 감싸는 JavaScript입니다. Obsidian과 Hyper는 내 CSS도 받습니다. VS Code의 확장은 인터페이스의 DOM에 접근하지 못하고, VS Code는 내 스타일시트를 지원하지 않습니다. Zed는 확장을 WebAssembly로, 제한할 수 있는 권한과 함께 실행합니다. tmux, WezTerm, kitty, iTerm2는 템플릿이나 함수로 제목과 상태 줄을 만듭니다.

오늘의 Aubergine은 설정 쪽 끝에 있습니다. 테마, 색, 키를 스스로를 설명하는 파일 하나에 두고, 그 일부를 페이지가 씁니다. 페이지에서 내 코드를 실행하지 않고, 내 스타일시트를 받지 않으며, 템플릿도 없습니다. 이것들은 로드맵에 있으며 아직 만들어지지 않았습니다.

계획된 것

내 테마 파일, 프로젝트나 태그에 따른 모양, 템플릿, custom.css, 플러그인은 계획되어 있으며 아직 만들어지지 않았습니다. 로드맵을 보세요.

질문

터미널마다 다른 색 테마를 쓸 수 있나요?

네. 터미널 메뉴의 Theme…는 페이지의 테마와 상관없이 그 본문을 열 가지 테마 중 어느 것으로든 그립니다. 나머지는 터미널에 정한 기본값이나 페이지를 따릅니다.

Aubergine에 내 CSS를 넣을 수 있나요?

지금은 안 됩니다. 개별 색은 설정 파일에서 직접 정할 수 있고, 문서화된 훅이 있는 custom.css는 계획되어 있지만 아직 만들어지지 않았습니다.

Aubergine의 설정 파일은 어디에 있나요?

Aubergine 데이터 폴더의 config.json입니다. aubergine settings path가 위치를 알려 주고, 서버도 시작할 때 보여 줍니다.

에이전트가 Aubergine의 모양을 바꿀 수 있나요?

설정은 아닙니다. 설정은 오직 여러분의 것입니다. 에이전트는 자기 터미널의 이름을 정하고 설명할 수 있으며, API 토큰이 허락하는 프로그램은 터미널의 이름을 바꾸고 태그를 달고 테마를 주고 캔버스를 정리할 수 있습니다.

관련: 원하는 터미널 찾기 · tmux를 배우지 않고 tmux 쓰기 · 보안과 개인 정보 · 자주 묻는 질문

Aubergine은 이 페이지에 이름이 나온 어떤 도구와도 제휴하지 않았습니다. 각 이름은 해당 소유자의 상표입니다.

5분이면 시작합니다

tmux 3.2 이상과 Node.js 22 이상이 설치된 macOS가 필요합니다. brew install tmux node로 둘 다 설치할 수 있습니다.

npm install -g @meatgarden/aubergine
