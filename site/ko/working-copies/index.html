에이전트 둘, 저장소 하나: 작업 사본

모든 터미널은 보통 여러분의 실제 폴더에서 작업합니다. 그러면 한 저장소의 두 에이전트가 같은 파일을 편집하고, 어느 변경이 누구의 것인지 알 수 없습니다. 작업 사본은 각 터미널에게 자체 브랜치에 있는 자체 체크아웃을 줍니다.

작업 사본에서 터미널 시작하기

  1. 터미널 목록 맨 위에 있는 New terminal 끝의 ▾를 누른 다음 Shell in a folder or a working copy…를 누르세요.
  2. 폴더를 지정하고 In its own working copy를 고르세요. 이 선택지는 가능한 곳에서만 제공되며, 불가능한 곳에서는 이유를 알려 줍니다. Git 저장소가 아니거나, bare 저장소이거나, 아직 커밋이 없는 경우입니다.

터미널에서도 같은 일을 할 수 있습니다.

aubergine here --copy
aubergine new "api" --copy --in ~/code/my-project

얻게 되는 것

Aubergine이 저장소 안이 아니라 자체 데이터 폴더 아래에 두는 폴더에 만든 Git 워크트리이며, aubergine/<terminal name>-<six characters>라는 새 브랜치에 있습니다. 여러분의 체크아웃이 있는 커밋에서 시작하고, 터미널은 여러분이 있던 하위 폴더와 같은 곳에서 시작합니다. 여러분의 체크아웃은 결코 바뀌지 않습니다. 파일도, 스테이징된 내용도, 체크아웃된 브랜치도 그대로입니다.

옮겨지지 않는 것: 커밋하지 않은 변경(대신 stash하거나 커밋하지 않습니다), 그리고 설치된 의존성이나 로컬 설정처럼 Git이 무시하거나 추적하지 않는 파일. 설치 단계가 필요한 프로젝트는 작업 사본에서도 다시 설치해야 합니다.

에이전트가 바꾼 것 읽기

작업 사본에 있는 터미널은 제목 표시줄에 브랜치와 달라진 파일 수를 보여 줍니다. 클릭하면 변경, 추가, 삭제된 파일이 나오고 어느 커밋에도 없는 작업은 표시되며, 고른 파일의 차이를 읽기 전용으로 볼 수 있습니다.

터미널이 끝나면

작업 사본은 터미널이 끝났다는 이유만으로 지워지지 않습니다. 여러분이 고릅니다.

  • 모두 커밋되어 있다면 Keep the branch, remove the folder(브랜치는 남기고 폴더는 지우기).
  • Keep everything.(모두 남기기) 목록에 남아, 터미널이 사라졌다고 표시합니다.
  • Discard both(둘 다 버리기). 사본에 다른 어디에도 없는 작업이 있으면 한 번 더 묻습니다.
aubergine copies
aubergine copies show api
aubergine copies keep-branch api
aubergine copies discard api

Aubergine은 병합, 푸시, 리베이스를 하지 않습니다. 남긴 브랜치로 무엇을 할지는 여러분이 정합니다.

Aubergine이 저장소에서 실행하는 것

Aubergine은 git을 사용합니다. PATH에 있는 것으로, 2.31 이상이어야 합니다. 시작하는 모든 Git 명령에서 훅은 실행되지 않고, 아무것도 묻지 않고, 네트워크에 닿지 않으며, 서브모듈을 가져오지 않습니다. 대용량 파일 저장소처럼 여러분의 Git 설정에 지정된 필터는 여러분이 직접 실행하는 git status에서처럼 실행됩니다.

샌드박스가 아닙니다

작업 사본은 작업을 떼어 놓습니다. 에이전트를 가두지는 않습니다. 에이전트는 여러분으로서 실행되며 여러분의 체크아웃을 포함해 여러분이 할 수 있는 모든 파일을 읽고 바꿀 수 있습니다. 잘못된 일을 하는 에이전트를 막는 용도로 의존하지 마세요. 보안을 참고하세요.

관련: 여러 코딩 에이전트를 한꺼번에 실행하기 · 대기열과 일정(새 터미널에서 시작된 작업은 폴더가 저장소 안에 있으면 자체 작업 사본을 받습니다).

5분이면 시작합니다

tmux 3.2 이상과 Node.js 22 이상이 설치된 macOS가 필요합니다. brew install tmux node로 둘 다 설치할 수 있습니다.

npm install -g @meatgarden/aubergine
