Two agents, one repository: working copies

Every terminal normally works in your real folder. Two agents in one repository then edit the same files, and you cannot tell whose change is whose. A working copy gives each terminal its own checkout, on its own branch.

Start a terminal in a working copy

  1. Press ▾ at the end of New terminal, at the top of the list of terminals, then Shell in a folder or a working copy….
  2. Give the folder and choose In its own working copy. The choice is offered only where it can be had, and says why where it cannot: not a Git repository, a bare repository, or no commit yet.

From a terminal, the same thing:

aubergine here --copy
aubergine new "api" --copy --in ~/code/my-project

What you get

A Git worktree in a folder Aubergine keeps under its data folder, never inside your repository, on a new branch named aubergine/<terminal name>-<six characters>. It starts from the commit your checkout is on, and the terminal starts in the same subfolder you were in. Your own checkout is never changed: not its files, not what is staged, not the branch you have checked out.

Not carried over: your uncommitted changes (nothing is stashed or committed for you), and files Git ignores or does not track, such as installed dependencies and local settings. A project that needs an install step needs it again in the working copy.

Read what an agent changed

A terminal in a working copy shows its branch and the number of files that differ on its title bar. Click it for the changed, added and removed files, with work that is in no commit marked, and the read-only difference for any file you choose.

When the terminal ends

A working copy is never removed just because its terminal ended. You choose:

  • Keep the branch, remove the folder, when everything is committed.
  • Keep everything. It stays in the list, saying its terminal is gone.
  • Discard both, which asks a second time when the copy holds work that exists nowhere else.
aubergine copies
aubergine copies show api
aubergine copies keep-branch api
aubergine copies discard api

Aubergine never merges, pushes or rebases. What you do with a kept branch is yours.

What Aubergine runs in your repository

Aubergine uses the git on your PATH (2.31 or newer). For every Git command it starts, no hook runs, nothing prompts, nothing reaches the network, and submodules are not fetched. Filters named in your own Git configuration, such as large-file storage, do run, as they do for your own git status.

It is not a sandbox

A working copy keeps work apart. It does not keep an agent in: the agent runs as you and can read and change every file you can, including your own checkout. Do not rely on it to hold back an agent that does the wrong thing. See security.

Related: run several coding agents at once · the queue and schedules (a task started on a new terminal gets a working copy of its own where the folder is in a repository).

Up and running in five minutes

You need macOS with tmux 3.2 or newer and Node.js 22 or newer. brew install tmux node gets both.

npm install -g @meatgarden/aubergine
