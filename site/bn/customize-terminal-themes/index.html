Aubergine নিজে ইংরেজিতে: এর বোতাম, মেনু আর ছবি সবই ইংরেজি।

এই পেজটি ইংরেজি থেকে মেশিন দিয়ে অনুবাদ করা। সংশোধন পাঠান।

  1. Aubergine
  2. গাইড
  3. নিজের মতো করুন

টার্মিনালের থিম, রং, ফন্ট ও কী নিজের মতো করুন

দশটি থিম থেকে পেজের রং বেছে নিন, প্রতিটি টার্মিনালকে তার নিজের থিম দিন, আর আলাদা রং, টার্মিনালের ফন্ট ও কার্সর এবং প্রতিটি কী ঠিক করুন, Settings-এ বা এমন একটি সেটিংস ফাইলে যা নিজেই নিজের বর্ণনা দেয়।

হালকা ও গাঢ়, দশটি রঙের থিম

Settings → Appearance শুরু হয় তিনটি বিকল্প দিয়ে: Light, Dark আর Match the system; নতুন ইনস্টল এটি দিয়েই শুরু হয় এবং সিস্টেম বদলালে এটিও বদলায়। তার নিচে প্রতিটি ধরনের একটি করে থিম বাছেন: Light, High contrast light, Solarized light বা Gruvbox light; Dark, High contrast dark, Solarized dark, Gruvbox dark, Nord বা Dracula। প্রতিটি থিম তার রঙের একটি ছোট ছবির সঙ্গে দেখানো হয়।

কোনো বদল রিলোড ছাড়াই সঙ্গে সঙ্গে পেজ আর প্রতিটি টার্মিনালে লাগে, আর সেটিংস ফাইলে রাখা হয়, তাই যে ব্রাউজারেই Aubergine খুলুন, সব একই থাকে। প্যালেটেও একই জিনিস কমান্ড হিসেবে আছে, যেমন Color theme: Nord।

প্রতিটি টার্মিনালের জন্য আলাদা রঙের থিম

টার্মিনালের মেনুর Theme… সেই টার্মিনালকে দশটি থিমের যেকোনোটিতে আঁকে, পেজ যে থিমেই থাকুক। বদলায় শুধু তার ভেতরের অংশ: শিরোনাম, নোট আর বিবরণ পেজের মতোই থাকে। যে টার্মিনালের নিজের থিম নেই, সে Settings-এর Terminal theme মেনে চলে, অর্থাৎ টার্মিনালের ডিফল্ট, আর সেটিও না থাকলে পেজকে।

একই বিকল্প তালিকায় টার্মিনালের সারির মেনুতে, তার বিবরণে আর প্যালেটে আছে। টার্মিনাল আর ফ্রেমেরও নিজের রং থাকতে পারে, তেরোটির একটি বা যেকোনো রঙের জন্য Your own…, আর ক্যানভাসের ট্যাবেরও; টার্মিনালের রং তালিকায় তার সারিরও রং।

আলাদা রং হাতে ঠিক করুন

থিমের বাইরেও পেজের ৩৫টি রং সেটিংস ফাইল config.json-এ appearance.colors-এর নিচে ঠিক করা যায়: রঙের নাম আর #rrggbb আকারে লেখা মান। ওপরে লিখলে রংটি সব থিমের ওপর খাটে; বন্ধনীর ভেতরে থিমের ID-র নিচে লিখলে, যেমন "[nord]", শুধু সেই থিমের ওপর খাটে, আর সেটিই প্রাধান্য পায়।

{
  "$schema": "./config.schema.json",
  "appearance": {
    "colors": {
      "accent": "#c678dd",
      "[nord]": { "terminal-bg": "#242933" }
    }
  }
}

নামগুলো পেজের রঙের টোকেন, যেমন bg, text, accent আর terminal-bg; docs/design.md-এ তালিকা আছে। ভুল এন্ট্রি বাদ দেওয়া হয়, আর ফাইলের বাকিটা খাটে; কোনটি বাদ গেল তা Settings → Appearance জানায়। আপনার ঠিক করা রং আপনার দায়িত্ব: যা লিখলেন তা পড়া যায় কি না, কিছুই যাচাই করে না।

আপনার নিজের থিম, ফাইল হিসেবে

আপনার নিজের থিম হলো ডেটা ফোল্ডারের themes/-এ একটি JSON ফাইল: দশটির মধ্যে একই ধরনের একটি ভিত্তি হিসেবে, তার ওপর ৩৫টি রঙের যেকোনোটি, আর টার্মিনালের নিজের রং: তার লেখা, কার্সর, নির্বাচিত অংশ, এবং একটি প্রোগ্রাম যে ষোলোটি রং চায়। এটি নিজের ধরনের দশটির পরে, আপনার হিসেবে চিহ্নিত হয়ে তালিকায় আসে, এবং সেগুলো যেখানে বাছা যায় সেখানে বাছা যায়: পেজের জন্য, টার্মিনালের ডিফল্ট হিসেবে, বা একটি টার্মিনালের জন্য। ছায়া আর ফোকাস রিং ভিত্তিরই থাকে, এবং ফাইলের কিছুই চালানো হয় না।

{
  "$schema": "../theme.schema.json",
  "name": "Harbor",
  "kind": "dark",
  "base": "nord",
  "colors": { "bg": "#0e1a24", "accent": "#5fb3b3" },
  "terminal": { "foreground": "#d8dee9", "cursor": "#5fb3b3" }
}

aubergine theme new harbor --from nord শুরু করার জন্য একটি ফাইল লেখে, মূল থিমের প্রতিটি রং সহ; aubergine theme check বলে একটি ফাইলে কী ভুল; Settings-এ Read themes again একটি পরিবর্তন পড়ে নেয়। আপনার রং পড়া যায় কি না তা আপনিই বিচার করবেন: Settings শুধু তখনই জানায় যখন লেখা পড়তে কঠিন হতে পারে। ফরম্যাট docs/themes.md-এ আছে।

একটি প্রজেক্টের থিম, আর ট্যাগ অনুযায়ী টার্মিনালের থিম

আপনি যতক্ষণ একটি প্রজেক্ট দেখছেন, ততক্ষণ সেটি পেজটিকে নিজের থিমে আঁকতে পারে, যাতে এক নজরে বোঝা যায় আপনি কোথায়। Projects…-এ প্রজেক্টের পাশে When light আর When dark প্রতিটি ধরনের একটি করে থিম বেছে নেয়; As the page বিষয়টি Settings-এর ওপর ছেড়ে দেয়। অন্য যেকোনো প্রজেক্টে পেজ আপনার বেছে নেওয়া মতোই থাকে, আর সেই প্রজেক্টের ঠিকানায় রিলোড করলে প্রথম আঁকা থেকেই তার থিমে আঁকা হয়।

Settings-এ Terminal theme-এর নিচে By tag কোনো ট্যাগওয়ালা টার্মিনালগুলোকে নিজের থিম দেয়: যেমন prod ট্যাগওয়ালা প্রতিটি টার্মিনাল Dracula-তে, সঙ্গে সঙ্গে, পেজের থিম যা-ই হোক। টার্মিনালের যে ট্যাগের লাইন প্রথমে আসে সেটিই খাটে, আর টার্মিনালের নিজের থিম সবার আগে। সেটিংস ফাইলে এটি appearance.byTag:

{
  "appearance": {
    "byTag": [
      { "tag": "prod", "theme": "dracula" },
      { "tag": "docs", "theme": "solarized-light" }
    ]
  }
}

প্রায়ই একটি আলাদা অ্যাকসেন্ট রংই যথেষ্ট। aubergine theme new teal --from nord --accent "#2f9e8f" এমন একটি থিম ফাইল লেখে যা শুধু Nord-এর অ্যাকসেন্ট আর তার সঙ্গের পাঁচটি রং বদলায়, এমনভাবে হিসাব করে যাতে সেগুলো পড়া যায়। অন্য যেকোনো থিমের মতো এটি একটি প্রজেক্ট বা ট্যাগের জন্য বেছে নিন।

ফন্ট, কার্সর ও কিবোর্ড শর্টকাট

Settings → Appearance-এর Terminal text টার্মিনালের লেখার আকার, ৮ থেকে ৩২ পিক্সেল, আর ফন্ট ঠিক করে; ফন্ট একটি তালিকা, যার প্রথম পাওয়া ফন্টটি ব্যবহার হয়। Cursor তার আকার, ব্লক, বার বা আন্ডারলাইন, আর সেটি জ্বলে-নেভে কি না ঠিক করে।

প্রতিটি কী বদলানো যায়। সেটিংস ফাইলে shortcuts যোগ করুন: কোনো কমান্ডের নাম আর একটি কী-সমন্বয়, সমন্বয়ের তালিকা, বা কোনো কী না রাখতে null। shortcutsInAppWindow একই জিনিস নেয় আর শুধু সেখানে খাটে যেখানে Aubergine নিজস্ব জানালার অ্যাপ হিসেবে ইনস্টল করা। পেজ রিলোড করুন, তারপর শর্টকাট শিট (?), প্যালেট আর টুলটিপ কীগুলো ঠিক আপনার দেওয়া মতো দেখায়।

{
  "shortcuts": {
    "terminal.park": "X",
    "attention.next": ["Ctrl+Cmd+G", "W"],
    "view.fit": null
  }
}

দুবার ঠিক করা কী, বা যা পড়া যায় না, শর্টকাট শিটের ওপরে আর সার্ভারে জানানো হয়, আর ফাইলের বাকিটা খাটে। একা একটি কী, বা Ctrl বা Option-এর সঙ্গে একটি কী, তখনই কাজ করে যখন কোনো টার্মিনালের হাতে কিবোর্ড নেই, যাতে টার্মিনালের প্রতিটি প্রোগ্রাম তার দরকারি কী পেতে থাকে। আরও জানতে README-তে Keyboard দেখুন।

শিরোনাম আর সারি কী বলবে তা বেছে নিন

একটি টার্মিনালের নামের পরে, তার শিরোনাম আর তালিকায় তার সারি দুটি টেমপ্লেট যা বলে তা-ই বলে: {state}, {folder}, {time} ও {field:Ticket}-এর মতো প্লেসহোল্ডারসহ লেখা। এগুলো বদলান Settings → Appearance → Titles and rows-এ, যেখানে আপনি টাইপ করার সময় প্রতিটি ঘরের নিচে আসল শিরোনাম আর সারি আঁকা হয়, অথবা সেটিংস ফাইলে। এখানে শিরোনাম বলে অবস্থা, ফোল্ডার, ফিল্ড Ticket, লিংক আর ট্যাগ, আর সারি বলে অবস্থা, রানের ধাপ, ব্রাঞ্চ আর সময়:

{
  "appearance": {
    "titleFormat": "{state} {folder} · {field:Ticket} {links} {tags}",
    "rowFormat": "{state} {step} {branch} · {time}"
  }
}

যে প্লেসহোল্ডারের বলার কিছু নেই, তা তার দিকে নিয়ে যাওয়া লেখাসহ বাদ পড়ে: টিকিট, লিংক বা ট্যাগ ছাড়া কোনো টার্মিনালে সেই শিরোনাম শুধু তার অবস্থা আর ফোল্ডার বলে, কোনো বাড়তি বিন্দু থাকে না। টেমপ্লেটে শুধু লেখা আর প্লেসহোল্ডার থাকে, কোনো মার্কআপ বা স্টাইল নয়; প্রত্যেকটি এমনভাবে আঁকা হয় যেভাবে পেজ অন্য জায়গায় সেই জিনিস আঁকে, অবস্থা তার রঙে আর লিংক একটি চিপ হিসেবে। ভুল প্লেসহোল্ডার ঘরের নিচে জানানো হয় ও বাদ দেওয়া হয়, আর Reset টেমপ্লেট ছাড়া যা আঁকা হয় ঠিক তা-ই ফিরিয়ে আনে। সব প্লেসহোল্ডার আছে docs/templates.md-এ।

নিজের স্টাইলশিট

সেটিংস যেখানে পৌঁছায় না, সেখানের জন্য নিজের একটি স্টাইলশিট লিখুন: ডেটা ফোল্ডারে custom.css। সার্ভার এটিকে পেজের head-এ সবার শেষে যুক্ত করে, তাই প্রথম আঁকা থেকেই এটি থাকে, আর সমান নির্দিষ্টতার অ্যাপের নিয়মের ওপর আপনার নিয়ম জেতে, !important ছাড়াই। aubergine css new শুরু করার জন্য একটি লিখে দেয়, আর Settings → Appearance → Your stylesheet বলে এটি পাওয়া গেছে কি না, এটি বন্ধ করে, আর রিলোড ছাড়াই আবার পড়ে।

শুধু হুকের ওপর ভরসা করুন, অন্য কিছুর ওপর নয়: প্রতিটি টোকেন (--accent, --radius-surface এবং বাকিগুলো), পেজের রুটের অ্যাট্রিবিউট (data-theme, data-page), data-part দিয়ে চিহ্নিত অংশ, আর টার্মিনালের নিজের অ্যাট্রিবিউট (data-tags, data-state, data-name), যা তার নোড, তার সারি আর তার নিজের ব্রাউজার ট্যাবে একই। এগুলো docs/hooks.md-এ তালিকাভুক্ত এবং এক রিলিজ থেকে পরেরটিতে রাখা হয়; ক্লাসের নাম নয়। এখানে prod ট্যাগওয়ালা প্রতিটি টার্মিনালের শিরোনাম গাঢ় লাল, আর মানচিত্রটি নেই:

[data-part="terminal"][data-tags~="prod"] [data-part="terminal-title"] {
  background: #5c1f24;
}
[data-part="map"] {
  display: none;
}

আর দুটি টোকেন দিয়ে সব জায়গায় আরও গোল কোণ:

:root {
  --radius-surface: 16px;
  --radius-control: 10px;
}

কোনো নিয়ম পেজ ভেঙে দিলে, ঠিকানার পরে ?plain দিয়ে খুলুন: পেজটি আপনার স্টাইলশিট ছাড়া পাঠানো হয়। স্টাইলশিট যা উল্লেখ করে তার কিছুই অন্য ঠিকানা থেকে আনা হয় না: ছবি, ফন্ট বা স্টাইলশিট আসে এই সার্ভার থেকে বা ইনলাইন ডেটা থেকে, তাই পেস্ট করা কোনো স্নিপেট আপনার পেজে যা আছে তা অন্য কোথাও পাঠাতে পারে না। এটি আপনার লেখা বা পেস্ট করা ফাইলের জন্য একটি সুরক্ষা, স্যান্ডবক্স নয়। এটি শুধু Chromium-এ চেষ্টা করা হয়েছে।

আপনার নিজের কোড: প্লাগইন

সেটিংস আর স্টাইলশিটের পরে, কোড লিখুন: প্লাগইন হলো ডেটা ফোল্ডারের plugins/<id>/-এ আপনার নিজের একটি JavaScript মডিউল, সঙ্গে তার নাম বলা একটি plugin.json। পেজ কোনো বিল্ড ধাপ ছাড়াই সেটি যেমন আছে তেমনই ইমপোর্ট করে এবং তাকে একটি অবজেক্ট দেয়, aubergine: সাইড প্যানেলের একটি অংশ, তালিকার একটি ফিল্টার, শিরোনাম বা সারির জন্য একটি প্লেসহোল্ডার, প্যালেটে একটি কমান্ড, একটি রান দেখার একটি উপায়, অবস্থা ও ঘটার সঙ্গে সঙ্গে প্রতিটি পরিবর্তন, এবং পেজের প্রতিটি কল। aubergine plugin new <id> শুরু করার জন্য একটি লিখে দেয়।

প্লাগইন পেজে আপনার হয়ে চলে, আর কিছুই তাকে আলাদা রাখে না। এটি প্রতিটি টার্মিনাল পড়তে পারে, যেকোনোটিতে টাইপ করতে পারে এবং পেজের যেকোনো কিছু বদলাতে পারে। এটি স্যান্ডবক্সে নেই। এটি তখনই চলে যখন আপনি Settings → Plugins-এ এটি চালু করেন, এবং শুধু তখনকার ফাইলগুলোর মতোই: বদলে যাওয়া ফাইল আবার না দেখা পর্যন্ত লোড হয় না। এতে কোড ভুল করে চলে না; এটি তালা নয়, কারণ টার্মিনালের এজেন্টও আপনার হয়ে চলে এবং সেটিংস ফাইল লিখতে পারে। শুধু সেটাই চালু করুন যা আপনি লিখেছেন বা পড়েছেন।

aubergine-এর সদস্যরা docs/plugins.md-এ তালিকাভুক্ত এবং এক রিলিজ থেকে পরেরটিতে শুধু যোগ হয়; প্লাগইন তার বাইরে যা ছোঁয় তা বদলাতে পারে। প্যালেটে একটি কমান্ড, কয়েক লাইনে:

// plugins/hello/index.js
export function activate(aubergine) {
  aubergine.commands.add({
    id: 'hello',
    title: 'Say hello',
    run: () => aubergine.say('Hello from my plugin'),
  });
}

কোনো প্লাগইন পেজ ভেঙে দিলে, ঠিকানার পরে ?plain দিয়ে খুলুন: কোনো প্লাগইন লোড হয় না, আর আপনার স্টাইলশিট বাদ পড়ে। ব্যর্থ প্লাগইনের কথা Settings-এ বলা হয়, আর পেজ ও অন্য প্লাগইনগুলো চলতে থাকে। বন্ধ করলে, aubergine দিয়ে সে যা যোগ করেছে তা সঙ্গে সঙ্গে চলে যায়; তার বাইরে যা করেছে তা রিলোডে যায়। এটি শুধু Chromium-এ চেষ্টা করা হয়েছে।

একটি সেটিংস ফাইল যা নিজেই নিজের বর্ণনা দেয়

এই সব Aubergine-এর ডেটা ফোল্ডারে config.json-এ রাখা হয়, আর সেটি কোথায় তা aubergine settings path দেখায়। যেকোনো কী বাদ দেওয়া যায়। যে ফাইল পড়া যায় না তার মানে ডিফল্ট, কখনো এমন সার্ভার নয় যা চালু হয় না। পেজের Settings শুধু যে কীগুলো বদলায় সেগুলোই লেখে, আর ফাইলের বাকিটা আপনি যেমন লিখেছেন তেমনই রাখে।

প্রতিবার চালু হলে সার্ভার ফাইলের পাশে config.schema.json লেখে। একটি লাইন যোগ করুন, আর JSON Schema পড়তে পারা এডিটর প্রতিটি কীর বর্ণনা দেয় ও নিজে থেকে পূরণ করে:

{ "$schema": "./config.schema.json" }

aubergine settings list প্রতিটি কী তার এখনকার মানসহ দেখায়, যেখানে ডিফল্ট নয় সেখানে চিহ্ন দিয়ে, আর aubergine settings schema স্কিমা দেখায়। docs/settings.md প্রতিটি কী, তার ডিফল্ট, আর সেটি Settings লেখে নাকি আপনি, তা বর্ণনা করে।

পেজে Settings → Every setting একই কীগুলো তাদের মানসহ দেখায়, আর টাইপ করতেই খুঁজে দেয়। যে কী Settings বদলায় সেটি আপনাকে তার নিয়ন্ত্রণে নিয়ে যায়; হাতে লেখা কীর পাশে আছে Copy, ফাইলে যোগ করার লাইনের জন্য। সেখানে কোনো সেটিং বদলায় না।

কিছু বিকল্প এই ব্রাউজারের, আর সেখানেই রাখা হয়: ক্যানভাসগুলো ট্যাব, একটি তালিকা না একটি কলাম; ক্যানভাসের ওপরের বার কোথায় আর খোলা থাকে কি না; পাশের প্যানেল আর মানচিত্র ভাঁজ করা কি না; প্যানেল আর টার্মিনালের বিবরণের চওড়া; আর টার্মিনালের তালিকা কীভাবে ছাঁকা, দলবদ্ধ ও সাজানো হয়।

কোনো প্রোগ্রাম বা এজেন্ট কী বদলাতে পারে, আর কী আপনার থাকে

লোকাল API দিয়ে, API টোকেন থাকা প্রোগ্রাম canvases:write নিয়ে ক্যানভাস সাজাতে পারে: নাম, রং ও ক্রম ঠিক করা, তাদের ওপর টার্মিনাল সরানো, আকার বদলানো ও রং দেওয়া, আর ফ্রেম যোগ করা। sessions:write নিয়ে সে টার্মিনালের নাম বদলাতে, ট্যাগ দিতে, ফিল্ড বদলাতে আর রঙের থিম দিতে পারে। সে শুধু সেই প্রজেক্টগুলোতেই পৌঁছায় যেখানে তার টোকেন পৌঁছায়।

টার্মিনালের ভেতরের এজেন্ট শুধু নিজের টার্মিনালের বর্ণনা দেয়, অন্য কারও নয়: নাম, সেটি কিসের জন্য তার সারাংশ, লিংক আর ফিল্ড, aubergine describe, aubergine link add আর aubergine field set দিয়ে। যেখানে আপনি নিজে নাম, সারাংশ বা ফিল্ড লিখেছেন, সেখানে আপনারটাই থাকে, আর এজেন্ট যা পাঠাল তা পাশে প্রস্তাব হিসেবে রাখা হয়। এজেন্ট, বা workflows:write থাকা কোনো প্রোগ্রাম, aubergine theme propose দিয়ে একটি রঙের থিমও প্রস্তাব করতে পারে: Review-এ আপনি সেটি পড়ে, আঁকা অবস্থায় দেখে, পেজে চেষ্টা করে গ্রহণ না করা পর্যন্ত সেটি কোথাও আঁকা হয় না, আর গ্রহণ করলে তার ফাইল লেখা হয়, কিছুই বেছে নেওয়া হয় না।

সেটিংস নিজেই শুধু আপনার। কোনো টোকেন, টার্মিনাল বা এজেন্ট সেগুলো বদলাতে পারে না: PUT /v1/settings/appearance শুধু সাইন-ইন করা ব্রাউজারকে উত্তর দেয়, আর appearance.colors, shortcuts ও বাকিগুলো ফাইলে হাতে লেখা হয়।

অন্য টুলগুলো ইন্টারফেস নিজের মতো করতে কীভাবে দেয়?

এটি কীভাবে লেখা হয়েছে। সারণি প্রতিটি টুল সম্পর্কে যা বলে তা সেই টুলের নিজের ডকুমেন্টেশন থেকে, ২৮ নভেম্বর ২০২৬-এ পড়া, আর তার নাম ও ঘর থেকে লিংক করা। এর জন্য আমরা এই টুলগুলো চালাইনি। “পাওয়া যায়নি” মানে আমাদের পড়া ডকুমেন্টেশনে এর বর্ণনা নেই, এই নয় যে টুলটি এটি পারে না। কিছু ভুল বা পুরোনো হলে আমাদের জানান।

টুলসেটিংসথিম ও রংআপনার নিজের CSSআপনার নিজের কোডশিরোনাম ও স্ট্যাটাসের টেমপ্লেট

একটি টার্মিনাল		একটি ফাইল: নথিভুক্ত রিলিজে .hyper.js, ডেভেলপমেন্ট ব্রাঞ্চে hyper.jsonথিম হলো প্লাগইনজানালার জন্য css; termCSS, যা সংস্করণ ২ থেকে আর টার্মিনালের লেখা সাজায় নাElectron ও রেন্ডারার যে npm প্লাগইন লোড করে: সেগুলো তার React কম্পোনেন্ট মোড়ে আর Redux মিডলওয়্যার যোগ করেপাওয়া যায়নি
WezTerm
একটি টার্মিনাল		একটি Lua ফাইল, .wezterm.lua৭০০-র বেশি স্কিম; আপনার নিজেরগুলো Lua বা TOML-এ; আলাদা রঙের জন্য colorsপাওয়া যায়নিকনফিগারেশনই Lua; প্লাগইন হলো কোনো Git ঠিকানা থেকে আসা LuaLua ফাংশন ট্যাব ও জানালার শিরোনাম ফেরত দেয় (format-tab-title)
tmux
একটি টার্মিনাল মাল্টিপ্লেক্সার		ফাইলে tmux কমান্ড; সার্ভার, সেশন, জানালা ও প্যান অনুযায়ী বিকল্পstatus-style আর window-style-এর মতো স্টাইলপাওয়া যায়নিহুক tmux কমান্ড চালায়; প্রোগ্রামের জন্য কন্ট্রোল মোড#{…} দিয়ে ফরম্যাট, স্ট্যাটাস লাইন, জানালার তালিকা, প্যানের সীমানা ও শিরোনামের জন্য
kitty
একটি টার্মিনাল		kitty.conf, অন্য ফাইল যোগ করা যায়, বদলালে আবার পড়া হয়থিম একটি .conf ফাইল; kitten themes ৩০০-র বেশি থেকে বাছে, আর গাঢ় ও হালকার জন্য আলাদা ঠিক করা যায়পাওয়া যায়নিkitty-র ভেতরে পুরো প্রবেশাধিকারসহ Python kitten; watchertab_title_template, যেখানে {custom} আপনার নিজের Python ডাকে
Ghostty
একটি টার্মিনাল		একটি key = value ফাইল; config-file অন্যগুলো যোগ করেথিম হলো কনফিগারেশন ফাইল; হালকার জন্য একটি, গাঢ়র জন্য একটিপাওয়া যায়নিটার্মিনালের ওপর GLSL শেডার; macOS-এ AppleScriptপাওয়া যায়নি
Windows Terminal
একটি টার্মিনাল		Settings পর্দা বা settings.json, একটি JSON স্কিমাসহপ্রোফাইল অনুযায়ী রঙের স্কিম; জানালা ও ট্যাবের থিম, হালকা ও গাঢ়, শুধু JSON-এপাওয়া যায়নিপাওয়া যায়নি; অন্য অ্যাপ JSON টুকরো হিসেবে প্রোফাইল ও রঙের স্কিম যোগ করেপাওয়া যায়নি; প্রোফাইল tabTitle আর tabColor ঠিক করে
iTerm2
একটি টার্মিনাল		Settings-এ প্রোফাইল; প্রপার্টি-লিস্ট ফাইল হিসেবে Dynamic Profilesব্যবহারকারী, হোস্ট, ফোল্ডার বা জব অনুযায়ী বাছা প্রোফাইল, Shell Integration-সহপাওয়া যায়নিএকটি Python API, Python-এ লেখা স্ট্যাটাস বারের অংশ, AppleScriptসেশনের নাম, ব্যাজ আর স্ট্যাটাস বারে ইন্টারপোলেটেড স্ট্রিং, \(…)
Aubergine
ক্যানভাসের ওপর টার্মিনাল		config.json আর Settings, এডিটরের জন্য JSON Schema-সহদশটি থিম, লাইট, ডার্ক বা সিস্টেমের মতো; এর যেকোনো একটির ওপর আপনার নিজের JSON ফাইল; একটি প্রজেক্টের জন্য, ট্যাগওয়ালা টার্মিনালের জন্য আর প্রতিটি টার্মিনালের জন্য একটি; ৩৫টি রং হাতে, সব থিম বা একটির জন্যহ্যাঁ: ডেটা ফোল্ডারে custom.css, নথিভুক্ত হুকসহহ্যাঁ: প্লাগইন, JavaScript মডিউল যা পেজে আপনার হয়ে চলে, নথিভুক্ত API দিয়ে এবং তার বাইরেও। স্যান্ডবক্স নেইদুটি, টার্মিনালের শিরোনাম আর তালিকার একটি সারির জন্য: {state} ও {field:Ticket}-এর মতো প্লেসহোল্ডারসহ লেখা

এখানকার প্রতিটি টুল তার সেটিংস একটি ফাইলে রাখে, আর VS Code, Zed ও Windows Terminal-এ Aubergine-এর মতো সেটি লেখার একটি পর্দাও আছে। বেশির ভাগে থিমও একটি ফাইল: VS Code ও Zed-এ JSON, Obsidian-এ CSS, WezTerm-এ Lua বা TOML, kitty ও Ghostty-তে কনফিগারেশন ফাইল। VS Code, Zed ও WezTerm থিমের ওপর আলাদা রং বদলাতে দেয়, যেমন এখানে appearance.colors করে।

সবচেয়ে বড় পার্থক্য কোডে। WezTerm-এর পুরো কনফিগারেশন একটি Lua প্রোগ্রাম, kitty ও iTerm2 আপনার নিজের Python চালায়, আর Hyper-এর প্লাগইন তার ইন্টারফেস মোড়ানো JavaScript; Obsidian ও Hyper আপনার নিজের CSS-ও নেয়। VS Code-এর এক্সটেনশনের তার ইন্টারফেসের DOM-এ প্রবেশ নেই, আর এটি আপনার নিজের স্টাইলশিট সমর্থন করে না; Zed এক্সটেনশন WebAssembly হিসেবে চালায়, এমন সক্ষমতাসহ যা আপনি সীমিত করতে পারেন। tmux, WezTerm, kitty ও iTerm2 টেমপ্লেট বা ফাংশন দিয়ে শিরোনাম ও স্ট্যাটাস লাইন বানায়।

আজ Aubergine সেটিংসের প্রান্ত থেকে কোড পর্যন্ত পৌঁছায়: নিজেকে বর্ণনা করা ফাইলে থিম, রং ও কী, সেটিংসের একাংশ লেখে এমন একটি পেজ, টার্মিনালের শিরোনাম ও তার সারি কী বলে তার টেমপ্লেট, স্থির রাখা হুকসহ আপনার নিজের স্টাইলশিট, এবং প্লাগইন, পেজে আপনার নিজের JavaScript, এমন API-সহ যাতে শুধু যোগ হয়। প্লাগইন পেজ যা পারে তার সব নিয়ে চলে; অন্যদের প্লাগইনের জন্য স্যান্ডবক্স মোড রোডম্যাপে আছে, তৈরি হয়নি।

কী পরিকল্পনায় আছে

অন্য কারও লেখা প্লাগইন স্যান্ডবক্সে চালানোর উপায়, আর রিভিউ স্ক্রিন দিয়ে একটি ইনস্টল করা, পরিকল্পিত এবং তৈরি হয়নি: রোডম্যাপ দেখুন।

প্রশ্ন

প্রতিটি টার্মিনালের কি আলাদা রঙের থিম হতে পারে?

হ্যাঁ। টার্মিনালের মেনুতে Theme… তার মূল অংশ দশটি থিমের যেকোনোটিতে আঁকে, পেজের থিম যা-ই হোক। ট্যাগওয়ালা টার্মিনালকে Settings-এ সেই ট্যাগ দিয়ে থিম দেওয়া যায়, আর বাকিরা টার্মিনালের জন্য আপনার ঠিক করা ডিফল্ট বা পেজ অনুসরণ করে।

Aubergine-এ কি নিজের CSS যোগ করতে পারি?

হ্যাঁ: ডেটা ফোল্ডারে custom.css (aubergine css new শুরু করার জন্য একটি লিখে দেয়)। প্রথম আঁকা থেকেই এটি পেজে সবার শেষে যুক্ত হয়, আর যে হুকগুলোর ওপর এটি ভরসা করতে পারে সেগুলো docs/hooks.md-এ আছে। এটি ছাড়া দেখতে পেজের ঠিকানায় ?plain যোগ করুন।

আমি কি Aubergine-এর জন্য নিজের প্লাগইন লিখতে পারি?

হ্যাঁ: ডেটা ফোল্ডারের plugins/<id>/-এ একটি JavaScript মডিউল (aubergine plugin new <id> শুরু করার জন্য একটি লিখে দেয়), Settings → Plugins-এ চালু করা। এটি পেজে আপনার হয়ে, পেজ যা পারে তার সবকিছু নিয়ে চলে; এটি স্যান্ডবক্সে নেই।

Aubergine-এর সেটিংস ফাইল কোথায়?

এটি Aubergine-এর ডেটা ফোল্ডারে config.json। aubergine settings path জানায় কোথায়, আর সার্ভার চালু হওয়ার সময় তা দেখায়।

কোনো এজেন্ট কি Aubergine-এর চেহারা বদলাতে পারে?

সেটিংস নয়: সেগুলো শুধু আপনার। এজেন্ট নিজের টার্মিনালের নাম রাখতে ও বর্ণনা দিতে পারে, আর একটি রঙের থিম প্রস্তাব করতে পারে যা আপনার পড়া ও গ্রহণের অপেক্ষায় থাকে; যে প্রোগ্রামের API টোকেন অনুমতি দেয় সে টার্মিনালের নাম বদলাতে, ট্যাগ দিতে, থিম দিতে, ক্যানভাস সাজাতে আর থিম প্রস্তাবও করতে পারে।

এই পেজে নাম নেওয়া কোনো টুলের সঙ্গে Aubergine যুক্ত নয়। নামগুলো তাদের মালিকদের ট্রেডমার্ক।
