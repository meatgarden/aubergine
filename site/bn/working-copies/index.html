Aubergine নিজে ইংরেজিতে: এর বোতাম, মেনু আর ছবি সবই ইংরেজি।

এই পেজটি ইংরেজি থেকে মেশিন দিয়ে অনুবাদ করা। সংশোধন পাঠান।

  2. গাইড

দুটি এজেন্ট, একটি রিপোজিটরি: ওয়ার্কিং কপি

সাধারণত প্রতিটি টার্মিনাল আপনার আসল ফোল্ডারে কাজ করে। তখন এক রিপোজিটরিতে দুটি এজেন্ট একই ফাইল বদলায়, আর কোন পরিবর্তন কার তা বোঝা যায় না। ওয়ার্কিং কপি প্রতিটি টার্মিনালকে তার নিজস্ব চেকআউট দেয়, নিজস্ব ব্রাঞ্চে।

ওয়ার্কিং কপিতে একটি টার্মিনাল চালু করুন

  1. টার্মিনালের তালিকার একদম উপরে New terminal-এর শেষে ▾ চাপুন, তারপর Shell in a folder or a working copy…।
  2. ফোল্ডারটি দিন আর In its own working copy বেছে নিন। বিকল্পটি শুধু সেখানেই দেওয়া হয় যেখানে তা সম্ভব, আর যেখানে সম্ভব নয় সেখানে কারণ বলে: Git রিপোজিটরি নয়, bare রিপোজিটরি, বা এখনো কোনো কমিট নেই।

টার্মিনাল থেকে, একই কাজ:

aubergine here --copy
aubergine new "api" --copy --in ~/code/my-project

আপনি যা পান

একটি Git worktree, এমন একটি ফোল্ডারে যা Aubergine তার ডেটা ফোল্ডারের নিচে রাখে, কখনো আপনার রিপোজিটরির ভেতরে নয়, aubergine/<terminal name>-<six characters> নামের একটি নতুন ব্রাঞ্চে। এটি শুরু হয় সেই কমিট থেকে যেখানে আপনার চেকআউট আছে, আর টার্মিনাল চালু হয় একই সাবফোল্ডারে যেখানে আপনি ছিলেন। আপনার নিজের চেকআউট কখনো বদলায় না: না তার ফাইল, না যা stage করা আছে, না যে ব্রাঞ্চটি আপনি চেকআউট করে রেখেছেন।

যা সঙ্গে আসে না: আপনার কমিট না করা পরিবর্তন (আপনার হয়ে কিছু stash বা কমিট করা হয় না), আর যে ফাইলগুলো Git উপেক্ষা করে বা ট্র্যাক করে না, যেমন ইনস্টল করা ডিপেন্ডেন্সি আর লোকাল সেটিংস। যে প্রজেক্টে ইনস্টল ধাপ লাগে, ওয়ার্কিং কপিতে আবার তা লাগে।

এজেন্ট কী বদলেছে পড়ুন

ওয়ার্কিং কপির টার্মিনাল তার টাইটেল বারে নিজের ব্রাঞ্চ আর আলাদা হওয়া ফাইলের সংখ্যা দেখায়। বদলানো, যোগ করা আর মোছা ফাইল দেখতে তাতে ক্লিক করুন, যেখানে কোনো কমিটে না থাকা কাজ চিহ্নিত থাকে, আর আপনার বেছে নেওয়া যেকোনো ফাইলের শুধু-পড়ার পার্থক্য।

টার্মিনাল শেষ হলে

শুধু টার্মিনাল শেষ হয়েছে বলে কোনো ওয়ার্কিং কপি কখনো মোছা হয় না। আপনি বেছে নেন:

  • Keep the branch, remove the folder (ব্রাঞ্চ রাখুন, ফোল্ডার সরান), যখন সবকিছু কমিট করা।
  • Keep everything. (সব রাখুন।) এটি তালিকায় থাকে, বলে যে এর টার্মিনাল আর নেই।
  • Discard both (দুটোই বাদ দিন), যা দ্বিতীয়বার জিজ্ঞেস করে যখন কপিতে এমন কাজ থাকে যা আর কোথাও নেই।
aubergine copies
aubergine copies show api
aubergine copies keep-branch api
aubergine copies discard api

Aubergine কখনো merge, push বা rebase করে না। রাখা ব্রাঞ্চ নিয়ে কী করবেন, তা আপনার ব্যাপার।

Aubergine আপনার রিপোজিটরিতে কী চালায়

Aubergine সেই git ব্যবহার করে যা আপনার PATH-এ আছে (2.31 বা নতুনতর)। এটি যে প্রতিটি Git কমান্ড চালু করে, তাতে কোনো হুক চলে না, কিছু জিজ্ঞেস করা হয় না, কিছুই নেটওয়ার্কে পৌঁছায় না, আর submodule ফেচ করা হয় না। আপনার নিজের Git কনফিগারেশনে নাম দেওয়া ফিল্টার, যেমন large-file storage, চলে, যেমন আপনার নিজের git status-এর জন্য চলে।

এটি স্যান্ডবক্স নয়

ওয়ার্কিং কপি কাজ আলাদা রাখে। এটি এজেন্টকে আটকে রাখে না: এজেন্ট আপনার পরিচয়ে চলে আর আপনি যে ফাইল পড়তে ও বদলাতে পারেন সবই পারে, আপনার নিজের চেকআউট সহ। ভুল কাজ করা এজেন্টকে থামাতে এর ওপর ভরসা করবেন না। নিরাপত্তা দেখুন।

সম্পর্কিত: একসঙ্গে কয়েকটি কোডিং এজেন্ট চালান · কিউ আর শিডিউল (নতুন টার্মিনালে শুরু হওয়া টাস্ক নিজস্ব ওয়ার্কিং কপি পায়, যেখানে ফোল্ডারটি কোনো রিপোজিটরিতে আছে)।

পাঁচ মিনিটে চালু

আপনার লাগবে macOS, সঙ্গে tmux 3.2 বা নতুনতর আর Node.js 22 বা নতুনতর। brew install tmux node দুটোই এনে দেয়।

npm install -g @meatgarden/aubergine
