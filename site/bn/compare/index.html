Tools for running several coding agents, compared

Seven tools for the same moment: more than one coding agent at work, and you in the middle. Here is Aubergine beside Conductor, Claude Squad, Vibe Kanban, cmux, Warp and Paradev, with a page for each.

How this was written. What these pages say about another tool is from that tool's own site, documentation and repository as read on 26 November 2026, and each page links to them. We have not run the other tools. Where their documentation says nothing, the page says that nothing was found, not that the tool cannot do it. These tools change fast: if something here is wrong or out of date, tell us and it will be corrected.

One page for each

Each page has the whole table for the two, where they differ, and what the other tool has that Aubergine does not.

  • Aubergine vs Conductor

    Pick Conductor if you want a Mac app that takes a task from a prompt to a merged pull request, with a cloud for work that goes on while your Mac is off.

  • Aubergine vs Claude Squad

    Pick Claude Squad if you live in a terminal and want one small program there that starts agents in worktrees and pushes their branches, and nothing more.

  • Aubergine vs Vibe Kanban

    Pick Vibe Kanban if you think in issues: plan on a board, hand each card to an agent, review its diff with comments, and merge.

  • Aubergine vs cmux

    Pick cmux if you want a fast native Mac terminal app with panes, an in-app browser and macOS notifications, and you script your own way of working on top of it.

  • Aubergine vs Warp

    Pick Warp if you want one terminal app for everything, on Windows and Linux too, with its own agent built in and cloud agents you can schedule.

  • Aubergine vs Paradev, formerly Superset

    Pick Paradev if you want a desktop app that makes a worktree for every task and takes it through diff, checks and merge, with phone apps and a cloud when you pay for them.

What Aubergine is built around

  • Ordinary terminals. An agent runs in Aubergine as it runs in any terminal app. There is no chat view over it and nothing between you and what it prints.
  • All of them in sight. Terminals stand side by side on a canvas you pan and zoom, with one list of every terminal and its state in words. See Find the right terminal.
  • Closing the window ends nothing. Every terminal is a tmux session, so the browser and Aubergine itself can stop while your agents go on. See what a restart keeps.
  • Your computer only. No account, no cloud, no paid plan and no model of its own; the server listens on 127.0.0.1. See security.
  • A person decides. What an agent proposes waits for your review, an approval in a workflow is yours alone, and one list, For you, holds everything that waits on you. See the queue.

What Aubergine does not have

  • No desktop app and no phone app. It is a page in your browser. Another device can be paired through a proxy you run; that was run once on one Mac and never on a real phone.
  • No pull requests and no merging. It shows what changed in a working copy, file by file, and never commits, pushes, rebases or merges.
  • No cloud. Agents run on the computer Aubergine runs on, and schedules fire only while it is on.
  • No sound and no push. Notifications come from an Aubergine page open in your browser.
  • Built for macOS. On Linux it has been run in containers only; on Windows it runs only inside WSL 2, which has not been tried.
  • Most for Claude Code. Any command-line agent runs in a terminal, but what Aubergine does by itself for an agent (seeing that it waits, resuming a conversation) is built for Claude Code; another agent reports through the aubergine commands.

Questions

What is the best tool for running several Claude Code agents at once?

It depends on what you want around the agents. For a Mac app with diffs, pull requests and merging: Conductor or Paradev. For a program inside the terminal you already use: Claude Squad. For a board of issues: Vibe Kanban. For a native Mac terminal: cmux. For a terminal with its own agent and cloud agents: Warp. For plain terminals side by side in a browser page, kept running by tmux, with no account: Aubergine.

Which of these tools are open source?

As read on 26 November 2026: Aubergine (MIT), Paradev (MIT), Vibe Kanban (Apache-2.0), Claude Squad (AGPL-3.0), the cmux app (GPL-3.0-or-later) and the Warp client (AGPL-3.0). Conductor's terms call it proprietary.

Which of these tools run on Linux or Windows?

By their own documentation: Warp on macOS, Windows and Linux; Vibe Kanban on all three; Claude Squad on macOS and Linux, and on Windows with tmux through WSL; Paradev on macOS with an experimental Linux build; Conductor and cmux on macOS only. Aubergine is built for macOS, has been run on Linux in containers only, and runs on Windows only inside WSL 2, not yet tried.

Which keep agents running after you close the app?

Aubergine and Claude Squad run each agent in a tmux session. Paradev documents a background daemon that keeps terminals when its window closes. cmux keeps live processes only in its opt-in tmux mode. Conductor says local sessions end with the app. Warp restores windows and recent output, not running programs. Each of Conductor, cmux, Warp and Paradev also has a cloud where agents go on. None, Aubergine included, keeps a local agent running through a restart of the computer.
