Aubergine unter Windows mit WSL installieren

Aubergine läuft nicht auf Windows selbst. Es läuft in WSL 2, dem Linux, das Windows mitbringt, und du bedienst es in deinem Browser unter Windows.

Was ausprobiert wurde. Die Linux-Schritte liefen am 25. November 2026 unter Ubuntu 24.04.5 (x86_64) in einem Container, nicht in WSL, mit Aubergine 0.2.2 von npm: Es hat seine Terminal-Bibliothek kompiliert, ist gestartet, hat einen Browser angemeldet und ein Terminal und die Demo laufen lassen. Node.js mit nvm zu installieren wurde dort nicht ausgeführt, weil Node.js 22 schon installiert war. Nichts auf dieser Seite wurde bisher unter Windows ausgeführt. Wenn du es ausprobierst, erzähl uns, wie es lief.

Was du brauchst

Windows 11 oder Windows 10 Version 2004 (Build 19041) oder neuer, wo sich WSL 2 mit einem Befehl installieren lässt. Microsofts Seite zur Installation von WSL hat die Einzelheiten.

Installieren und starten

  1. Installiere WSL. Öffne PowerShell als Administrator, führe das hier aus und starte Windows neu, wenn es fertig ist. Es installiert WSL 2 mit Ubuntu.

    wsl --install

    Öffne nach dem Neustart Ubuntu aus dem Startmenü und wähle dort einen Benutzernamen und ein Passwort. Alle folgenden Befehle tippst du dort ein, in Ubuntu.

  2. Installiere, was Aubergine braucht: tmux, zsh und Git sowie die Werkzeuge, die seine Terminal-Bibliothek kompilieren, denn für Linux gibt es sie nicht fertig gebaut.

    sudo apt update

    sudo apt install -y tmux zsh git build-essential python3

    Installiere Node.js 22. Ubuntus eigenes Paket ist Version 18 und damit zu alt. Ein bekannter Weg ist nvm: installiere es, öffne ein neues Ubuntu-Fenster und installiere dann Node.js 22.

    curl -o- https://raw.githubusercontent.com/nvm-sh/nvm/v0.40.3/install.sh | bash

    nvm install 22

    node -v sollte jetzt v22 oder neuer melden.

  3. Installiere Aubergine von npm. Es kompiliert beim Installieren seine Terminal-Bibliothek; im Versuch dauerte die ganze Installation 13 Sekunden.

    npm install -g @meatgarden/aubergine

  4. Starte es und lass das Fenster offen:

    aubergine start

    Melde deinen Browser an. Gib in einem zweiten Ubuntu-Fenster die Anmeldeadresse aus und öffne sie in deinem Browser unter Windows. Sie meldet diesen Browser an, behandle sie also wie ein Passwort.

    aubergine open --print

    Danach funktioniert http://127.0.0.1:4600 in diesem Browser von allein. Auf einem leeren Canvas startet Show me around die Tour.

Gut zu wissen

  • Leg deine Projekte in Ubuntu ab, in seinem Home-Ordner, nicht unter /mnt/c, wo die Dateien von Windows über eine langsamere Brücke erreicht werden.
  • Installiere deine Agenten in Ubuntu, Claude Code, Codex oder einen anderen, wie auf jedem Linux. Ein unter Windows installierter Agent ist in den Terminals von Aubergine nicht da.
  • Terminals leben, solange WSL läuft. Den Browser zu schließen beendet nichts, und Ctrl+C im Fenster von aubergine start hält nur den Server an. Wenn WSL anhält, weil Windows neu startet oder nach wsl --shutdown, enden die Terminals, und das nächste aubergine start öffnet frische Shells in ihren letzten Ordnern, wie nach einem Neustart auf einem Mac.
  • bash oder zsh. Ubuntus Shell ist bash, und Terminals funktionieren darin. Der Befehlsstatus eines Terminals (beschäftigt, der Exit-Code eines fehlgeschlagenen Befehls) kommt nur von zsh: Im Versuch zeigte ein zsh-Terminal nach einem fehlgeschlagenen Befehl exit 3. Mach zsh zu deiner Shell in Ubuntu, um ihn zu bekommen.
  • Was es dort nicht gibt: Start bei der Anmeldung funktioniert nur unter macOS (aubergine service install sagt das), und Open on desktop hat keine Einstellung für eine Terminal-App unter Windows. aubergine open fand im Versuch keinen Browser zum Öffnen; aubergine open --print funktioniert immer.
  • Tastenkürzel unter Windows wurden nach der Dokumentation der Browser gewählt und nicht gemessen: siehe docs/keys.md. Die Palette funktioniert immer.

Wenn etwas schiefgeht

Führe zuerst aubergine doctor in Ubuntu aus. Es prüft Node.js, tmux, Git und den Server.
