Mehrere Coding-Agenten gleichzeitig laufen lassen

Zwei Agenten sind einfach. Fünf sind Chaos: Welcher hängt, welcher wartet auf dich, welcher hat diese Datei geändert? Für genau diesen Moment ist Aubergine gebaut. Es läuft auf deinem eigenen Rechner.

1. Gib jedem Agenten ein Terminal auf einem Canvas

Klick auf New terminal (neues Terminal) oben in der Liste der Terminals (oder drück N) und starte darin einen Agenten. Zieh Terminals an ihrer Titelleiste, ändere ihre Größe und gruppiere sie in Rahmen. Zusammengehörige Arbeit kommt auf ein Canvas; getrennte Arbeiten kommen auf getrennte Canvases (Tabs) oder in Projekte, jedes mit eigenen Terminals, eigener Warteschlange und eigenen Zeitplänen.

Jedes Terminal ist eine echte Shell in einer tmux-Session. Schließ den Browser oder stoppe Aubergine, und deine Agenten laufen weiter.

2. Sieh, welcher Agent dich braucht

Jedes Terminal zeigt, ob es beschäftigt, untätig oder wartend auf dich ist. Dieser Status kommt aus Hooks in deiner Shell und von den Agenten selbst, nicht aus dem Lesen des Bildschirms. Die Zahl neben For you oben und die Taste W bringen dich direkt zum nächsten wartenden.

Eine Liste, For you (für dich), sammelt alles, was auf einen Menschen wartet: Fragen, freizugebende Läufe, fertige Aufgaben zum Ansehen und fehlgeschlagene mit dem Grund.

3. Verteile Arbeit aus einer Warteschlange

Schreib eine Aufgabe einmal und stell sie in die Warteschlange. Ein freier Agent übernimmt sie, wenn du es sagst, mit einer Grenze, wie viele gleichzeitig laufen. Für Arbeit, die sich wiederholt, leg einen Zeitplan an. Agenten können Aufgaben vorschlagen und dir Fragen stellen, aber nichts startet, bevor du zustimmst.

4. Halte die Änderungen jedes Agenten getrennt

Zwei Agenten in einem Ordner bearbeiten dieselben Dateien. Starte jeden in einer eigenen Arbeitskopie: einem separaten Checkout auf einem eigenen Branch, damit du die Arbeit jedes Agenten getrennt lesen kannst. Aubergine merget, pusht und rebased nie für dich.

5. Gib Agenten Schritte vor und entscheide an den Toren

Ein Workflow ist eine geordnete Liste von Schritten, denen ein Agent folgt, mit einem Streifen, der zeigt, wo er steht. Ein Schritt kann darauf warten, dass du ihn freigibst oder zurückschickst. Jeder aktive Lauf erscheint auf einem Board.

Was es nicht tut

  • Es ruft kein Modell auf und wählt keins für dich aus. Die Agenten sind deine.
  • Es hält einen Agenten nicht davon ab, etwas zu tun, was du tun könntest. Agenten laufen als du. Unter Sicherheit steht, was geschützt ist und was nicht.
  • Es läuft heute auf einem Rechner. Ein Canvas mit anderen Menschen teilen und Agenten in der Cloud laufen lassen stehen auf der Roadmap und sind nicht gebaut.
