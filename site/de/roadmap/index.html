Roadmap

Nichts davon gibt es heute. Es ist, wo wir hinwollen, und die Reihenfolge kann sich ändern. Was jetzt gebaut ist, steht in den Anleitungen.

Teams und Verbindungen

Menschen, die zusammenarbeiten, und Agenten, die du aus den Tools erreichst, die du schon nutzt.

  • Mehrspieler

    Teile ein Canvas mit anderen Menschen und ihren Agenten. Sieh, wer wo arbeitet, gib einen wartenden Agenten an jemanden aus dem Team weiter und antwortet gemeinsam.

  • Chat-Oberfläche

    Sprich Agenten an und beantworte ihre Fragen aus einer Team-Chat-App, mit derselben Identität und denselben Einstellungen wie im Browser.

  • Tickets und Pull Requests

    Mach aus einem Issue eine Aufgabe in der Warteschlange, öffne einen Pull Request aus einer Arbeitskopie und melde das Ergebnis an das Ticket zurück.

  • Beobachtungen, Webhooks und Triage

    Starte Arbeit, wenn etwas passiert: ein fehlgeschlagener CI-Job, ein Alarm, eine beobachtete Änderung oder ein Aufruf aus einem anderen Dienst. Regeln entscheiden, was eine Aufgabe wird.

  • Geteilte Skills und ein Marktplatz

    Teile die Skills eines Agenten per Freigabe, hebe sie mit Zustimmung aufs ganze Team, importiere sie aus Git und finde geprüfte Einträge in einem öffentlichen Katalog.

  • Gedächtnis für Menschen und Räume

    Behalte, was ein Agent gelernt hat, für jeden Menschen und jeden geteilten Raum, getrennt von den anderen.

Außerdem: Admin-Einstellungen für Modelle, Teilen und Strenge · ein selbst gehosteter Team-Server · Anmeldung für Teams (SSO und MFA) · Nutzungsgrenzen pro Person, Token oder Agent · schreibgeschützte Berichte zum Teilen, ohne Terminals zu teilen · eine Handy-Ansicht der Liste „For you“ · geprüfte Konnektoren zu Firmen-Tools · mehr Chat-Apps · kleine interne Web-Apps, veröffentlicht für ausgewählte Menschen.

Cloud

Agenten, die deinen Laptop nicht wach brauchen.

  • Agenten in Sandboxes in der Cloud

    Lass einen Agenten in einer isolierten Cloud-Sandbox laufen und verfolge ihn auf demselben Canvas wie deine lokalen. Sandboxes schlafen, wenn sie untätig sind, wachen bei Bedarf auf und behalten ihren Speicher zwischen Läufen.

  • Ein Pool von Agenten

    Beschreib die Arbeit und lass einen Pool von Agenten sie aufgreifen, statt für jede Aufgabe ein Terminal zu benennen.

  • Fertige Umgebungen

    Speichere Abhängigkeiten, Tools, Skills, Dateien und Variablen einmal und starte jedes neue Terminal oder jeden Cloud-Agenten daraus.

  • Lange, mehrphasige Arbeit

    Aufgaben, die Stunden oder Tage in Etappen laufen, mit einem Check-in nach jeder Etappe und Fortschritt, der Neustarts übersteht.

  • Cloud-Deployment mit einem Befehl

    Bring das geteilte Aubergine eines Teams mit einem Befehl auf dein eigenes Cloud-Konto.

  • Arbeit, die du sehen kannst

    Ein Cloud-Agent gibt Screenshots oder eine kurze Aufnahme dessen zurück, was er gebaut hat, in deiner Liste „For you“.

Außerdem: MCP über HTTP für Agenten auf anderen Rechnern · getestete Linux-Unterstützung · Shell-Integration über zsh hinaus.

Kontrolle

Wie viel ein Agent darf, und ein Protokoll dessen, was er getan hat.

  • Freigabemodi

    Wähle, wie viel ein Agent allein tun darf: jede Aktion freigeben, die riskanten freigeben oder keine.

  • Befehlsrichtlinien und Prüfung

    Regeln für Befehle, die eine Freigabe brauchen oder immer abgelehnt werden, und eine optionale Prüfung von Inhalten von außen, bevor ein Agent sie liest.

  • Risikostufen pro Repository

    Strengere Grenzen, wo es darauf ankommt, lockerere, wo nicht.

  • Ein vollständiges Audit-Protokoll

    Ein Protokoll, wer oder was was getan hat, pro Projekt, über die heute erfassten Token-Aufrufe hinaus.

  • Die Arbeit eines Agenten rückgängig machen

    Eine Arbeitskopie auf den Stand vor einer Aufgabe zurücksetzen oder ihren Branch in einem Schritt verwerfen.

  • Admin-Einstellungen

    Teamweite Einstellungen, welche Modelle genutzt werden dürfen und wie Teilen funktioniert.

Außerdem: Modellwahl pro Terminal, Aufgabe oder Zeitplan.

Qualität

Prüfungen, bevor Arbeit als erledigt gilt.

  • Qualitätstore

    Ein Lauf kann erst enden, wenn Review, Tests oder eine Sicherheitsprüfung ein Bestanden melden.

  • Review von Pull Requests

    Ein Agent prüft einen Pull Request und meldet sich in deiner Liste „For you“.

  • Browsergesteuertes Testen

    Ein Agent steuert einen Browser, um eine Änderung zu testen, und gibt die Ergebnisse zurück.

  • Erst planen, dann bauen

    Ein Agent schlägt einen Plan vor und wartet auf deine Freigabe, bevor er Dateien anfasst.

  • Aufgabenrezepte

    Fertige Workflows für Testgenerierung, Review, Scans von Abhängigkeiten und Geheimnissen und aktuelle Dokumentation.

  • Ergebniskennzahlen

    Zeit von der Aufgabe bis zum Abschluss, wie oft ein Agent auf dich gewartet hat, und Nutzung danach, wer gestartet hat, pro Projekt.

Außerdem: Vorfallberichte, bei denen ein Agent nachforscht und ein Postmortem entwirft.

Überall

Mehr Wege, Aubergine zu erreichen und darauf aufzubauen.

  • Veröffentlichtes SDK

    Der typisierte Client als installierbares Paket, danach Clients für andere Sprachen wie Python.

  • Editor-Erweiterung

    Zeig deine Terminals und deine Liste „For you“ in VS Code und ähnlichen Editoren, ohne den Editor zu verlassen.

  • Desktop-App

    Eine gepackte App mit einem Symbol in der Menüleiste statt eines Browser-Tabs.

  • Windows-Unterstützung

    Aubergine auf Windows selbst laufen lassen. Heute läuft es nur in WSL 2, wie die Anleitung für Windows beschreibt, und unter Windows hat das noch niemand ausprobiert.

Nach Ihrem Geschmack

Mehr von der Seite nach Ihren Vorstellungen, über die heutigen Themen, Farben und Tasten hinaus.

  • Eigene Themendateien

    Ein Farbthema als Datei schreiben und neben den zehn wählen, die mit Aubergine kommen. Ein Agent kann eines vorschlagen, und es wartet, bis Sie es annehmen.

  • Aussehen nach Bedingung

    Ein Thema oder eine Akzentfarbe für ein Projekt oder für die Terminals mit einem Tag, damit Sie auf einen Blick sehen, wo Sie sind.

  • Vorlagen

    Bestimmen, was der Titel eines Terminals und eine Zeile der Liste zeigen, aus einer eigenen Vorlage.

  • Ein eigenes Stylesheet

    Eine Datei custom.css, in die Seite geladen, mit dokumentierten Ansatzpunkten, die stabil bleiben.

  • Plugins

    Eigener Code in der Seite, mit voller Kontrolle, über benannte Stellen und darüber hinaus. Ein abgeschotteter Modus für Code anderer Leute kann später kommen.

Geplante Arbeit ist eine Richtung, kein Versprechen. Das Repository zeigt, was ausgeliefert ist.

In fünf Minuten startklar

Du brauchst macOS mit tmux 3.2 oder neuer und Node.js 22 oder neuer. brew install tmux node holt beides.

npm install -g @meatgarden/aubergine
