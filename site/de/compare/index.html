Tools für mehrere Coding-Agenten gleichzeitig im Vergleich

Sieben Tools für dieselbe Lage: mehr als ein Coding-Agent bei der Arbeit, und du mittendrin. Hier steht Aubergine neben Conductor, Claude Squad, Vibe Kanban, cmux, Warp und Paradev, mit einer Seite für jedes.

Wie das geschrieben wurde. Was diese Seiten über ein anderes Tool sagen, stammt von dessen eigener Website, Dokumentation und Repository, gelesen am 26. November 2026, und jede Seite verlinkt dorthin. Wir haben die anderen Tools nicht ausgeführt. Wo ihre Dokumentation nichts sagt, sagt die Seite, dass nichts gefunden wurde, nicht, dass das Tool es nicht kann. Diese Tools ändern sich schnell: Wenn hier etwas falsch oder veraltet ist, sag es uns, und es wird korrigiert.

Eine Seite für jedes

Jede Seite hat die ganze Tabelle für die beiden, wo sie sich unterscheiden und was das andere Tool hat, das Aubergine nicht hat.

  • Aubergine vs. Conductor

    Wähl Conductor, wenn du eine Mac-App willst, die eine Aufgabe vom Prompt bis zum gemergten Pull Request bringt, mit einer Cloud für Arbeit, die weiterläuft, während dein Mac aus ist.

  • Aubergine vs. Claude Squad

    Wähl Claude Squad, wenn du im Terminal lebst und dort ein kleines Programm willst, das Agenten in Worktrees startet und ihre Branches pusht, und nichts weiter.

  • Aubergine vs. Vibe Kanban

    Wähl Vibe Kanban, wenn du in Issues denkst: auf einem Board planen, jede Karte einem Agenten übergeben, seinen Diff mit Kommentaren prüfen und mergen.

  • Aubergine vs. cmux

    Wähl cmux, wenn du eine schnelle, native Terminal-App für den Mac willst, mit Bereichen, einem Browser in der App und macOS-Benachrichtigungen, und deine eigene Arbeitsweise darauf skriptest.

  • Aubergine vs. Warp

    Wähl Warp, wenn du eine Terminal-App für alles willst, auch unter Windows und Linux, mit eingebautem eigenem Agenten und Cloud-Agenten, die du planen kannst.

  • Aubergine vs. Paradev, früher Superset

    Wähl Paradev, wenn du eine Desktop-App willst, die für jede Aufgabe einen Worktree anlegt und sie durch Diff, Checks und Merge bringt, mit Handy-Apps und einer Cloud, wenn du dafür bezahlst.

Worum Aubergine gebaut ist

  • Gewöhnliche Terminals. Ein Agent läuft in Aubergine so, wie er in jeder Terminal-App läuft. Es gibt keine Chat-Ansicht darüber und nichts zwischen dir und dem, was er ausgibt.
  • Alle im Blick. Terminals stehen nebeneinander auf einem Canvas, das du verschiebst und zoomst, mit einer Liste aller Terminals und ihrem Zustand in Worten. Siehe Das richtige Terminal finden.
  • Das Fenster zu schließen beendet nichts. Jedes Terminal ist eine tmux-Session, also können der Browser und Aubergine selbst anhalten, während deine Agenten weiterlaufen. Siehe was ein Neustart behält.
  • Nur dein Rechner. Kein Konto, keine Cloud, kein bezahlter Plan und kein eigenes Modell; der Server lauscht auf 127.0.0.1. Siehe Sicherheit.
  • Ein Mensch entscheidet. Was ein Agent vorschlägt, wartet auf deine Prüfung, eine Freigabe in einem Workflow ist allein deine, und eine Liste, For you, enthält alles, was auf dich wartet. Siehe die Warteschlange.

Was Aubergine nicht hat

  • Keine Desktop-App und keine Handy-App. Es ist eine Seite in deinem Browser. Ein anderes Gerät lässt sich über einen Proxy koppeln, den du selbst betreibst; das wurde einmal auf einem Mac ausgeführt und nie auf einem echten Handy.
  • Keine Pull Requests und kein Mergen. Es zeigt, was sich in einer Arbeitskopie geändert hat, Datei für Datei, und committet, pusht, rebased oder merget nie.
  • Keine Cloud. Agenten laufen auf dem Rechner, auf dem Aubergine läuft, und Zeitpläne lösen nur aus, solange er an ist.
  • Kein Ton und kein Push. Benachrichtigungen kommen von einer Aubergine-Seite, die in deinem Browser offen ist.
  • Für macOS gebaut. Unter Linux lief es bisher nur in Containern; unter Windows läuft es nur in WSL 2, was noch nicht ausprobiert wurde.
  • Am meisten für Claude Code. Jeder Kommandozeilen-Agent läuft in einem Terminal, aber was Aubergine von sich aus für einen Agenten tut (sehen, dass er wartet, eine Unterhaltung fortsetzen), ist für Claude Code gebaut; ein anderer Agent meldet sich über die aubergine-Befehle.

Fragen

Was ist das beste Tool, um mehrere Claude-Code-Agenten gleichzeitig laufen zu lassen?

Das hängt davon ab, was du um die Agenten herum willst. Für eine Mac-App mit Diffs, Pull Requests und Mergen: Conductor oder Paradev. Für ein Programm in dem Terminal, das du schon nutzt: Claude Squad. Für ein Board mit Issues: Vibe Kanban. Für ein natives Mac-Terminal: cmux. Für ein Terminal mit eigenem Agenten und Cloud-Agenten: Warp. Für einfache Terminals nebeneinander auf einer Browserseite, am Laufen gehalten von tmux, ohne Konto: Aubergine.

Welche dieser Tools sind Open Source?

Stand 26. November 2026: Aubergine (MIT), Paradev (MIT), Vibe Kanban (Apache-2.0), Claude Squad (AGPL-3.0), die cmux-App (GPL-3.0-or-later) und der Warp-Client (AGPL-3.0). Die Bedingungen von Conductor nennen es proprietär.

Welche dieser Tools laufen unter Linux oder Windows?

Laut ihrer eigenen Dokumentation: Warp unter macOS, Windows und Linux; Vibe Kanban auf allen dreien; Claude Squad unter macOS und Linux und unter Windows mit tmux über WSL; Paradev unter macOS mit einem experimentellen Linux-Build; Conductor und cmux nur unter macOS. Aubergine ist für macOS gebaut, lief unter Linux bisher nur in Containern und läuft unter Windows nur in WSL 2, noch nicht ausprobiert.

Welche lassen Agenten weiterlaufen, wenn du die App schließt?

Aubergine und Claude Squad lassen jeden Agenten in einer tmux-Session laufen. Paradev dokumentiert einen Daemon im Hintergrund, der Terminals behält, wenn sein Fenster geschlossen wird. cmux behält laufende Prozesse nur in seinem tmux-Modus, den man eigens einschaltet. Conductor sagt, dass lokale Sessions mit der App enden. Warp stellt Fenster und jüngste Ausgabe wieder her, keine laufenden Programme. Conductor, cmux, Warp und Paradev haben außerdem jeweils eine Cloud, in der Agenten weiterlaufen. Keines, Aubergine eingeschlossen, lässt einen lokalen Agenten über einen Neustart des Rechners hinweg laufen.

Du brauchst macOS mit tmux 3.2 oder neuer und Node.js 22 oder neuer. brew install tmux node holt beides.
