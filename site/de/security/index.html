Sicherheit und Datenschutz

Was Aubergine tut, um deine Terminals zu schützen, und, genauso wichtig, was nicht. Kurz gesagt: Es ist lokal, es fragt, bevor es für einen Agenten handelt, und Agenten laufen trotzdem als du.

Alles bleibt auf deinem Rechner

  • Der Server bindet nur an 127.0.0.1. Bei jeder Anfrage und jedem WebSocket-Upgrade werden Host und Origin geprüft, und der Browser muss ein Zugangs-Cookie haben.
  • Die Nutzung von Aubergine von einem anderen Gerät ist aus, bis du sie einrichtest: Etwas auf demselben Rechner leitet HTTPS unter einem Namen dorthin, den du in die Einstellungen schreibst, und jeder Browser wird mit einem Einmalcode gekoppelt und kann widerrufen werden. Ein gekoppeltes Gerät kann alles, was der Besitzer kann. Aubergine von anderswo nutzen erklärt, wie.
  • Aubergine ruft kein Modell auf und startet von sich aus keine Netzwerkanfrage, mit zwei Ausnahmen: eine Bibliotheksquelle (eine Git-Adresse) holen, wenn du danach fragst, und dein eigenes gh-Tool, wo es installiert und angemeldet ist, nach dem Pull Request zum Branch eines Terminals fragen.
  • Desktop-Benachrichtigungen kommen von der offenen Seite. Nichts verlässt deinen Rechner.

Drei Arten von Aufrufern, jede für sich beurteilt

Jede Anfrage wird mit dem abgeglichen, was der Aufrufer darf, bevor irgendetwas nachgeschlagen wird, sodass ein Aufrufer ohne das Recht aus der Antwort nichts erfährt. Die Aufrufer sind du (im Browser angemeldet), die Session eines Agenten und ein API-Token.

  • API-Tokens haben Scopes. Das Geheimnis wird einmal gezeigt und nie gespeichert; nur ein Hash wird aufbewahrt. Aufrufe mit einem Token landen in einem Aktivitätsprotokoll: wer, was und wie es ausging, nie das Geheimnis und nie, was gesendet wurde.
  • Manches kann kein Token je tun: Tokens erstellen oder widerrufen, das Aktivitätsprotokoll lesen, Einstellungen ändern und alles, was Terminals außerhalb von Aubergine betrifft.
  • Terminal-Zugriff besteht aus zwei getrennten Scopes, einem zum Lesen und einem zum Tippen, jeder auf die Sessions beschränkt, die du wählst. Du kannst ein Terminal als people only (nur Menschen) markieren, um es für jedes Token zu sperren.
  • Der eigene Zugang eines Agenten ist eng. Er kann seine eigene Aufmerksamkeit setzen, seine eigenen Notizen ergänzen, seinen eigenen Status melden und den Lauf lesen, an dem er hängt. Andere Terminals, Canvases oder Tokens erreicht er nicht.

Was ein Agent nicht allein tun kann

  • Was ein Agent oder Programm schreibt (einen Workflow, einen Schritt), kommt als Entwurf an, den du prüfst. Annehmen kannst nur du.
  • Ein Schritt, der auf einen Menschen wartet, kann nur von einem Menschen freigegeben oder zurückgeschickt werden. Regeln, Zeitpläne und die Demo gehören dir allein.
  • Aubergine tippt nur ein paar feste Sätze in das Terminal eines Agenten, etwa „read your next step“. Nichts, was du gespeichert hast, und nichts, was ein Agent geschrieben hat, wird getippt.
  • Eine Installation aus einer Bibliothek setzt voraus, dass du genau den Inhalt annimmst, der dir gezeigt wurde.

Wovor das nicht schützt

Agenten laufen als du. Ein Agent in einem Terminal kann alles tun, was du in diesem Terminal tun kannst, auch Befehle ausführen, Dateien lesen und, wenn er will, deine eigene Browser-Session nutzen.

  • Freigaben sind kein Schloss. Ein Agent, der als du läuft, kann als du entscheiden. Die Entscheidung wird festgehalten, nicht verhindert.
  • Arbeitskopien sind keine Sandbox. Sie halten Arbeit getrennt und sperren keinen Agenten ein.
  • Der Prüfbildschirm ist die Kontrolle für Bibliothekseinträge. Ein Eintrag besteht aus Anweisungen, denen ein Agent mit allem folgt, was dieser Agent darf. Installiere nichts, was du nicht gelesen hast.
  • Die Anleitung für Agenten ist ein Rat, kein Schloss.

Der Installer

Er ändert zwei Dinge: seinen eigenen Ordner und einen Link namens aubergine. Kein sudo, keine Änderungen an den Startdateien deiner Shell, und deinen Datenordner rührt er nie an. aubergine uninstall entfernt nur, was er angelegt hat.

Ein Problem melden

Eröffne ein Issue auf GitHub. Schreib keine Geheimnisse oder Tokens hinein.

In fünf Minuten startklar

Du brauchst macOS mit tmux 3.2 oder neuer und Node.js 22 oder neuer. brew install tmux node holt beides.

npm install -g @meatgarden/aubergine
