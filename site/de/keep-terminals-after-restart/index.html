Deine Terminals bleiben, wenn der Rechner neu startet

Den Browser zu schließen oder Aubergine neu zu starten verliert nichts: Jedes Terminal läuft weiter. Ein Neustart des Rechners beendet, was lief, und Aubergine holt alles drumherum zurück, damit du dort weitermachst, wo du warst, statt von vorn zu beginnen.

Was passiert, wenn…

Jedes Terminal ist eine Shell in einer tmux-Session, die getrennt vom Browser und vom Server von Aubergine läuft. Was es enthält, liegt an zwei Orten: die laufende Shell, die nur tmux hält, und alles, was über das Terminal gesagt ist, das Aubergine bei jeder Änderung in eine Datei in seinem Datenordner schreibt.

Ein geparktes Terminal wird genauso behalten und bekommt auch eine frische Shell. Ein Terminal, dessen Shell schon vorher geendet hatte, bleibt beendet, mit Restart here (hier neu starten).

Nach einem Update behält ein Terminal, das schon offen war, das, womit seine Shell gestartet ist (seinen PATH und die Shell-Integration von Aubergine), bis diese Shell neu gestartet wird. Startet Aubergine beim Anmelden, führ nach einem Update aubergine service install noch einmal aus, statt den Server von Hand neu zu starten.

Nach einem Neustart: zurück an die Arbeit

  1. Starte Aubergine. Startet es beim Anmelden (aubergine service install, nur macOS), läuft es, sobald du angemeldet bist, und launchd startet es wieder, wenn es anhält. Sonst starte es und öffne die Seite:

    aubergine start --open

  2. Der Canvas ist, wie du ihn verlassen hast. Jedes Terminal steht an seinem Platz mit Name, Farbe, Tags, Feldern, Links und Notiz, jetzt eine frische Shell im letzten Ordner, in dem Aubergine es gesehen hat, oder in deinem Standardordner, wenn es den nicht mehr gibt. Nichts wird erneut getippt oder ausgeführt.

  3. Setz deine Agenten fort. Wo Claude Code lief und Aubergine seine Unterhaltung kennt (es wurde aus Aubergine gestartet), bietet die Titelleiste des Terminals Resume agent (Agent fortsetzen) an: Es startet Claude Code in dieser Unterhaltung wieder. Bei einem Terminal, das an einem Lauf eines Workflows hängt, erzählt es dem Agenten auch noch einmal vom Lauf, damit er bei dem Schritt weitermacht, an dem der Lauf steht.

  4. Sieh nach, wo jedes stand. Details im Titel eines Terminals zeigt, was über es bekannt ist (den Schritt eines Laufs und seinen letzten Bericht, den Ordner, die Tags), seine Zusammenfassung, seine Felder und Links und sein Log unter Log. Zeigst du in der Liste auf den Namen eines Terminals, erscheint seine Zusammenfassung des Stands.

  5. Finde eine Unterhaltung, die nicht auf dem Canvas ist. Past conversations… (frühere Unterhaltungen) in der Palette (⌘K) oder „Past conversations in this folder…“ in den Details eines Terminals listet die früheren Unterhaltungen von Claude Code in einem Ordner und öffnet eine auf dem Canvas.

Jeder andere Agent hat kein Resume agent, weil Aubergine seine Unterhaltung nicht kennt: Starte ihn im selben Terminal mit der eigenen Fortsetzen-Funktion dieses Agenten wieder und lies die Notiz, um ihm zu sagen, wo er stand.

Was verloren geht, und was du tun kannst

  • Was lief, endet. Ein Build, ein Testlauf, ein Server oder ein Agent mitten in der Arbeit hält mit dem Rechner an, und Aubergine startet keins davon von selbst wieder. Starte sie selbst neu; ein Job, der einen Neustart überdauern muss, gehört in etwas, das dafür gemacht ist, etwa einen Dienst deines Systems.
  • Arbeit, die Aubergine verfolgt, wartet auf dich. Ein Lauf eines Workflows behält seinen Schritt und jeden abgegebenen Bericht. Aufgaben in der Warteschlange behalten ihren Platz; eine, die gerade gestartet wurde, als der Server anhielt, wird mit einem Satz als fehlgeschlagen markiert, und nichts wird von selbst erneut versucht. Eine Zeit eines Zeitplans, die verstrich, während der Server stand, läuft einmal, verspätet, wenn sie weniger als sechs Stunden zurückliegt (schedules.lateWithinHours), und wird sonst als verpasst markiert.
  • Der Scrollback ist weg. Solange eine Shell läuft, hält tmux die letzten 50.000 Zeilen, die sie ausgegeben hat, und die Suche der Palette liest sie. Aubergine zeichnet nicht auf, was ein Terminal ausgibt, also gibt es nach einem Neustart des Rechners nichts zurückzuholen, und die Suche findet nur, was seitdem ausgegeben wurde.
  • „Während du weg warst“ fängt neu an. Es liegt im Speicher des Servers, nicht in einer Datei, also weiß es nach dem Start des Servers nur, was sich seitdem geändert hat, und sagt das.

Die Gewohnheit, die einen Neustart billig macht

Die Notiz ist, was überlebt, also lass Agenten unterwegs hineinschreiben: eine Entscheidung, ein Ergebnis, wo sie aufgehört haben. Bei einem aus Aubergine gestarteten Claude Code kommt jeder Prompt, den du schickst, von selbst ins Log, und er wird zu Beginn gebeten, sein Terminal zu benennen und seine Zusammenfassung zu pflegen. Jeder Agent kann dasselbe mit diesen Befehlen tun, die aubergine guide ihm erklärt:

aubergine note "Tests pass on the branch. The migration is not written yet."
aubergine describe --summary "Fixing the double redirect at sign-in"

Bevor du für heute aufhörst, drück Ask its agent for a recap (den Agenten um eine Zusammenfassung bitten) in den Details eines Terminals: Der Agent schreibt mit aubergine recap --write, wo er steht, und die Zusammenfassung bleibt beim Terminal.

Laptop zuklappen, Ruhezustand und der Browser

  • Ruhezustand ist kein Neustart. Den Deckel eines Laptops zuzuklappen schickt ihn meist in den Ruhezustand: Programme pausieren und laufen weiter, wenn er aufwacht, und nichts aus der letzten Spalte der Tabelle passiert. Aubergine hält den Rechner weder wach noch weckt es ihn, also läuft ein Zeitplan, dessen Zeit im Ruhezustand verstrich, verspätet oder wird verpasst, wie oben.
  • Den Browser, einen Tab oder sein Fenster zu schließen, oder ein Browser-Update, das ihn neu startet, beendet nichts. Öffne die Seite wieder (aubergine open öffnet sie angemeldet), und jedes Terminal wird aus tmux so gezeichnet, wie es jetzt ist. Eine offen gelassene Seite verbindet sich von selbst neu, wenn der Server zurück ist.
  • Das Fenster zu schließen, in dem aubergine start läuft, oder dort Ctrl+C zu drücken, hält den Server an und sonst nichts: die mittlere Spalte der Tabelle.
  • Unter Windows mit WSL ist ein Anhalten von WSL, weil Windows neu startet oder nach wsl --shutdown, für Aubergine ein Neustart des Rechners. Siehe Windows mit WSL.

Fragen

Kann Aubergine meine Terminals nach einem Neustart wiederherstellen?

Ja, alles außer dem, was in ihnen lief. Jedes Terminal kommt an seinen Platz auf dem Canvas zurück, mit Name, Farbe, Notiz, Tags, Feldern und Links, als frische Shell in seinem letzten Ordner. Die Programme, die darin liefen, werden nicht wieder gestartet; für Claude Code setzt Resume agent die Unterhaltung fort.

Behält Aubergine die Ausgabe und den Verlauf meines Terminals?

Die Ausgabe nur, solange die Shell läuft: tmux hält 50.000 Zeilen Scrollback je Terminal, und den Browser zu schließen oder Aubergine neu zu starten verliert nichts davon. Nach einem Neustart des Rechners ist sie weg, weil Aubergine keine Terminal-Ausgabe aufzeichnet. Der Verlauf der Befehle, die du getippt hast und die der Pfeil nach oben zurückholt, ist die eigene Datei deiner Shell und wird von deiner Shell wie immer behalten.

Überlebt meine Claude-Code-Unterhaltung einen Neustart?

Die Unterhaltung, ja: Claude Code behält sie in seinen eigenen Dateien, und Aubergine merkt sich, in welcher jedes Terminal war. Nach dem Neustart startet Resume agent in der Titelleiste des Terminals Claude Code in dieser Unterhaltung wieder. Was der Agent in dem Moment tat, hat aufgehört und wird erst wieder getan, wenn du darum bittest.

Funktioniert es, wenn sich macOS nachts selbst aktualisiert?

Ein Update, das den Rechner neu startet, ist ein Neustart wie jeder andere: Laufende Programme enden, alles andere bleibt. Mit dem Start beim Anmelden (aubergine service install) läuft der Server wieder, sobald du dich anmeldest, und der Canvas wartet. Frische Shells in ihren letzten Ordnern wurden beim Neustart eines Containers von Aubergine gesehen; ein echtes nächtliches macOS-Update wurde nicht ausprobiert.

Muss ich tmux können?

Nein. Es muss installiert sein (3.2 oder neuer), und Aubergine betreibt es auf einem eigenen Socket mit eigenen Einstellungen, ohne Statusleiste und ohne Präfix-Taste, sodass du nie einen tmux-Befehl tippst. Dein eigenes tmux, falls du eins benutzt, wird nicht angefasst.
