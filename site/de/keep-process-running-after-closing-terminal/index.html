Einen Prozess weiterlaufen lassen, wenn du das Terminal schließt

Du hast einen Build, einen Server oder einen Coding-Agenten gestartet, und das Fenster zu schließen würde ihn beenden. In Aubergine beendet das Schließen des Fensters nichts: Jedes Terminal läuft getrennt vom Browser, und was es ausgegeben hat, ist da, wenn du zurückkommst.

Was man üblicherweise tut

Ein Terminalfenster zu schließen beendet die Shell darin und mit ihr, was diese Shell gestartet hat. Die üblichen Wege drumherum:

  • nohup startet einen Befehl, der das Hang-up-Signal ignoriert, das beim Schließen des Terminals kommt. Seine Ausgabe geht in eine Datei (nohup.out, wenn du sie nicht woandershin schickst).
  • disown lässt in bash und zsh einen schon gestarteten Job los, sodass die Shell das Hang-up-Signal nicht an ihn weitergibt. Danach kommst du in keinem Terminal mehr an ihn heran.
  • screen und tmux lassen die Shell in einem eigenen Server laufen. Du trennst dich ab, schließt das Fenster und hängst dich später wieder an dieselbe Shell mit ihrer Ausgabe. Sie sind die verlässliche Antwort, und um sie zu nutzen, lernst du ihre Tasten und Befehle.

Aubergine baut auf dem letzten davon auf. Es betreibt tmux für dich, sodass du seine Antwort ohne seine Tasten bekommst.

Was Aubergine tut

Jedes Terminal in Aubergine ist eine Shell in einer eigenen tmux-Session, auf einem tmux-Socket von Aubergine. tmux läuft getrennt vom Browser und vom Server von Aubergine, also:

  • Den Tab, das Fenster oder den ganzen Browser zu schließen beendet nichts. Öffne die Seite wieder (aubergine open öffnet sie angemeldet), und jedes Terminal wird aus tmux so gezeichnet, wie es jetzt ist, mit dem, was es inzwischen ausgegeben hat, in seinem Scrollback.
  • Aubergine anzuhalten beendet auch nichts. Ctrl+C dort, wo aubergine start läuft, ein Absturz des Servers oder ein Update hält den Server an und sonst nichts. Starte ihn wieder und lade die Seite neu.
  • Ein Terminal auf dem Canvas zu schließen parkt es. Das × in seinem Titel nimmt es vom Canvas, und seine Shell läuft weiter. Parked (geparkt) in der Leiste über dem Canvas listet geparkte Terminals, und Restore (wiederherstellen) holt eins zurück.
  • Eine Shell endgültig zu beenden fragt vorher. End (beenden) in der Liste der geparkten Terminals beendet ein Terminal erst, wenn du Ja sagst.
  • Andere Ansichten davon beenden nichts. Tab ↗ im Titel eines Terminals öffnet es allein in einem Browser-Tab, und aubergine attach <name> zeigt es in einem Fenster deiner Terminal-App. Es ist jedes Mal dasselbe Terminal, keine Kopie; diesen Tab oder dieses Fenster zu schließen lässt es weiterlaufen.

Solange eine Shell läuft, hält tmux die letzten 50.000 Zeilen, die sie ausgegeben hat. Das Mausrad scrollt im Terminal, das die Tastatur hat, durch sie zurück, und die Palette (⌘K) durchsucht sie.

Was es nicht tut

  • Es überlebt keinen Neustart des Rechners. Ein Neustart, ein Absturz des Rechners oder ein Update, das ihn neu startet, beendet jede Shell und was in ihr läuft. Aubergine holt alles drumherum zurück, jedes Terminal als frische Shell in seinem letzten Ordner, und startet von selbst nichts wieder. Siehe Terminals nach einem Neustart behalten.
  • Es hält den Rechner nicht wach. Ein Laptop im Ruhezustand pausiert seine Programme, diese auch; sie laufen weiter, wenn er aufwacht.
  • Es ist kein Dienstverwalter. Ein Job, der nach einem Neustart von selbst wiederkommen muss, gehört zu den Diensten deines Systems.
  • Es kann kein Programm übernehmen, das schon woanders läuft. Kein Werkzeug kann ein laufendes Programm in ein anderes Terminal verschieben. aubergine here in einem Tab deiner Terminal-App gibt diesem Ordner ein Terminal auf dem Canvas; ein Programm, das im Tab läuft, bleibt dort und muss im neuen Terminal neu gestartet werden.

Auf einer anderen Maschine, über SSH

Aubergine läuft auf deinem eigenen Rechner: Sein Server lauscht auf 127.0.0.1, und seine Terminals sind Shells auf diesem Rechner. Wenn du einen Prozess auf einem entfernten Server behalten willst, den du per SSH erreichst, ist tmux oder screen auf diesem Server weiterhin die Antwort.

Aubergine selbst kann auf einer anderen Maschine laufen und aus deinem Browser benutzt werden, über einen SSH-Tunnel, ein privates Netz oder einen Namen und einen Proxy: Die Schritte stehen in Using Aubergine from elsewhere. Über einen SSH-Tunnel hält das Schließen des SSH-Fensters, in dem aubergine start läuft, den Server an, und die Terminals laufen weiter. Linux wurde nur in Containern ausgeführt, nie auf einer Cloud-Maschine.

Fragen

Hält das Schließen des Browsers mein Terminal an?

Nein. Jedes Terminal ist eine Shell in tmux, das getrennt vom Browser läuft. Schließ den Tab, das Fenster oder den Browser, öffne die Seite wieder, und jedes Terminal ist so, wie es jetzt ist, läuft noch und zeigt, was es inzwischen ausgegeben hat.

Wie lasse ich einen Prozess weiterlaufen, wenn SSH die Verbindung verliert?

Starte ihn auf der entfernten Maschine in tmux oder screen oder mit nohup. Aubergine behält Terminals auf dem Rechner, auf dem es läuft. Es kann auch auf einer entfernten Maschine laufen und über einen SSH-Tunnel oder einen Proxy benutzt werden, aber das wurde nur in Containern ausgeführt, nie auf einer Cloud-Maschine.

Soll ich nohup oder tmux nehmen?

nohup passt zu einem Befehl, dessen Ausgabe in eine Datei gehen kann. tmux passt zu einer Shell, zu der du zurückkehren und in die du tippen willst. Aubergine gibt jedem Terminal das Zweite, in einer Browserseite, ohne die Tasten von tmux.

Kann ich die Ausgabe sehen, nachdem ich das Terminal geschlossen habe?

Ja, solange die Shell läuft: tmux hält die letzten 50.000 Zeilen jedes Terminals, und die Seite zeigt sie, wenn du zurückkommst. Aubergine zeichnet selbst nichts auf, also ist diese Ausgabe nach einem Neustart des Rechners weg.

Läuft es nach einem Neustart weiter?

Nein. Ein Neustart des Rechners beendet jedes Programm. Aubergine holt jedes Terminal als frische Shell in seinem letzten Ordner zurück, mit Platz, Name und Notiz, und führt nichts erneut aus.
