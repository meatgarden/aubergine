Zwei Agenten, ein Repository: Arbeitskopien

Normalerweise arbeitet jedes Terminal in deinem echten Ordner. Zwei Agenten in einem Repository bearbeiten dann dieselben Dateien, und du kannst nicht sagen, welche Änderung von wem ist. Eine Arbeitskopie gibt jedem Terminal einen eigenen Checkout auf einem eigenen Branch.

Ein Terminal in einer Arbeitskopie starten

  1. Drück ▾ am Ende von New terminal oben in der Liste der Terminals, dann Shell in a folder or a working copy….
  2. Gib den Ordner an und wähl In its own working copy (in einer eigenen Arbeitskopie). Die Wahl wird nur angeboten, wo sie möglich ist, und sagt, warum nicht, wo sie es nicht ist: kein Git-Repository, ein Bare-Repository oder noch kein Commit.

Aus einem Terminal geht dasselbe so:

aubergine here --copy
aubergine new "api" --copy --in ~/code/my-project

Was du bekommst

Einen Git-Worktree in einem Ordner, den Aubergine unter seinem Datenordner hält, nie in deinem Repository, auf einem neuen Branch namens aubergine/<terminal name>-<six characters>. Er beginnt bei dem Commit, auf dem dein Checkout steht, und das Terminal startet im selben Unterordner, in dem du warst. Dein eigener Checkout wird nie verändert: nicht seine Dateien, nicht das, was gestagt ist, nicht der Branch, den du ausgecheckt hast.

Nicht übernommen: deine nicht committeten Änderungen (nichts wird für dich gestasht oder committet) und Dateien, die Git ignoriert oder nicht verfolgt, etwa installierte Abhängigkeiten und lokale Einstellungen. Ein Projekt, das einen Installationsschritt braucht, braucht ihn in der Arbeitskopie noch einmal.

Lesen, was ein Agent geändert hat

Ein Terminal in einer Arbeitskopie zeigt in seiner Titelleiste seinen Branch und die Zahl der abweichenden Dateien. Klick darauf für die geänderten, hinzugefügten und entfernten Dateien, wobei Arbeit, die in keinem Commit steckt, markiert ist, und für den schreibgeschützten Diff jeder Datei, die du wählst.

Wenn das Terminal endet

Eine Arbeitskopie wird nie entfernt, nur weil ihr Terminal geendet hat. Du wählst:

  • Keep the branch, remove the folder (Branch behalten, Ordner entfernen), wenn alles committet ist.
  • Keep everything. Alles behalten: Sie bleibt in der Liste und sagt, dass ihr Terminal weg ist.
  • Discard both (beides verwerfen), das ein zweites Mal fragt, wenn die Kopie Arbeit enthält, die es nirgends sonst gibt.
aubergine copies
aubergine copies show api
aubergine copies keep-branch api
aubergine copies discard api

Aubergine merget, pusht und rebased nie. Was du mit einem behaltenen Branch machst, ist deine Sache.

Was Aubergine in deinem Repository ausführt

Aubergine nutzt das git auf deinem PATH (2.31 oder neuer). Bei jedem Git-Befehl, den es startet, läuft kein Hook, nichts fragt nach, nichts geht ins Netz, und Submodule werden nicht geholt. Filter, die in deiner eigenen Git-Konfiguration stehen, etwa Large File Storage, laufen sehr wohl, so wie bei deinem eigenen git status.

Es ist keine Sandbox

Eine Arbeitskopie hält Arbeit getrennt. Sie sperrt keinen Agenten ein: Der Agent läuft als du und kann jede Datei lesen und ändern, die du lesen und ändern kannst, auch deinen eigenen Checkout. Verlass dich nicht darauf, dass sie einen Agenten aufhält, der das Falsche tut. Siehe Sicherheit.

Siehe auch: mehrere Coding-Agenten gleichzeitig · Warteschlange und Zeitpläne (eine Aufgabe, die in einem neuen Terminal startet, bekommt eine eigene Arbeitskopie, wenn der Ordner in einem Repository liegt).

In fünf Minuten startklar

Du brauchst macOS mit tmux 3.2 oder neuer und Node.js 22 oder neuer. brew install tmux node holt beides.

npm install -g @meatgarden/aubergine
