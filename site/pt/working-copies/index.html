Dois agentes, um repositório: cópias de trabalho

Normalmente todo terminal trabalha na sua pasta real. Aí dois agentes no mesmo repositório editam os mesmos arquivos, e você não consegue saber qual mudança é de quem. Uma cópia de trabalho dá a cada terminal seu próprio checkout, no próprio branch.

Inicie um terminal em uma cópia de trabalho

  1. Pressione ▾ no final de New terminal, no topo da lista de terminais, e depois Shell in a folder or a working copy….
  2. Informe a pasta e escolha In its own working copy (na própria cópia de trabalho). A opção só é oferecida onde é possível, e diz por quê onde não é: não é um repositório Git, é um repositório bare ou ainda não tem nenhum commit.

De um terminal, a mesma coisa:

aubergine here --copy
aubergine new "api" --copy --in ~/code/my-project

O que você ganha

Uma worktree do Git em uma pasta que o Aubergine mantém dentro da pasta de dados dele, nunca dentro do seu repositório, em um branch novo chamado aubergine/<terminal name>-<six characters>. Ela parte do commit em que o seu checkout está, e o terminal começa na mesma subpasta em que você estava. O seu checkout nunca é alterado: nem os arquivos, nem o que está no stage, nem o branch em que você está.

Não vêm junto: as suas mudanças sem commit (nada é guardado em stash nem commitado por você), e os arquivos que o Git ignora ou não rastreia, como dependências instaladas e configurações locais. Um projeto que precisa de uma etapa de instalação precisa dela de novo na cópia de trabalho.

Leia o que um agente mudou

Um terminal em uma cópia de trabalho mostra na barra de título o branch e o número de arquivos diferentes. Clique ali para ver os arquivos alterados, adicionados e removidos, com o trabalho que não está em nenhum commit marcado, e a diferença, somente leitura, de qualquer arquivo que você escolher.

Quando o terminal termina

Uma cópia de trabalho nunca é removida só porque o terminal dela terminou. Você escolhe:

  • Keep the branch, remove the folder (manter o branch, remover a pasta), quando tudo está commitado.
  • Keep everything. (Manter tudo.) Ela fica na lista, dizendo que o terminal dela não existe mais.
  • Discard both (descartar os dois), que pergunta uma segunda vez quando a cópia tem trabalho que não existe em nenhum outro lugar.
aubergine copies
aubergine copies show api
aubergine copies keep-branch api
aubergine copies discard api

O Aubergine nunca faz merge, push ou rebase. O que você faz com um branch mantido é com você.

O que o Aubergine roda no seu repositório

O Aubergine usa o git do seu PATH (2.31 ou mais recente). Em todo comando Git que ele inicia, nenhum hook roda, nada pede confirmação, nada acessa a rede e os submódulos não são baixados. Os filtros definidos na sua própria configuração do Git, como o armazenamento de arquivos grandes, rodam sim, como rodam no seu próprio git status.

Não é um sandbox

Uma cópia de trabalho mantém o trabalho separado. Ela não prende um agente: o agente roda como você e pode ler e alterar qualquer arquivo que você pode, inclusive o seu próprio checkout. Não conte com ela para segurar um agente que faz a coisa errada. Veja segurança.

Relacionado: rodar vários agentes de programação ao mesmo tempo · a fila e os agendamentos (uma tarefa iniciada em um terminal novo ganha uma cópia de trabalho própria quando a pasta está em um repositório).

Funcionando em cinco minutos

Você precisa de macOS com tmux 3.2 ou mais recente e Node.js 22 ou mais recente. brew install tmux node instala os dois.

npm install -g @meatgarden/aubergine
