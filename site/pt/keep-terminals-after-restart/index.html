Mantenha seus terminais quando o computador reinicia

Fechar o navegador ou reiniciar o Aubergine não perde nada: cada terminal continua rodando. Uma reinicialização do computador encerra o que estava rodando, e o Aubergine traz de volta tudo ao redor, para você retomar de onde parou em vez de começar do zero.

O que acontece quando…

Cada terminal é um shell numa sessão do tmux, que roda separado do navegador e do servidor do Aubergine. O que ele guarda está em dois lugares: o shell rodando, que só o tmux mantém, e tudo o que se diz sobre o terminal, que o Aubergine grava num arquivo da sua pasta de dados a cada mudança.

Um terminal estacionado é mantido do mesmo jeito e também ganha um shell novo. Um terminal cujo shell já tinha terminado continua terminado, com Restart here (reiniciar aqui).

Depois de uma atualização, um terminal que já estava aberto mantém aquilo com que seu shell começou (o PATH e a integração de shell do Aubergine) até esse shell ser iniciado de novo. Se o Aubergine inicia no login, rode aubergine service install de novo depois de atualizar, em vez de reiniciar o servidor à mão.

Depois de reiniciar: de volta ao trabalho

  1. Inicie o Aubergine. Se ele inicia no login (aubergine service install, só no macOS), já está rodando quando você entra, e o launchd o inicia de novo se ele parar. Caso contrário, inicie-o e abra a página:

    aubergine start --open

  2. O canvas está como você deixou. Cada terminal está no seu lugar com nome, cor, tags, campos, links e nota, agora um shell novo na última pasta em que o Aubergine o viu, ou na sua pasta padrão se aquela não existir mais. Nada é digitado ou executado de novo.

  3. Retome seus agentes. Onde o Claude Code rodava e o Aubergine conhece a conversa (ele foi iniciado pelo Aubergine), a barra de título do terminal oferece Resume agent (retomar o agente): inicia o Claude Code de novo naquela conversa. Num terminal que está numa execução de um workflow, também conta ao agente sobre a execução de novo, para ele seguir a partir do passo em que ela está.

  4. Veja onde cada um estava. Details (detalhes) no título de um terminal mostra o que se sabe dele (o passo de uma execução e seu último relatório, a pasta, as tags), seu resumo, seus campos e links, e seu registro em Log. Apontar para o nome de um terminal na lista mostra a recapitulação dele.

  5. Encontre uma conversa que não está no canvas. Past conversations… (conversas anteriores) na paleta (⌘K), ou “Past conversations in this folder…” nos detalhes de um terminal, lista as conversas anteriores do Claude Code numa pasta e abre uma no canvas.

Qualquer outro agente não tem Resume agent, porque o Aubergine não conhece a conversa dele: inicie-o de novo no mesmo terminal com o jeito de retomar desse agente, e leia a nota para dizer a ele onde estava.

O que se perde, e o que fazer

  • O que estava rodando termina. Um build, uma rodada de testes, um servidor ou um agente no meio do trabalho para junto com o computador, e o Aubergine não inicia nenhum deles de novo sozinho. Inicie-os você mesmo; um trabalho que precisa sobreviver a uma reinicialização pertence a algo feito para isso, como um serviço do seu sistema.
  • O trabalho que o Aubergine acompanha espera por você. Uma execução de um workflow mantém seu passo e cada relatório entregue. As tarefas da fila mantêm o lugar; uma que estava sendo iniciada no momento em que o servidor parou é marcada como falha, com uma frase, e nada é tentado de novo sozinho. Um horário de agendamento que passou enquanto o servidor estava parado roda uma vez, atrasado, se tiver menos de seis horas (schedules.lateWithinHours), e senão é marcado como perdido.
  • O histórico de rolagem se perde. Enquanto um shell roda, o tmux guarda as últimas 50.000 linhas que ele imprimiu, e a busca da paleta as lê. O Aubergine não grava o que um terminal imprime, então depois de reiniciar o computador não há nada para trazer de volta, e a busca só encontra o que foi impresso desde então.
  • “Enquanto você estava fora” recomeça. Fica na memória do servidor, não num arquivo, então depois que o servidor inicia ele só sabe o que mudou desde então, e diz isso.

O hábito que barateia uma reinicialização

A nota é o que sobrevive, então faça os agentes escreverem nela enquanto trabalham: uma decisão, um resultado, onde pararam. Um Claude Code iniciado pelo Aubergine tem cada prompt que você envia adicionado ao registro sozinho, e ao começar é instruído a dar nome ao terminal e manter o resumo. Qualquer agente pode fazer o mesmo com estes comandos, que o aubergine guide explica a ele:

aubergine note "Tests pass on the branch. The migration is not written yet."
aubergine describe --summary "Fixing the double redirect at sign-in"

Antes de encerrar o dia, clique em Ask its agent for a recap (pedir uma recapitulação ao agente) nos detalhes de um terminal: o agente escreve onde está com aubergine recap --write, e a recapitulação fica guardada com o terminal.

Fechar o notebook, a suspensão e o navegador

  • Suspender não é reiniciar. Fechar a tampa de um notebook costuma suspendê-lo: os programas pausam e continuam quando ele acorda, e nada da última coluna da tabela acontece. O Aubergine nem mantém o computador acordado nem o acorda, então um agendamento cujo horário passou durante a suspensão roda atrasado, ou é perdido, como acima.
  • Fechar o navegador, uma aba ou a janela dele, ou uma atualização do navegador que o reinicia, não encerra nada. Abra a página de novo (aubergine open a abre já com login) e cada terminal é desenhado a partir do tmux como está agora. Uma página deixada aberta se reconecta sozinha quando o servidor volta.
  • Fechar a janela em que aubergine start roda, ou apertar Ctrl+C nela, para o servidor e nada mais: a coluna do meio da tabela.
  • No Windows com WSL, o WSL parar, porque o Windows reinicia ou depois de wsl --shutdown, é uma reinicialização do computador para o Aubergine. Veja Windows com WSL.

Perguntas

O Aubergine consegue restaurar meus terminais depois de reiniciar?

Sim, tudo menos o que estava rodando neles. Cada terminal volta ao seu lugar no canvas com nome, cor, nota, tags, campos e links, como um shell novo na última pasta. Os programas que rodavam nele não são iniciados de novo; para o Claude Code, Resume agent continua a conversa.

O Aubergine guarda a saída e o histórico do meu terminal?

A saída, só enquanto o shell roda: o tmux guarda 50.000 linhas do histórico de rolagem de cada terminal, e fechar o navegador ou reiniciar o Aubergine não perde nada disso. Depois de reiniciar o computador ela se perde, porque o Aubergine não grava a saída dos terminais. O histórico dos comandos que você digitou, que a seta para cima traz de volta, é o arquivo do seu próprio shell, guardado pelo seu shell como sempre.

Minha conversa do Claude Code sobrevive a uma reinicialização?

A conversa, sim: o Claude Code a guarda nos próprios arquivos, e o Aubergine lembra em qual cada terminal estava. Depois de reiniciar, Resume agent na barra de título do terminal inicia o Claude Code de novo naquela conversa. O que o agente fazia naquele momento parou, e não é feito de novo até você pedir.

Funciona quando o macOS se atualiza sozinho durante a noite?

Uma atualização que reinicia o computador é uma reinicialização como qualquer outra: os programas rodando terminam e todo o resto é mantido. Com o início no login (aubergine service install), o servidor volta a rodar assim que você entra, e o canvas está esperando. Shells novos nas últimas pastas foram vistos ao reiniciar um contêiner do Aubergine; uma atualização noturna real do macOS não foi testada.

Preciso saber tmux?

Não. Ele precisa estar instalado (3.2 ou mais novo), e o Aubergine o roda num socket próprio com as próprias configurações, sem barra de status e sem tecla de prefixo, então você nunca digita um comando do tmux. Seu próprio tmux, se você usa um, não é tocado.

Funcionando em cinco minutos

Você precisa de macOS com tmux 3.2 ou mais recente e Node.js 22 ou mais recente. brew install tmux node instala os dois.

npm install -g @meatgarden/aubergine
