路线图

这里的一切目前都还不存在。这是我们想去的方向，顺序可能会变。现在已经构建了什么，请看指南。

团队与连接

人们一起工作，并从你已经在用的工具中调动智能体。

  • 多人协作

    与其他人及其智能体共享画布。看到谁在哪里工作，把一个在等待的智能体交给队友，一起回答。

  • 聊天界面

    在团队聊天应用中向智能体提出请求并回答它们的问题，使用与浏览器中相同的身份和设置。

  • 工单与拉取请求

    把一个 issue 变成队列中的任务，从工作副本打开拉取请求，并把结果报告回工单。

  • 监视、Webhook 与分诊

    事情发生时开始工作：CI 任务失败、告警、被监视的变更，或来自其他服务的调用。由规则决定什么变成任务。

  • 共享技能与市场

    通过授权共享智能体的技能，经审批推广到整个团队，从 Git 导入，并在公开目录中找到审阅过的条目。

  • 面向个人和房间的记忆

    为每个人和每个共享房间分别保存智能体学到的东西，彼此隔开。

此外：关于模型、共享和严格程度的管理员控制 · 自托管的团队服务器 · 团队登录（SSO 与 MFA） · 按人、令牌或智能体的用量限制 · 无需共享终端即可分享的只读报告 · “For you”列表的手机视图 · 经审阅的公司工具连接器 · 更多聊天应用 · 发布给指定人员的小型内部 Web 应用。

云端

不需要你的笔记本醒着的智能体。

  • 云端沙箱中的智能体

    在隔离的云端沙箱中运行智能体，并在与本地智能体相同的画布上查看它。沙箱空闲时休眠，按需唤醒，并在多次运行之间保留存储。

  • 智能体池

    描述工作，让一个智能体池去认领，而不是为每个任务指定一个终端。

  • 现成的环境

    把依赖、工具、技能、文件和变量保存一次，以后任何新终端或云端智能体都可以从中启动。

  • 长时间、多阶段的工作

    分阶段运行数小时或数天的任务，每个阶段后都有一次确认，进度在重启后也能保留。

  • 一条命令部署到云端

    用一条命令把团队共享的 Aubergine 部署到你自己的云账号上。

  • 看得见的工作

    云端智能体把它所做东西的截图或简短录屏交回到你的“For you”列表。

此外：基于 HTTP 的 MCP，供其他机器上的智能体使用 · 经过测试的 Linux 支持 · zsh 之外的 shell 集成。

控制

智能体可以做多少，以及它做过什么的记录。

  • 审批模式

    选择智能体可以独自做多少：每个操作都审批、只审批有风险的，或都不审批。

  • 命令策略与筛查

    规定哪些命令需要审批、哪些始终拒绝，以及在智能体读取外部内容之前对其进行可选的筛查。

  • 按仓库设定风险等级

    重要的地方限制更严，不重要的地方更宽松。

  • 完整的审计记录

    按项目记录谁或什么做了什么，范围超出今天已记录的令牌调用。

  • 撤销智能体的工作

    把工作副本回滚到某个任务之前，或一步丢弃它的分支。

  • 管理员控制

    团队范围的设置：可以使用哪些模型，共享如何运作。

此外：按终端、任务或定时计划选择模型。

质量

在工作被称为完成之前进行的检查。

  • 质量关卡

    在审阅、测试或安全检查报告通过之前，运行无法结束。

  • 拉取请求审阅

    智能体审阅一个拉取请求，并把结果报告到你的“For you”列表。

  • 浏览器驱动的测试

    智能体操作浏览器来测试一项改动，并交回结果。

  • 先规划，后构建

    智能体提出一个计划，在动文件之前等你批准。

  • 任务配方

    现成的工作流，用于生成测试、审阅、依赖与机密扫描，以及保持文档更新。

  • 成果指标

    按项目统计从任务到完成的时间、智能体等你的频率，以及按发起人划分的用量。

此外：事故报告，由智能体调查并起草事后复盘。

无处不在

更多访问 Aubergine 和在其上构建的方式。

  • 正式发布的 SDK

    把有类型的客户端发布为可安装的包，然后提供 Python 等其他语言的客户端。

  • 编辑器扩展

    在 VS Code 及类似编辑器中显示你的终端和“For you”列表，无需离开编辑器。

  • 桌面应用

    一个带菜单栏图标的打包应用，取代浏览器标签页。

  • Windows 支持

    在 Windows 本身上运行 Aubergine。目前它只能在 WSL 2 里运行，正如Windows 指南所写，而且还没有人在 Windows 上试过。

计划中的工作是方向，不是承诺。已发布的内容以代码仓库为准。

五分钟上手

你需要 macOS，以及 tmux 3.2 或更高版本和 Node.js 22 或更高版本。brew install tmux node 可以一次装好两者。

npm install -g @meatgarden/aubergine
