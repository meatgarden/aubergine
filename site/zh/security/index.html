安全与隐私

Aubergine 为保护你的终端做了什么，以及同样重要的，它没有做什么。简而言之：它在本地运行，替智能体行动前会先询问，而智能体仍然以你的身份运行。

一切都留在你的电脑上

  • 服务器只绑定 127.0.0.1。每个请求和每次 WebSocket 升级都会检查 Host 和 Origin，浏览器还必须持有访问 Cookie。
  • 从其他设备使用 Aubergine 默认关闭，直到你自己设置：同一台电脑上的某个程序以你在设置中写的名称为它提供 HTTPS，每个浏览器都用一次性代码配对，并且可以吊销。已配对的设备能做所有者能做的一切。Using Aubergine from elsewhere 说明了具体做法。
  • Aubergine 不调用模型，也不会自行发起网络请求，只有两个例外：在你要求时获取一个库来源（Git 地址），以及在你自己的 gh 工具已安装并登录时，向它查询某个终端分支的拉取请求。
  • 桌面通知来自打开的页面。没有任何东西离开你的电脑。

三类调用方，各自单独判断

每个请求在查找任何内容之前，都会先对照调用方被允许做什么进行检查，因此没有权限的调用方从回应中什么也得不到。调用方有三种：你（在浏览器中登录）、智能体的会话，以及 API 令牌。

  • API 令牌有权限范围。密钥只显示一次，从不保存；只保留一个哈希。用令牌发起的调用会记入活动日志：谁、做了什么、结果如何，从不记录密钥，也从不记录发送的内容。
  • 有些事任何令牌都永远做不到：创建或吊销令牌、读取活动日志、修改设置，以及任何与 Aubergine 之外的终端有关的事。
  • 终端访问是两个独立的权限范围，一个用于读取，一个用于输入，各自只限于你选择的会话。你可以把一个终端标为 people only（仅限人），对所有令牌关闭它。
  • 智能体自己的凭据范围很窄。它可以设置自己的关注状态、向自己的笔记添加内容、报告自己的状态，以及读取自己所在的运行。它无法触及其他终端、画布或令牌。

智能体不能独自做的事

  • 智能体或程序写的东西（工作流、步骤）会作为草稿交给你审阅。只有你能接受。
  • 等待人的步骤只能由人批准或退回。规则、定时计划和演示都只属于你。
  • Aubergine 只会往智能体的终端里输入几句固定的话，比如“读取你的下一步”。你保存的任何内容、智能体写的任何内容都不会被输入。
  • 从库中安装需要你接受与你所看到的完全相同的内容。

这些防不住什么

智能体以你的身份运行。终端里的智能体能做你在那个终端里能做的任何事，包括运行命令、读取文件，以及在它愿意时使用你自己的浏览器会话。

  • 审批不是锁。以你的身份运行的智能体可以以你的身份做决定。决定会被记录，而不会被阻止。
  • 工作副本不是沙箱。它们把工作分开，但不会把智能体关在里面。
  • 审阅界面是库条目的把关手段。一个条目就是一组指令，智能体会用它被允许做的一切去执行。没读过的东西不要安装。
  • 给智能体的指南是建议，不是锁。

安装脚本

它只改动两样东西：它自己的文件夹，以及一个名为 aubergine 的链接。不用 sudo，不编辑你的 shell 启动文件，也从不碰你的数据文件夹。aubergine uninstall 只移除它自己创建的东西。

报告问题

在 GitHub 上提一个 issue。不要在里面放机密或令牌。

五分钟上手

你需要 macOS，以及 tmux 3.2 或更高版本和 Node.js 22 或更高版本。brew install tmux node 可以一次装好两者。

npm install -g @meatgarden/aubergine
