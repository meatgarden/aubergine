Aubergine 为 Claude Code 做了什么

Claude Code 像任何程序一样在 Aubergine 终端里运行。从 Aubergine 启动时，它还会告诉画布自己在做什么，Aubergine 可以向它交代任务、恢复它，并显示它是如何配置的。下面就是全部内容，按你遇到它们的顺序排列。

Claude Code 由你自己安装和登录。Aubergine 不调用模型，也不持有密钥：它启动的是你已经有的 claude 命令。

  1. 从菜单启动

    New terminal ▾ → Claude Code，或在没有终端占用键盘时按 C，会在新终端中启动 claude，并使用 Aubergine 写在自己数据文件夹里的一个设置文件。你自己的 Claude Code 配置不会被改动。

    它启动的命令是设置中的 agents.claudeCommand，除非你修改，否则就是 claude；Aubergine 会在末尾加上自己的参数。

    位置：终端列表顶部 New terminal（新建终端）旁边的菜单。

  2. 看到它何时在工作、在等待、已完成

    那个设置文件里的钩子会告诉画布智能体在做什么。你提交提示词时，提示词会加入终端的笔记日志，终端显示 working（工作中）。当智能体需要你时，无论是权限询问还是因为空闲等待输入，它的边框会变成等待的颜色，标题和列表中的行显示 waiting for you（在等你）。它停下时显示 finished（已完成）。

    W 跳到下一个在等待的终端，Notify 为开始等待的终端打开桌面通知。提示词里可能有机密：把 "agents": { "logPrompts": false } 写进 config.json，就不会把它们记进笔记日志。

    位置：终端的标题、它在列表中的行，以及顶部 For you 旁边的数字。

  3. 你自己启动的 Claude Code

    在普通终端里手动输入的 claude 像任何程序一样工作，但 Aubergine 只看到一个正在运行它的 shell：不会显示 waiting for you，你在那里启动工作流时也不会替它输入任何内容。要改变这一点，可以打印出钩子，手动加到你自己的 Claude Code 设置中。它们在 Aubergine 终端之外不起任何作用。

    aubergine hooks print

  4. 它会给自己命名并保持摘要

    Aubergine 启动的智能体在开始时会被告知：用 aubergine describe、aubergine link add 和 aubergine field set 按工作内容给终端命名并保持一份摘要；如果它停下时还没有自己的名称或摘要，会被提醒一次。你自己写的内容优先；智能体对同一件事的说法会带着 Use this（使用这个）在旁边等着。这个提醒可以在 Settings 中关闭。

    位置：终端的详情，其中有它的名称、摘要、字段和链接。

  5. 工作流、任务、回顾和消息都能送达它

    Aubergine 只会往终端里输入四句固定的话，仅此而已：启动了一个工作流、请智能体写点东西、你要求一份回顾、有一条消息在等待。每句话都指明一条让智能体运行的命令。只有在能看出智能体占着键盘的地方才会输入：要么是 Aubergine 启动的智能体，要么是设置里装有 aubergine hooks print 所给钩子的智能体。

    同样，队列中的任务只会交给前台有这样的智能体且它空闲的终端；Claude Code on a workflow… 会启动一个新终端，其中的智能体在第一条提示词里就被告知这次运行。

    位置：终端标题菜单中的 Run a workflow…，以及页面顶部的 Runs。

  6. Resume agent

    Aubergine 会记住一个智能体终端处于哪个对话。当它的 shell 回到提示符时，无论是因为你退出了智能体还是电脑重启了，终端都会提供 Resume agent（恢复智能体），在那个对话中再次启动智能体。在处于某次运行中的终端上，它还会再次把这次运行告诉智能体。

    位置：终端的标题栏。

  7. 过去的对话

    Past conversations… 列出某个文件夹里智能体以前的对话：可以阅读，可以在画布上打开，也可以打开一个不改动原件的副本。在命令面板中输入 @ 和一些词来搜索；aubergine history 在命令行中列出它们。读取的内容不会保留，任何令牌和智能体都无法通过 Aubergine 读取对话。

    它读取 Claude Code 保存的文件。这些文件的格式是 Claude Code 的内部格式，会随版本变化。智能体更新后，名称和对话记录可能会变得不完整；Aubergine 读不了的记录会明确说读不了，绝不会显示成空的。

    位置：命令面板（⌘K），以及终端详情中的“Past conversations in this folder…”。

  8. 它是如何配置的

    一份清单，列出智能体的配置文件中说给了它什么：MCP 服务器、插件、钩子、技能、权限规则和设置文件，每项都注明来源，以及 Aubergine 加了什么。只显示名称，绝不显示值或机密。它说明智能体是如何配置的，而不是正在运行的智能体加载了什么；对于它无法知道的事，例如随你的账号而来的连接器，它会直接说明。

    位置：终端上的 ⚙ on、命令面板中的“What is switched on for this agent…”，以及终端的详情。

  9. 为它准备的 Aubergine 工具

    Claude Code with Aubergine tools… 会先问智能体可以做什么：None（无）；Its own work only（仅限自己的工作），使用该终端自己的凭据；或 More…（更多），由你选择权限范围，此时会为这一个终端创建一个令牌，并在终端被彻底结束时吊销。工具是 aubergine mcp，通过启动命令行传给智能体；不会写入它自己的配置。

    位置：New terminal 旁边的菜单。

  10. 把已经打开的 Claude Code 搬过来

    正在运行的智能体无法搬移，但它的对话可以。Open elsewhere 列出你的 Claude Code 标签页，提供 Fork to canvas，对于空闲的智能体还有 Stop and resume here，它会先征求你的确认。在终端中，aubergine move 做同样的事，aubergine here --claude 会在画布上启动 Claude Code，接着该文件夹的上一次对话继续。

    位置：画布上方工具栏中的 Open elsewhere，或按 O。

  11. 在它自己的工作副本中

    aubergine here --copy --claude 会在仓库的独立检出、独立分支中启动 Claude Code，两个智能体永远不会编辑同一批文件。带工具的 Claude Code 终端对话框中也有同样的选项。

已经试过什么

Aubergine 自带的演示使用替身，也就是运行与真实智能体相同的命令和钩子的简短脚本，而不是真正的 Claude Code。用真实智能体尚未试过审批、工作副本、来自队列的任务和定时计划。

其他智能体可以通过 aubergine 命令告诉它其中的大部分内容：见 Codex 与 ChatGPT。

Aubergine 与 Anthropic 没有关联。Claude 和 Claude Code 是 Anthropic 的商标。

五分钟上手

你需要 macOS，以及 tmux 3.2 或更高版本和 Node.js 22 或更高版本。brew install tmux node 可以一次装好两者。

npm install -g @meatgarden/aubergine
