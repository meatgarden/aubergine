Aubergine vs cmux

这些页面中最接近的一对：两者都是为编程智能体打造的终端，都能运行任何可以从命令行启动的智能体，都开源。cmux 是一个原生 macOS 终端应用。Aubergine 是你电脑上的一个服务器，加上你浏览器里的一张终端画布。

信息来源。这里关于 cmux 的内容来自它的网站和文档以及它的仓库，阅读时间为 2026 年 11 月 26 日。我们没有运行过 cmux。如果有错误或已过时，请告诉我们。

选哪个

选 cmux：如果你想要一个快速的原生 Mac 终端应用，带窗格、应用内浏览器和 macOS 通知，并在它之上用脚本搭建你自己的工作方式。

选 Aubergine：如果你想让智能体在应用关闭后继续运行而不必选择某种模式，想自动为每个智能体创建 worktree，并想要已经内置的队列、定时计划和审批。

cmux 是什么

按它自己的描述，是一个基于 libghostty 构建、用 Swift 编写的 macOS 终端，带垂直标签页和面向编程智能体的通知。侧边栏列出各个工作区及其分支、拉取请求、文件夹和最新通知；一个工作区可以拆分成带标签页的窗格。每个操作同时也是一条命令和 Unix 套接字上的一条消息。应用采用 GPL-3.0-or-later 许可证，免费；云端机器和测试版的 iOS 应用需要账号和付费套餐。

不同之处

关掉它会结束什么。cmux 的文档说，退出时会保存布局和文件夹，但不会保留运行中的进程，除非你手动开启它的本地 tmux 模式。在 Aubergine 中，tmux 不是一种模式：每个终端从一开始就是一个 tmux 会话。两者都无法让进程在电脑重启后保留。

一个基础构件，还是它周围的东西。cmux 称自己是基础构件而非解决方案，给你一条命令和一个套接字去自己搭建。Aubergine 自带位于 Git worktree 中的工作副本、带上限的队列、定时计划、带审批的工作流，以及一份汇集所有在等你的事的列表。

应用还是页面。cmux 是由系统绘制的 Mac 应用。Aubergine 是浏览器里的一个页面：绘制速度比原生终端慢，但可以从你通过自己运行的代理配对的另一个浏览器访问。

cmux 有而 Aubergine 没有的

  • 基于 libghostty 的原生终端、拆分窗格，以及一个可由它的命令驱动的应用内浏览器。Aubergine 在浏览器页面里绘制终端，没有窗格：终端摆放在画布上。
  • 当某个窗格需要你时发出 macOS 通知并运行自定义命令，由终端已经在用的转义序列触发，对任何程序都适用。Aubergine 通过为 Claude Code 构建的钩子看出智能体在等待，并且只从打开的页面发出通知。
  • 用于远程机器上工作区的 cmux ssh、一个测试版的 iOS 应用，以及其付费套餐中的云端机器。

常见问题

Aubergine 是 cmux 的替代品吗？

是的：两者都是用来运行多个编程智能体并看清哪一个需要你的终端。cmux 是一个原生 macOS 应用；Aubergine 在浏览器里运行，建立在 tmux 之上，并且多了工作副本、队列、定时计划和工作流。

cmux 需要 tmux 吗？

不需要。它的文档说不需要 tmux，并提供一个需要手动开启的本地 tmux 模式，用于在 cmux 退出时保留运行中的进程。Aubergine 需要 tmux 3.2 或更高版本，并让每个终端都在其中运行。

cmux 能在 Linux 或 Windows 上运行吗？

它的 README 说目前只支持 macOS，需要 macOS 14 或更高版本。Aubergine 为 macOS 构建，在 Linux 上只在容器里运行过，在 Windows 上只能在 WSL 2 里运行，而这还没有试过。

两者都免费开源吗？

cmux 应用采用 GPL-3.0-or-later 许可证，免费，它的云有付费套餐；它的服务器软件采用另一种许可证。Aubergine 采用 MIT 许可证，没有付费套餐。

Aubergine 与 cmux 及其开发者没有任何关联。cmux 是 Manaflow, Inc. 一款产品的名称。

五分钟上手

你需要 macOS，以及 tmux 3.2 或更高版本和 Node.js 22 或更高版本。brew install tmux node 可以一次装好两者。

npm install -g @meatgarden/aubergine
