Aubergine vs Vibe Kanban

两者都开源，都运行在你自己的电脑上，都在浏览器里使用。Vibe Kanban 从工作出发：看板上的 issue，每个交给一个智能体。Aubergine 从智能体出发：并排的终端，旁边有一个队列。

信息来源。这里关于 Vibe Kanban 的内容来自它的文档和它的仓库，阅读时间为 2026 年 11 月 26 日。我们没有运行过 Vibe Kanban。如果有错误或已过时，请告诉我们。

Vibe Kanban 的现状。2026 年 4 月 10 日，它的开发者写道，背后的公司 bloop 将关闭，项目会作为由社区维护的开源项目继续，其远程服务将被移除，而本地工作区仍可使用。撰写本文时，它的文档和定价页面仍在描述这些服务；新版本仍在持续发布。

选哪个

选 Vibe Kanban：如果你习惯用 issue 思考：在看板上规划，把每张卡片交给一个智能体，带评论审阅它的差异，然后合并。

选 Aubergine：如果你想让智能体本身以终端的形式摆在眼前，比窗口活得更久，并且只在你说了算的时候才从队列中分派工作。

Vibe Kanban 是什么

按它自己的描述，是一块供开发者用编程智能体跟踪编程任务的看板。npx vibe-kanban 会启动一个本地服务器并打开它的页面。一个 issue 会变成一个工作区：为你选择的仓库创建 Git worktree，与它点名支持的十多个智能体之一进行对话，旁边是改动，然后是拉取请求和合并。它采用 Apache-2.0 许可证。

不同之处

对话还是终端。Vibe Kanban 把智能体显示为一个对话面板，旁边是它的改动。Aubergine 显示智能体自己的终端，并在一张画布上同时显示许多个。

任何程序。Vibe Kanban 按名称列出它支持的智能体。Aubergine 的终端就是一个 shell：任何命令行智能体都能在里面运行，构建、测试或服务器也一样。Aubergine 自己为智能体做的事是为 Claude Code 构建的。

关掉它会结束什么。我们在 Vibe Kanban 的文档中没有找到关于其服务器停止时正在运行的智能体会怎样的内容。在 Aubergine 中，每个终端都是一个 tmux 会话，停止 Aubergine 或关掉浏览器不会结束任何东西。

Vibe Kanban 有而 Aubergine 没有的

  • 一块 issue 看板，带优先级、标签和子 issue。Aubergine 有任务队列和运行中工作流的看板，但不是 issue 跟踪器。
  • 带行内评论并回传给智能体的差异，然后是拉取请求、变基和合并。Aubergine 显示改了什么，但从不提交或合并。
  • 文档列出的平台中包括 Windows，有声音提示，还有一份更长的按名称支持的智能体列表。

常见问题

Aubergine 是 Vibe Kanban 的替代品吗？

如果是在本地的 Git worktree 中运行多个智能体，并看清哪一个需要你，是的。但形态不同：Vibe Kanban 有一块带对话的 issue 看板，Aubergine 则是画布上的终端和一个任务队列；而且 Aubergine 不会打开拉取请求，也不合并任何东西。

Vibe Kanban 还在维护吗？

它的开发者在 2026 年 4 月 10 日写道，背后的公司将关闭，项目作为由社区维护的开源项目继续。此后它的仓库仍有新版本发布。它现在的情况请看它的仓库。

两者都在本地运行吗？

是的。两者都是你自己电脑上的一个服务器，加上你浏览器里的一个页面。Vibe Kanban 的文档提到可选的登录，用于看板和团队功能；Aubergine 完全没有账号。

两者各支持哪些智能体？

Vibe Kanban 点名支持十多个，其中有 Claude Code、Codex、Gemini CLI、GitHub Copilot、Amp、Cursor 和 OpenCode。Aubergine 能在终端里运行任何命令行程序；从菜单启动智能体、看出它在等待以及恢复它的对话，这些是为 Claude Code 构建的。

Aubergine 与 Vibe Kanban 及其开发者没有任何关联。Vibe Kanban 是由 Bloop AI Limited 发起的项目的名称。

五分钟上手

你需要 macOS，以及 tmux 3.2 或更高版本和 Node.js 22 或更高版本。brew install tmux node 可以一次装好两者。

npm install -g @meatgarden/aubergine
