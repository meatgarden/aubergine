两个智能体，一个仓库：工作副本

通常每个终端都在你真实的文件夹里工作。于是同一个仓库中的两个智能体会编辑同一批文件，你也分不清哪个改动是谁的。工作副本给每个终端一份独立的检出，位于它自己的分支上。

在工作副本中启动终端

  1. 按下终端列表顶部 New terminal 末端的 ▾，然后选择 Shell in a folder or a working copy…。
  2. 指定文件夹并选择 In its own working copy（在它自己的工作副本中）。只有在可行时才提供这个选项，不可行时会说明原因：不是 Git 仓库、是裸仓库，或者还没有提交。

在终端中也可以这样做：

aubergine here --copy
aubergine new "api" --copy --in ~/code/my-project

你会得到什么

一个 Git worktree，位于 Aubergine 放在其数据文件夹下的一个文件夹中，绝不在你的仓库里，处于一个名为 aubergine/<terminal name>-<six characters> 的新分支上。它从你的检出当前所在的提交开始，终端会在你当时所在的同一个子文件夹中启动。你自己的检出永远不会被改动：文件不会，已暂存的内容不会，你检出的分支也不会。

不会带过去的：你未提交的改动（不会替你 stash 或提交），以及 Git 忽略或不跟踪的文件，例如已安装的依赖和本地设置。需要安装步骤的项目，在工作副本中也需要再做一次。

阅读智能体改了什么

处于工作副本中的终端会在标题栏显示它的分支和有差异的文件数。点击它可以看到修改、新增和删除的文件，不在任何提交中的工作会被标出，还可以查看你选择的任何文件的只读差异。

终端结束时

工作副本绝不会仅仅因为终端结束而被删除。由你选择：

  • 当一切都已提交时，选 Keep the branch, remove the folder（保留分支，删除文件夹）。
  • Keep everything.（全部保留）它会留在列表中，并注明它的终端已经不在了。
  • Discard both（两者都丢弃），当副本中有别处没有的工作时，它会再问一次。
aubergine copies
aubergine copies show api
aubergine copies keep-branch api
aubergine copies discard api

Aubergine 从不合并、推送或变基。保留下来的分支怎么处理由你决定。

Aubergine 在你的仓库中运行什么

Aubergine 使用的 git 是你 PATH 中的那个（2.31 或更高版本）。它启动的每条 Git 命令都不会运行钩子、不会弹出提示、不会访问网络，也不会拉取子模块。你自己的 Git 配置中指定的过滤器（例如大文件存储）会运行，就像你自己运行 git status 时一样。

它不是沙箱

工作副本把工作分开。它不会把智能体关在里面：智能体以你的身份运行，可以读取和修改你能读写的每个文件，包括你自己的检出。不要指望它拦住做错事的智能体。见安全。

五分钟上手

你需要 macOS，以及 tmux 3.2 或更高版本和 Node.js 22 或更高版本。brew install tmux node 可以一次装好两者。

npm install -g @meatgarden/aubergine
