电脑重启后，终端依然在

关掉浏览器或重启 Aubergine 不会丢失任何东西：每个终端都继续运行。电脑重启会结束正在运行的东西，而 Aubergine 会把它周围的一切带回来，让你从上次停下的地方继续，而不是从头开始。

当……时会发生什么

每个终端都是 tmux 会话中的一个 shell，独立于浏览器和 Aubergine 的服务器运行。它的内容分在两处：正在运行的 shell，只由 tmux 保存；以及关于这个终端的一切说明，Aubergine 每次变动都会写进其数据文件夹里的一个文件。

停放的终端也同样保留，同样会得到一个新 shell。shell 在此之前就已结束的终端保持结束状态，并提供 Restart here（在此重启）。

更新之后，已经打开的终端会保留它的 shell 启动时所带的东西（它的 PATH 和 Aubergine 的 shell 集成），直到那个 shell 重新启动。如果 Aubergine 在登录时启动，更新之后请再运行一次 aubergine service install，而不是手动重启服务器。

重启之后：回到工作

  1. 启动 Aubergine。如果它在登录时启动（aubergine service install，仅限 macOS），你一登录它就在运行，停止后 launchd 也会再把它启动。否则就启动它并打开页面：

    aubergine start --open

  2. 画布和你离开时一样。每个终端都在原位，带着名称、颜色、标签、字段、链接和笔记，现在是一个新 shell，位于 Aubergine 最后看到它所在的文件夹（如果那个文件夹已不存在，则在你的默认文件夹）。不会重新输入或运行任何东西。

  3. 恢复你的智能体。在运行过 Claude Code 且 Aubergine 知道其对话（它是从 Aubergine 启动的）的终端上，标题栏会提供 Resume agent（恢复智能体）：在那个对话中再次启动 Claude Code。在处于某个工作流运行中的终端上，它还会再次把这次运行告诉智能体，让它从运行所在的步骤继续。

  4. 看看每个终端进行到哪里。终端标题里的 Details（详情）会显示关于它的已知信息（运行的步骤和最后一份报告、文件夹、标签）、它的摘要、字段和链接，以及 Log 下的日志。在列表里把指针移到终端名称上，会显示它的回顾。

  5. 找回不在画布上的对话。命令面板（⌘K）中的 Past conversations…（过去的对话），或终端详情中的“Past conversations in this folder…”，会列出某个文件夹里 Claude Code 以前的对话，并能在画布上打开其中一个。

其他智能体没有 Resume agent，因为 Aubergine 不知道它的对话：请在同一个终端里用那个智能体自己的恢复方式重新启动它，并读一读笔记，告诉它进行到哪里了。

会丢失什么，以及怎么办

  • 正在运行的东西会结束。构建、测试、服务器或正在工作的智能体会随电脑一起停止，Aubergine 不会自行重新启动其中任何一个。请自己重新启动它们；必须撑过重启的任务，应当交给专门为此设计的东西，比如系统的服务。
  • Aubergine 跟踪的工作会等着你。工作流的运行会保留它的步骤和每一份提交的报告。队列中的任务保持原位；服务器停止那一刻正在启动的任务会被标为失败，并附一句说明，不会自动重试任何东西。服务器停止期间错过的计划时间，如果不超过六小时（schedules.lateWithinHours），会迟到运行一次，否则标为已错过。
  • 回滚记录会丢失。shell 运行期间，tmux 会保留它最后输出的 50,000 行，命令面板的搜索会读取这些内容。Aubergine 不记录终端的输出，所以电脑重启后没有东西可以找回，搜索只能找到此后输出的内容。
  • “你不在时”会重新开始。它保存在服务器的内存里，而不是文件里，所以服务器启动后它只知道此后发生的变化，并会这样说明。

让重启代价很小的习惯

能留下来的是笔记，所以让智能体边做边写进去：一个决定、一个结果、停在了哪里。从 Aubergine 启动的 Claude Code 会自动把你发送的每条提示加入日志，并在开始时被要求给终端命名、维护摘要。任何智能体都可以用下面这些命令做到同样的事，aubergine guide 会向它说明：

aubergine note "Tests pass on the branch. The migration is not written yet."
aubergine describe --summary "Fixing the double redirect at sign-in"

一天结束前，在终端详情里点 Ask its agent for a recap（请它的智能体写回顾）：智能体用 aubergine recap --write 写下现状，这份回顾会和终端一起保存。

合上笔记本、睡眠和浏览器

  • 睡眠不是重启。合上笔记本的盖子通常会让它睡眠：程序暂停，醒来后继续，表格最后一列的情况都不会发生。Aubergine 既不让电脑保持唤醒，也不唤醒它，所以睡眠期间到点的计划会迟到运行或被错过，同上。
  • 关闭浏览器、标签页或其窗口，或浏览器更新后重启，都不会结束任何东西。重新打开页面（aubergine open 会以登录状态打开），每个终端都会按 tmux 中的当前状态绘制。一直开着的页面会在服务器恢复后自动重新连接。
  • 关闭运行 aubergine start 的窗口，或在其中按 Ctrl+C，只会停止服务器：也就是表格中间那一列。
  • 在使用 WSL 的 Windows 上，WSL 停止（因为 Windows 重启或执行 wsl --shutdown 之后）对 Aubergine 来说就是电脑重启。参见 使用 WSL 的 Windows。

常见问题

Aubergine 能在重启后恢复我的终端吗？

能，除了其中正在运行的东西。每个终端都会回到画布上的原位，带着名称、颜色、笔记、标签、字段和链接，成为位于最后所在文件夹的新 shell。其中运行过的程序不会重新启动；对 Claude Code，Resume agent 可以接着之前的对话。

Aubergine 会保留我的终端输出和历史吗？

输出只在 shell 运行期间保留：tmux 为每个终端保留 50,000 行回滚记录，关掉浏览器或重启 Aubergine 都不会丢失。电脑重启后就没了，因为 Aubergine 不记录终端输出。你输入过的命令历史（按上箭头会出现的那些）是你的 shell 自己的文件，像往常一样由 shell 保存。

我的 Claude Code 对话能撑过重启吗？

对话可以：Claude Code 把它保存在自己的文件中，Aubergine 记得每个终端处于哪个对话。重启之后，终端标题栏上的 Resume agent 会在那个对话中再次启动 Claude Code。智能体那一刻正在做的事已经停止，在你要求之前不会重做。

macOS 夜里自动更新时还管用吗？

会重启电脑的更新就是一次普通的重启：正在运行的程序结束，其他一切都保留。开启登录时启动（aubergine service install）后，你一登录服务器就会再次运行，画布在等着你。在最后所在文件夹中打开新 shell 这一点，是在重启 Aubergine 的容器时看到的；真实的 macOS 夜间更新尚未试过。

我需要懂 tmux 吗？

不需要。只要装好它（3.2 或更新版本），Aubergine 会在自己的套接字上用自己的设置运行它，没有状态栏，也没有前缀键，所以你永远不用输入 tmux 命令。如果你自己也在用 tmux，它不会被动到。

五分钟上手

你需要 macOS，以及 tmux 3.2 或更高版本和 Node.js 22 或更高版本。brew install tmux node 可以一次装好两者。

npm install -g @meatgarden/aubergine
