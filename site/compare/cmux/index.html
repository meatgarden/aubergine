Aubergine vs cmux

The closest pair on these pages: both are terminals made for coding agents, both run any agent you can start from a command line, both are open source. cmux is a native macOS terminal app. Aubergine is a server on your computer and a canvas of terminals in your browser.

Where this comes from. What is said here about cmux is from its site and documentation and its repository as read on 26 November 2026. We have not run cmux. If something is wrong or out of date, tell us.

Which to pick

Pick cmux if you want a fast native Mac terminal app with panes, an in-app browser and macOS notifications, and you script your own way of working on top of it.

Pick Aubergine if you want agents that go on when the app is closed without choosing a mode, a worktree per agent made for you, and a queue, schedules and approvals already built.

What cmux is

By its own description, a macOS terminal built on libghostty with vertical tabs and notifications for coding agents, written in Swift. A sidebar lists workspaces with their branch, pull request, folder and latest notification; a workspace splits into panes with tabs. Every action is also a command and a message on a Unix socket. The app is under the GPL-3.0-or-later license and free; cloud machines and an iOS app in beta come with an account and paid plans.

Where they differ

What closing it ends. cmux documents that quitting saves the layout and folders and that live processes are not kept, unless you opt in to its local tmux mode. In Aubergine tmux is not a mode: every terminal is a tmux session from the start. Neither keeps a process through a restart of the computer.

A primitive, or the things around it. cmux calls itself a primitive, not a solution, and gives you a command and a socket to build with. Aubergine comes with working copies in Git worktrees, a queue with a limit, schedules, workflows with approvals and one list of what waits for you.

An app or a page. cmux is a Mac app drawn by the system. Aubergine is a page in a browser: slower to draw than a native terminal, and reachable from another browser you pair through a proxy you run.

What cmux has that Aubergine does not

  • A native terminal on libghostty, split panes, and an in-app browser its command can drive. Aubergine draws terminals in a browser page and has no panes: terminals are placed on a canvas.
  • macOS notifications and a custom command when a pane needs you, set off by the escape sequences terminals already use, for any program. Aubergine sees an agent wait through hooks built for Claude Code, and notifies from the open page only.
  • cmux ssh for a workspace on a remote machine, an iOS app in beta, and cloud machines on its paid plans.

Questions

Is Aubergine an alternative to cmux?

Yes: both are terminals for running several coding agents and seeing which one needs you. cmux is a native macOS app; Aubergine runs in a browser on top of tmux, and adds working copies, a queue, schedules and workflows.

Does cmux need tmux?

No. Its documentation says tmux is not required, and offers an opt-in local tmux mode for keeping live processes when cmux quits. Aubergine needs tmux 3.2 or newer and runs every terminal in it.

Does cmux run on Linux or Windows?

Its README says macOS only, for now, on macOS 14 or later. Aubergine is built for macOS, has been run on Linux in containers only, and on Windows runs only inside WSL 2, which has not been tried.

Are both free and open source?

The cmux app is under the GPL-3.0-or-later license and free, with paid plans for its cloud; its server software has a different license. Aubergine is under the MIT license and has no paid plan.

Aubergine is not affiliated with cmux or its makers. cmux is the name of a product of Manaflow, Inc.

Up and running in five minutes

You need macOS with tmux 3.2 or newer and Node.js 22 or newer. brew install tmux node gets both.

npm install -g @meatgarden/aubergine
